# Resource-owning seam fault-injection inventory

This is the gh-ocannl-571 / gh-ocannl-778 acceptance map, enforced by
`test/operations/resource_fault_inventory_scan.ml` (`@test/operations/scans`). "Covered" means a
test forces the named failure and has an uninjected negative control; a happy-path test alone is
listed as structural evidence, not error coverage. CPU rows run on `cc` even when the ambient
backend differs. GPU-only rows are explicit box-session legs: per-PR CI runs `cc` and cannot turn
those cells green.

The named injection points (`Delta_pool_allocated`, `Schedule_cache_before_commit`, ...) are
`Resource_fault_injection.hit` calls carrying both their derived `ownership_phase` and concrete
`artifact` identity. `with_event_callback`, `with_callback`, and `with_sticky_async_fault` install
a test's callback per DOMAIN: `hit` calls the value installed in the domain that runs it, and a
fresh domain starts with the no-op. Asynchronous synchronization failures are modeled as sticky by
default (`with_sticky_async_fault`, matching `Multidev`'s `dev_error` and Metal's `runner.failure`),
while one-shot exceptions stay explicit as negative controls. A new row's point must fire on the
domain that called the operation (a `Context` transfer, compile or release; a schedule-cache open,
store or lookup), never inside a task a scheduler enqueues (a kernel or transfer task). On
`multidev_cc` such a task runs on a worker domain, whose no-op callback never sees the hit, so no
test there can force the row's failure, and a `cc` leg, which runs every task on the calling thread,
would not notice. `test/operations/resource_fault_injection_domains.ml` pins both halves:
two-domain isolation on `cc`, and on `multidev_cc` the caller's callback seeing the same point set
as on `cc`. Two rows inject elsewhere: candidate admission through the `Autotune.Seam` hooks, which
are per domain under the same rule, and the mock slab's raw allocation failure in
`arrayjit/test/test_slab_free_on_grow.ml`. The mechanism is in
[backend-memory.md](agent-notes/backend-memory.md).

The next resource-owning feature should add rows before implementation. In particular, constant-pool
eviction (gh-ocannl-565) must enumerate cache mutation, mixed-purity pool refusal, eviction during
in-flight work, callback/report failure, and retry before its happy-path memory curve is evidence.
