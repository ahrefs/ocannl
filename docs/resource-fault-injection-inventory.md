# Resource-owning seam fault-injection inventory

This is the gh-ocannl-571 acceptance map. "Covered" means a test forces the named failure and has
an uninjected negative control; a happy-path test alone is listed as structural evidence, not error
coverage. CPU rows run on `cc` even when the ambient backend differs. GPU-only rows are explicit
box-session legs: per-PR CI runs `cc` and cannot turn those cells green.

| Seam | Failure mode | Status and acceptance evidence | Remaining leg |
| --- | --- | --- | --- |
| `Backends.allocate_delta` | A pool allocation commits, then later placement/initialization raises | Covered on `cc`: `resource_fault_injection` raises at `Delta_pool_allocated` and requires exactly one allocation, one free, zero live growth; its control commits and releases exactly once. | Run the same shared hook on each GPU box when allocator changes touch backend-specific allocation. |
| `Backend.link` after delta allocation | Codegen/link/validation raises after all buffer locations and constant-cache insertions exist, before a child context exists | Covered on `cc`: `Link_after_delta` requires the unreachable working delta to be freed exactly once and the control to execute correct values. Existing autotune decline tests cover classified real failures. | None at the shared seam: the assignments-level batch link was retired (gh-ocannl-767), and a fissioned routine's segments link against one delta covered by the same unwind. |
| `Context.release` / `Backends.finalize` | Await raises before any free | Covered on `cc`: `Finalize_before_await` requires no committed flag, free, or release count; the control retry frees once. `test_multidev_error_propagation` separately proves worker errors reach await. | Exercise a real device asynchronous error before release on CUDA/HIP; it is hardware-destructive and stays box-gated. |
| `Context.release` / `Backends.finalize` | Cleanup raises after a strict prefix of pools was freed | Covered on `cc`: failure before the second free records the first pool, retry invokes `free_pool` only for the remainder, and a third release is a no-op. `released_pool_ids` is the retry ledger. | A backend raw deallocator that itself raises after an ambiguous driver-side free cannot be simulated faithfully; cover when a backend exposes a safe failure API. |
| `free_pool` table-entry removal | Several tnodes share one pool; retry or duplicate map entries could double-free | Covered: finalization deduplicates by pool id, its persistent retry ledger is asserted exactly, and `test_slab_free_on_grow` proves a GC-backed backend drops the strong table entry. `Alloc_census` requires one semantic free per live entry. | CUDA/HIP raw frees should be rechecked on hardware whenever their slab table implementation diverges from the shared one. |
| Constant-cache exclusion during finalization | A tnode has a cached constant location and a distinct context-owned location from `from_host` | Covered on `cc`: transfer controls use the same tnode after a constant compile. Finalize now compares the cached location, not mere key presence, and must free the distinct working pool. | None at the shared seam. |
| Fresh `from_host` / device-copy destination | Allocation succeeds, then upload/copy raises before the location is installed in the context, including a queued upload whose error is first reported persistently by stream await | Covered on `cc`: `Transfer_pool_allocated` and `From_host_before_copy` require one allocation, one free, and no live growth. The paired `From_host_before_await` / `Transfer_cleanup_before_await` scenario makes both the operation and best-effort cleanup synchronization fail, matching sticky worker errors, and still requires the unreachable pool to be freed exactly once. Controls copy values and release once. | Same-device `init_from_device` uses the same protected owner but lacks a dedicated injected execution leg. |
| Existing-buffer `from_host` | Copy raises without minting a resource | Covered on `cc`: failure retains the destination with no allocation/free movement and an uninjected retry copies in place. | GPU direct-copy/queued-copy parity is inherited from the shared hook; run on boxes after backend transfer changes. |
| `to_host` | Await or copy raises while the host destination is temporary and the device source remains owned | Covered on `cc`: `To_host_before_copy` requires no device free and a successful retry from the same context. Host `Ndarray` lifetime remains GC-owned. | Real asynchronous device-to-host failures remain hardware-gated. |
| Reserved merge pool | Replacement allocation fails while growing pool id 0 | Covered without a GPU: `test_slab_free_on_grow` injects raw allocation failure and requires free-first replacement (no old+new peak), removal of the released pointer, invalidated merge location/capacity/writer marker, and a successful fresh retry. Shared, CUDA, and HIP slabs use the same ordering and metadata contract. | Metal allocates before `Hashtbl.set` already; a Metal allocation-failure injection needs API support from the binding. |
| Reserved merge pool | Copy after a successful grow fails | Ownership remains honest structurally: the new pool is the device's reserved reusable pool, not an abandoned per-operation delta. | Add a CUDA/HIP box leg if retry semantics or capacity rollback become a user contract. |
| Stream/event/device teardown | Stream synchronization, event destruction, or device finalizer raises while pools/modules remain | Uncovered as fault injection. `test_multidev_error_propagation` covers propagation, not teardown ownership. CUDA/HIP `finalize_device` and Metal ARC finalizers are hardware-specific. | Box legs must count stream/event/module/pool release, inject each available driver failure, and assert retry/no double-destroy. |
| CUDA/HIP graph capture | Begin/capture/instantiate/end fails; failed capture must leave the stream out of capture mode | Structural production guard exists: every capture attempt terminates with `end_capture` before fallback/re-raise, and RELAXED capture mode permits resource finalizers on other threads. No GPU-free binding-level injection exists. | CUDA and HIP box legs: inject begin, segment launch, end, instantiate, and replay failures; assert fallback correctness, capture invalidation, and module/buffer finalizers under RELAXED mode. |
| Graph cache invalidation | Merge pointer or static binding changes while captured graphs are cached | Existing GPU tests/notes cover key identity and replay behavior, but not teardown failures. | Box leg should grow the merge pool, force cache invalidation, collect the old graph, and count graph destruction exactly once. |
| Autotune candidate admission | A nonwinner callback raises before beam/round transfer | Covered on `cc` and Metal: `autotune_callback_release` injects at both post-admission callback boundaries, selects a strictly slower real measurement (re-rolling the search when the timings admit only winners, and skipping the injection claims as an environment skip if every roll is monotone), and requires zero working-pool/byte growth and exact created/released context counts. The uninjected control executes the winner and also catches an undispatched baseline abandoned outside the beam. | CUDA/HIP share the owner; hardware-specific release failure remains in the teardown rows above. |
| Schedule-cache store | Temp write succeeds, then commit raises; concurrent writers collide | Covered filesystem-only: `Schedule_cache_before_commit` requires the old complete entry to survive and the writer's unique temp artifact to disappear; retry replaces it. Temp names are per-process/per-attempt. | A platform-specific rename refusal still preserves the previous entry and cleans the temp; native checks on rog-nv-win or minix-amd-win are the development portability leg, with remote Windows CI as fallback. |
| Schedule-cache replay | Read/parse/replay preparation raises or the entry is corrupt/stale | Covered filesystem-only: `Schedule_cache_before_replay` becomes an honest miss, the control reads the entry, and corrupt content is also a miss. Autotune tests cover failed compiled replay falling back to search and releasing rejected replay artifacts. | None for file ownership; GPU schedule replay validity stays in backend search tests. |

The next resource-owning feature should add rows before implementation. In particular, constant-pool
eviction (gh-ocannl-565) must enumerate cache mutation, mixed-purity pool refusal, eviction during
in-flight work, callback/report failure, and retry before its happy-path memory curve is evidence.
