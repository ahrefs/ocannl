# Shape inference and projection inference

To separate concerns, OCANNL is split into the `arrayjit` library, responsible for compilation of high-level n-D array operation sequences (`Assignments.comp`) via backends such as cc, metal and cuda, and the main `ocannl` library, responsible for deriving the operations computing the forward propagation and backpropagation from tensor expressions. In particular, `arrayjit` contains `Indexing`, which represents complex indexing into arrays, and the main library `ocannl` has `Row` and `Shape` modules, which do the most "heavy-lifting" in the translation from concise tensor expressions to sequences of assignments.

Shape inference broadly speaking consists in OCANNL of inferring the `Shape.t` record -- shape inference proper, and inferring the `Indexing.projections` record -- projections inference. `Shape.t` records are mutable, so that the partially inferred shapes can be observed by the user. Shape and projections inference is intended to be declarative -- independent of the order in which constraints are added. There is one aspect that is not declarative: when tensor expressions are compiled to assignments, i.e. jitted, still-unsolved shape variables in terminal nodes are substituted by their greatest lower bounds if any, or by dimension-1 (no basis) / no-more-axes.

The bulk of the projections inference happens alongside shape inference, with the projections-relevant information stored in auxiliary fields -- this prevents subtle bugs where projection semantics deviates from shape semantics, and will simplify adding new shape/projection inference features. Shape inference happens during `propagate_shapes` calls, and then again in a `finish_inference` call, which is triggered whenever the dimensions or projections are required (i.e. typically by jitting). Finally, the projections are reconstructed in `derive_projections`. It would seem `derive_projections` could reuse the already-computed solutions constraints. But we face a problem: we must prevent contaminating projections across different operations. To illustrate: we conclude the dimensions of two axes are the same because they are reduced together in another operation -- this should not force the axes to share a projection in the processed operation. To prevent the contamination, in each `derive_projections` call, we freshen the projection ids in the (inferred) shapes, and regenerate and re-solve the constraints with the fresh projection ids.

The shape system in OCANNL is currently monomorphic: both row and dimension variables are interpreted existentially. It can in principle be made polymorphic: by abstracting over the remaining fresh variables when forming a tensor-producing function, and by replacing universally bound variables by fresh variables when applying such functions. However, this is non-trivial and would depend on introducing namespaces for tensor nodes. Then, we could perform "abstract interpretation" (aka. tracing like e.g. in JAX) by computing an OCaml function under an abstract tensor node namespace. Applying the function would not execute the OCaml code again, but instead would copy the tensors generated by "abstract interpretation"-stage execution with appropriately freshened shape variables into a concrete tensor node namespace. There is a natural context for introducing such abstraction: functions as processed by the `%op` syntax extension with a unit i.e. `()` parameter separating configuration from tensor arguments -- see [syntax extensions](syntax_extensions.md). Copying tensor graphs that way remains future work. Its shape half exists: **shape schemes** (gh-ocannl-404), described [below](#shape-schemes), which `%op` functions get automatically (gh-ocannl-1751): their applications are checked against the scheme.

## Representing shapes and constraints

A tensor shape in OCANNL is composed of three rows of axes: batch, input and output. These are ordered input-last (`batch @ output @ input`) in the underlying n-dimensional array implementation of tensors (at least when hosted, as backends can reorder axes via a stride mechanism NOTE: NOT IMPLEMENTED YET). A tensor shape can have empty axes, which represent scalars (tensors with a single element). This allows shape inference to naturally handle corner cases where tensors hold just one cell. For printing and einsum-notation-like specifications, we use the syntax: `batch|input->output` (or `input->output`, `batch|output`, `output`), where `batch`, `input`, `output` are whitespace or comma or parenthesis separated axis entries; or the axis entries are the individual characters, if no separators are used (except if it's digits only).

A row is a sequence of axes of a single kind: batch, input, or output. The shape type incorporates information relevant to inference, in particular shape variables: both for individual axes (`dim` variables), and for extending a row with more axes (`row` variables). Currently, all rows are (independently) broadcastable: can be broadcasted to a larger number of axes. However, in OCANNL the broadcasting can happen "in the middle", with not only the given trailing axes fixed, but also with the given leading axes fixed.
```ocaml
type solved_dim = { d : int; basis : string; proj_id : proj_id option }
(** A single axis in a shape. [basis] is total: unannotated user axes carry the reserved
    ["default"] tag, and the claim-free broadcast top carries the reserved ["bcast_if_1"] tag. *)

type convolution = { dilation : int; kernel : dim; use_padding : bool }
(** Convolution parameters. *)

type dim =
  | Var of dim_var
  | Dim of solved_dim
  | Affine of { stride : int; over : dim; conv : convolution option; stride_offset : int }
      (** An affine transformation of a dimension. When [conv] is [None], this is strided
          iteration. When [conv] is [Some], this includes convolution parameters.
          Invariants: [stride > 0], [dilation > 0] (when present), [0 <= stride_offset], and
          [stride_offset < stride] unless the axis is a padded window. *)

type bcast =
  | Row_var of row_var  (** The row can be inferred to have more axes. *)
  | Broadcastable  (** The shape does not have more axes of this kind, but is "polymorphic". *)

type row = Row.t = { dims : dim list; bcast : bcast; id : provenance }

type shape = Shape.t = {
  mutable batch : row;
  mutable input : row;
  mutable output : row;
  id : int;  (** A node that has the same shape as this shape. *)
  debug_name : string;
}
```

The actual implementation is split into the `Row` module, which handles multi-row inference, and the `Shape` module which deals with the specific axis kinds (batch, input, output), _einsum_ specifications, and the shape-relevant semantics of operations expressed via the `Shape.logic` variant type. Since broadcasting extends leading axes (preserves trailing axes), substituting a `row_var` means prepending to the `dims` of the row that has the row variable as its `bcast` field.

### Three kinds of labels

OCANNL uses three distinct label-like mechanisms in its shape system. It is important to understand which is which:

1. **Dimension basis (units)**: stored as a total `basis : string` on `solved_dim`. These are semantic annotations on dimension *values* -- e.g., `"rgb"` on a dimension of size 3 means "this axis represents three RGB channels." Two dimensions that must agree in size must also agree on basis. The basis is total: an unannotated user axis carries the reserved `"default"` tag (an ordinary atom, incompatible with named bases), and the claim-free broadcast top carries the reserved `"bcast_if_1"` tag (a size-1 axis with this tag broadcasts to any size; at sizes > 1 it is an inert atom). The broadcast order is then a flat partial order with `1_(bcast_if_1)` as top. Bases need not be unique within a row and are inferred during shape inference. They do not name the axis itself. See `Row.solved_dim` in `tensor/row.ml`.

2. **Einsum pseudo-labels**: the single- or multi-character identifiers used in einsum notation (e.g., `i`, `j`, `k` in `"ij;jk=>ik"`). These are local to the notation -- they identify which axes correspond to each other within a single einsum spec but do not persist on the resulting tensor. See `Einsum_types.axis_spec` in `tensor/einsum_types.ml`.

3. **Axis labels (planned, unscheduled)**: persistent names for axis *positions* within a row, stored as `axis_labels : string option list` on `Row.t`. Unlike dimension basis which annotates what a dimension measures (its unit), axis labels name the role the axis plays (e.g., `"seq_len"`, `"hidden"`). Axis labels are unique within a row, propagated during row unification, and checked for conflicts. They are strictly optional and do not change inference outcomes. See the design proposal in `archive/docs/proposals/axis-labels.md`.

### Affine indexing and convolutions

The `Affine` constructor represents affine transformations of dimensions, supporting both strided iteration and convolution-style indexing. The key insight is that `stride_offset` is purely a projection-time concern—it selects which elements within each stride window are accessed, but does not affect dimension sizes. This allows the same input tensor to be used with different `stride_offset` values (0 to stride-1) without shape errors. Because the dimension formulas below leave the offset out, an offset is in bounds only when it is smaller than the stride and the axis has no unpadded window; einsum specs that break this are refused while the tensor is built (`Shape.refuse_out_of_extent_offset`, gh-ocannl-1618), in either slot. A padded window keeps its offset, at or past the stride too: a tap it moves past the margins reads the padding value. A stride or a dilation below 1 is refused there as well (`Shape.refuse_nonpositive_coefficient`, gh-ocannl-1657).

**Dimension formulas** (during shape inference):

- `conv = None` (strided iteration): `input_dim = stride * output_dim`
- `conv = Some { use_padding = true; _ }`: `input_dim = stride * output_dim` (padding compensates for kernel)
- `conv = Some { use_padding = false; dilation; kernel }`: `input_dim = stride * (output_dim - 1) + effective_kernel_span`

where `effective_kernel_span = 1 + (kernel_dim - 1) * dilation`.

The formula for `use_padding = false` comes from the standard valid convolution relationship. For output position `o` (0 to output_dim-1) and kernel position `k` (0 to kernel_dim-1), the input index is:

```
input_index = o * stride + k * dilation
```

The maximum input index occurs at `o = output_dim - 1` and `k = kernel_dim - 1`:

```
max_index = (output_dim - 1) * stride + (kernel_dim - 1) * dilation
```

Since valid indices are 0 to input_dim-1, we have `input_dim = max_index + 1`:

```
input_dim = (output_dim - 1) * stride + (kernel_dim - 1) * dilation + 1
          = stride * (output_dim - 1) + effective_kernel_span
```

Equivalently, solving for output_dim: `output_dim = (input_dim - effective_kernel_span) / stride + 1`. This requires `(input_dim - effective_kernel_span)` to be non-negative and divisible by `stride`.

Two windows over one extent relate their outputs: `stride1 * (o1 - 1) + span1 = stride2 * (o2 - 1) + span2`, where a padded window or a plain stride has `span = stride`. If one stride divides the other, one output is an affine of the other (`window_pair_equation`). Otherwise (strides 2 and 3) neither output is a function of the other, so the equation is deferred until the extent or one output is solved, and is then checked like any concrete window (gh-ocannl-1972). When `gcd stride1 stride2` does not divide `span1 - span2`, no sizes satisfy the pair, and it is refused at once. A shape scheme's trace, where the widths are unsolved, takes the same path. If nothing ever sizes the extent, closure sets each output to 1 and the pair is refused as a mismatch.

**Projection inference** handles `Affine` terms differently depending on `use_padding`:

- If `use_padding = false`: the effective kernel span is incorporated during shape inference; projection inference just applies the index formula with the actual `stride_offset`.
- If `use_padding = true`: kernel extent doesn't affect shape inference; padding is computed during projection inference, keyed by `proj_id`. Each margin is the maximum, over the constraints involving that projection id, of `left = (span - 1) / 2` and `right = (span + 1) / 2` for the dilated kernel extent `span = effective_kernel_span`. A window reads at `stride * o + offset + dilation * k - left`, so it is centered for an odd kernel at stride 1, dilated or not (before gh-ocannl-1657 the margins were sized by the undilated kernel, leaving a dilated window off-center). An even span puts its extra tap on the right, as PyTorch's `padding='same'` does: `k = 4` reads `o - 1` through `o + 2`, and a 2/2 pool reads `2 * o`, `2 * o + 1`, tiling its operand like TF's `SAME` pool (gh-ocannl-1692). The anchor does not depend on the stride: an odd kernel at `stride > 1` keeps PyTorch's explicit `padding=kernel//2` (the torchvision ResNet convention), not TF's stride-aware `(span - stride) // 2`. Since no operand axis need carry the kernel (a one-operand window, `x ++ "s, 2*o=+k => s, o" ["k"]`), projection inference takes a captured kernel's size from its `Shape.set_dim` (the projection-local sizing constraints of `Shape.bind_delayed_vars_to_envs`), and refuses a padded window whose kernel nothing sized, naming the kernel (gh-ocannl-1691). That covers a kernel an axis carries but nothing sizes, which closure would otherwise guess to `1_(bcast_if_1)`, at any stride; an explicit 1 is a size (gh-ocannl-1983). Where the spec and captures alone condemn the kernel, construction refuses it first, naming the spec too: the operation is never registered, in any mode (gh-ocannl-1983, `Shape.unsized_padded_kernels`; see *Errors* under shape schemes). A padded window can only index an operand: one in an einsum spec's result slot is refused during constraint generation (`Shape.refuse_result_side_padded_window`, gh-ocannl-1550), since writing through it would be a padded transposed convolution, whose projections are not defined.

Shape inference does not maintain padding for axes of individual tensor nodes—these padding values are computed and updated during projections inference.

### Concatenation

The `Concat` constructor represents an axis arising from concatenating of the component dimensions. While for uniformity we use `dim list` here, currently we don't support the components themselves being affine. During shape inference, once the components are known, `Concat` resolves to the sum of the dimensions of the components. When not called from projections inference, also do simplifications that are valid arithmetically but don't make sense as projections: e.g. converting a `Concat` that repeats the same `dim` value (e.g. a variable), into a stride-only `Affine`.

#### Discardable variables in Block specs

For Block/Rev_sides operations (which use `Concat` dimensions), some dimension variables are "discardable" — they are allowed to resolve to dimension 0, which is normally an invalid dimension size. These variables represent parts of concatenated dimensions that are "projected away" and don't participate in actual array indexing.

The name records what the variable licenses — its concatenation component may be discarded, resolving to dimension 0 (the empty summand of the concatenation) — rather than merely the fact that 0 is otherwise an illegal size.

Note that this size-0 unit is the coproduct (concatenation) unit: it is the bottom of the *additive* order that concatenation induces, sits **off** the broadcast order entirely, and must not be conflated with the broadcast error bottom `⊥` (the contradiction state). The claim-free unit `1_(bcast_if_1)` is the **top** of the broadcast order, a distinct thing from both.

A variable `v` is in `discardable_vars` if:
1. `v` appears in a component of a `Concat` dimension on one side (RHS or LHS of the spec)
2. For ALL shapes on the other side, there EXISTS an axis such that for ALL components of that axis, the "complement" of `v`'s component (union of variables from other components of the same `Concat`) has non-empty intersection with that component

This is a four-quantifier condition: ∀shapes ∃axis ∀components: complement ∩ component ≠ ∅

Examples:
- `a^b => a`: `b` is discardable because the complement `{a}` intersects with `{a}` (the single component of the LHS axis)
- `a^b => b`: `a` is discardable because the complement `{b}` intersects with `{b}`
- `a^b => a^b`: neither is discardable (each complement only covers one component of the other side's axis, not all)
- `b^c => a`: no discardable vars because complements `{c}` and `{b}` don't intersect with `{a}`
- `a; b => a^b`: neither is discardable (two RHS shapes; complement `{a}` covers first shape but not second since `{a} ∩ {b} = ∅`)
- `a; b => a^c`: `c` is NOT discardable because complement `{a}` doesn't cover the second RHS shape (axis `b`)

When guessing dimension variables to minimal values (at Stage 5 and Stage 7), variables in `discardable_vars` are guessed to 0 instead of 1. This allows Block specs to express partial assignments and extractions where some concatenation components may be empty.

### Preventing Premature Guessing with Total_elems Constraints

A critical aspect of shape inference is avoiding premature "guessing" of dimension variables to minimal values (dimension-1-no-basis or no-further-axes for rows) when such guessing would make pending constraints unsatisfiable. This is particularly important for `Total_elems` constraints of the form:

```ocaml
Total_elems { numerator = Strided_var { coeff; var; denom }; divided_by }
```

where `var` appears in the numerator and other variables appear in `divided_by`.

The problem: If we guess `var` to be 1 prematurely (before the constraint is resolved), and the denominator variables are later inferred to have values > 1, the constraint becomes unsatisfiable. For example, if the constraint states `total = (64 * var) / [d1, d2]` and we guess `var = 1`, but later infer `d1 = 4` and `d2 = 1`, we get `total = 64 / 4 = 16`, which might not match the actual required total.

The solution: We use the `has_uniq_constr_unless` field in `Bounds_dim` entries to track these dependencies:

1. **Marking Phase**: When a `Total_elems` constraint with a `Strided_var` numerator is encountered, `mark_total_elems_vars` is called to mark the numerator variable with `has_uniq_constr_unless = Some (Set.of_list divided_by)`.

2. **Checking Phase**: Before guessing a terminal variable to 1 in `close_dim_terminal` at Stage 5, we call `can_guess_dim_to_one` to check:
   - If `has_uniq_constr_unless = None`: guessing is allowed (no restriction)
   - If `has_uniq_constr_unless = Some unless_vars`: guessing is allowed only if at least one variable in `unless_vars` is also prevented from guessing (has its own `has_uniq_constr_unless` set)

3. **Cycle Breaking**: The "unless at least one is also prevented" condition prevents infinite prevention chains. If both numerator and denominator variables would block each other indefinitely, the condition allows progress by permitting guessing when mutual prevention is detected.

4. **Deferred Closing**: If a variable cannot be guessed, `close_dim_terminal` returns `Terminal_dim (is_param, dim, origin)` instead of `Dim_eq`, allowing later stages to retry after more constraints are resolved.

This mechanism ensures that `Total_elems` constraints with stride-based numerators are fully resolved before any involved variables are closed to minimal values, preventing the "shape cannot be strided" errors that would otherwise occur.

#### Bounds-aware guessing for round-up totals (gh-ocannl-509)

Routing the default parameter initializer through the packed `uniform` exposed a subtler variant of
the premature-guessing problem, worth spelling out because "has no GLB" is **ambiguous** between
two situations that require opposite treatment:

1. *Genuinely unconstrained*: the row variable has no bounds at all — guessing (e.g. the bare
   `uniform ()` single-block default) is the intended closing policy.
2. *Bounds still arriving*: the row variable has a **registered but unresolved** GLB (its dims
   contain variables that solve only when the surrounding shapes do — e.g. a composite initializer
   `scale * (uniform () - 0.5)` over a parameter whose shape is inferred from its use sites).
   Guessing here commits an inconsistent solution: the counter gets one block and the result one
   128-bit row, and the contradiction only surfaces later — or worse, does not surface at all and
   the random stream silently repeats or truncates.

The round-up `Total_elems` elimination arms therefore distinguish `glb_pending` (a GLB entry exists
in the row environment but `collect_factors` fails on it after substitution) from an absent GLB.
Pending bounds defer the guess through the stored-constraint path; genuinely absent bounds keep the
previous stages and guesses. Sibling rows in a multi-row `Rows_constr` are closed to no-further-axes
before the final stage only when they carry no bounds at all — closing them on stage progression
alone would discard axes whose bounds are still arriving, silently repeating random values along
them. Both deferrals have a final-stage escape: at Stage 7 the guesses fire regardless, because
bounds that have not resolved by then never will, and every constraint must be consumed by the
final stage (see the termination discipline below).

### Inference strategy

The actual shape inference combines row polymorphism with (nominal) subtyping, as known in the type inference literature. The subtyping stems merely from the fact that a dimension-1-no-basis axis can be used in the context of any dimension due to per-axis broadcasting. Row polymorphism stems from broadcasting to more axes: for example, when unifying an unknown (shape) row with a known one, we cannot assume that the unknown row will have just the axes of the known one, because maybe the known row is meant to be broadcasted here to more axes. The combination of row polymorphism with nominal subtyping means that the constraints we are solving are inequalities, both inequalities between rows (the `Row.t` type, i.e. the `row` type above), and between axes/dimensions (the `Row.dim` type). We maintain the inequality ordering between variables in the environment and propagate lower bounds along it during simplification. We also maintain a greatest lower bound on the solution.

```ocaml
type dim_entry =
  | Solved_dim of dim
  | Bounds_dim of {
      is_in_param : bool;
      has_uniq_constr_unless : dim_var_set option;
          (** If set, the variable should not be guessed 1 unless a variable from the set is also
              prevented from being guessed 1. Used to prevent premature guessing for variables in
              Total_elems numerators. *)
      res : dim_var list;
      opnd : dim_var list;
      glb : dim option;
      constr : dim_constraint;
      origin : constraint_origin list;
    }

type row_entry =
  | Solved_row of t
  | Bounds_row of { res : row_var list; opnd : row_var list; glb : t option; constr : row_constraint }

type dim_env = dim_entry Map.M(Dim_var).t
type row_env = row_entry Map.M(Row_var).t

type environment = { dim_env : dim_env; row_env : row_env; discardable_vars : dim_var_set }

type constraint_ =
  | Dim_eq of { d1 : dim; d2 : dim }
  | Row_eq of { r1 : t; r2 : t }
  | Dim_ineq of { res : dim; opnd : dim }
  | Row_ineq of { res : t; opnd : t }
  | Dim_constr of { d : dim; constr : dim_constraint }
  | Rows_constr of { r : t list; constr : row_constraint }
  | Terminal_dim of dim
  | Terminal_row of t
```

We tie the direction of inequalities with capturing information in the structure of tensor expressions: where relevant, `res` is a part of the shape of a result tensor, and `opnd` of a (broadcastable) operand tensor in a tensor expression. This reflects the nature of broadcasting: it is one-directional in that the shape of an operand can be "smaller-than-expected" thanks to broadcasting, but the shape of a result tensor cannot be "smaller-than-expected". The constraint reads `res ⊑ opnd` ("the result refines the operand"). So, for ground (variable-free) dimensions, _res ⊑ opnd_ means: _either res = opnd, or opnd = 1\_(bcast\_if\_1)_ (the claim-free top); and for ground (variable-free) rows, _res ⊑ opnd_ means: _res has at least as many axes as opnd, and for each dimension m of opnd at an axis where res has dimension n, we have n ⊑ m (n = m, or m = 1\_(bcast\_if\_1))_. The greatest lower bound `glb` of a variable is derived from the `res` sides of inequalities with the variable on the `opnd` side, including lower bounds propagated transitively through variable-to-variable inequalities. For example, from `3 ⊑ alpha` and `alpha ⊑ beta`, `beta` receives `3` as part of its `glb`; if `beta` already has the incompatible lower bound `5`, the merged `glb` is the broadcast top `1_(bcast_if_1)`. We don't maintain a least upper bound field; upper-bound information is kept as variable-to-variable constraints and re-emitted when one side is solved. This makes the deterministic closing policy order-independent, but not complete: a satisfiable store can still fail if satisfying it would require relaxing a capped terminal upward instead of closing it to its GLB. For rows, we can substitute the row variable by a new row consisting of variables only, and add the corresponding `dim` inequalities with the variables on the `res` side.

The entry point to shape inference is the shape logic specification, that each operation instance needs to provide. There are shortcuts in the syntax extension `%cd` to make it painless.

```ocaml
type deduce_within_shape = Not_constrained | Input_equals_output

type compose_type =
  | Pointwise_bin
      (** NumPy-style broadcast matching batch, input and output axes, e.g. as in [s1 + s2]. *)
  | Compose
      (** Compose the outputs of the second shape with the inputs of the first shape, i.e. the shape
          of [fun x -> s1(s2(x))], or [s1 * s2] where [*] is the inner product (e.g. matrix
          multiply). *)
  | Einsum of string * Ir.Indexing.variable_ref list
      (** The binary "einsum" syntax: RHS1;RHS2=>LHS, where RHSi, LHS are labels specifications.
          OCANNL's extended einsum notation supports both axis variables and row variables.
          The [axis_labels] use pseudo-labels local to the notation, to line up the axes and row
          variables. The symmetric difference / disjunctive union of RHS1 and RHS2's pseudo-labels
          should be equal to LHS pseudo-labels.

          The optional {!Ir.Indexing.variable_ref}s will capture the solutions of the dimensions

          Note: The "right-hand-side" is on the left! I.e. the syntax is "rhs=>lhs",
          "rhs1;rhs2=>lhs". *)
[@@deriving sexp, equal]

  | Uint4x32_to_prec of Ir.Ops.prec Lazy.t

type ternary_type =
  | Pointwise_tern  (** As in the operation [Where]. *)
  | Compose_accumulate  (** As in the operation [FMA]. *)
```

### Non-tensor-like constraints

The above mechanisms (excluding `dim_constraint` and `row_constraint`) are sufficient to express tensor applications such as inner and outer products, axis permutations. They cannot directly express: size constraints, fixed position indexing (except for the special case of position 0), axis concatenation and "reverse concatenation" / splitting, strides, convolutions. At present, we implement size constraints including against a stride -- a multiple of another dimension, and fixed position indexing.

```ocaml
type dim_constraint = Unconstrained_dim | At_least_dim of int

type total_elems =
  | Num_elems of int
  | Range_elems of { lo : int; hi : int }
      (** The total is any value in the inclusive range [lo..hi]. Arises only from substituting the
          solved variable of a round-up [Strided_var]: the leftover slack window. When the total is
          otherwise unconstrained, late stages prefer [hi] (all blocks fully consumed). *)
  | Strided_var of { coeff : int Utils.safe_lazy; var : dim_var; denom : int; round_up : bool }
      (** The total is [(coeff * var) / denom]. With [round_up], solving for [var] from a known
          total rounds up instead of failing on non-divisibility: [coeff * (var - 1) < total * denom
          <= coeff * var]. Minted only by the [Uint4x32_to_prec] constraint (packed [uniform]),
          whose last 128-bit block may be consumed partially. *)

type row_constraint =
  | Unconstrained
  | Total_elems of { numerator : total_elems; divided_by : dim_var list; keep_axis : bool }
      (** The rows, inclusive of the further row spec, have this many elements. *)
  | Exact of dim list  (** The concatenated rows have these axes. *)
```

The `denom` field accumulates already-closed axes: `reduce_row_constraint` folds the product of a
row's known dimensions into the denominator when storing the constraint on that row's variable, so
a stored `Strided_var { coeff = 4; denom = 10; _ }` means "the remaining open part of the row
contributes `4 * var / 10` elements". Any arm that consumes such a constraint must therefore be
prepared for `coeff <= denom`, not just the freshly-minted `denom = 1` form. Similarly, any arm
that computes a row's element product must use `beg_dims @ dims`, not `dims` alone: block/stack
rows carry leading dimensions in `beg_dims`, and an omission there does not fail loudly — it
miscomputes the product (e.g. a slack-window re-check falsely rejecting a block row whose total was
actually inside the window).

The same `var` can also be a factor of the product the total is compared to: a row tied by product
to a dimension and holding that dimension. There the variable cancels, for `round_up = false`:
`(coeff * var / denom) / (var * rest) = (coeff / denom) / rest`. `var` stays free, and what remains
is the check that `rest` multiplies to `coeff / denom`; a fractional quotient is refused.

During the solution process, the constraints are incorporated, or propagated, into the environment `constr` entry fields, and into further `constraint_` constraints, as needed. This provides sufficient scaffolding to implement the other complex constraints as the need arises.

## Solving the constraints

The constraints are solved by: unification of the equation constraints, unification-like simplification of the inequality constraints, propagation of the complex constraints. The inequalities are like in type systems combining parametric polymorphism with structural and nominal subtyping, where the nominal subtyping relation states that dimension-1 without a basis axis is smaller than all axes, and axes of other mismatching dimensions or mismatching bases are incomparable. For rows, the subtyping is suffix-wise (shorter is smaller) and axis-wise.

Simplification of an inequality, and constraint propagation, can generate more constraints, so we need to be careful to keep it terminating. The solution proceeds in stages. Currently there are 8 stages, with a fractional stage coming from splitting an earlier design.

### Termination and consumption discipline

Two invariants keep the staged solver both terminating and total. They are easy to violate when
adding constraint forms or elimination arms (each was violated, and debugged back to health, while
landing gh-ocannl-509 task 5):

1. **Deferral must go through the stored-constraint path, never through re-emission.** The
   per-stage `solve_inequalities` loop reprocesses the constraint list until it stabilizes, and the
   stability test is structural equality of the list. An elimination arm that "defers" by returning
   a fresh `Rows_constr` livelocks the loop: substitution and origin merging churn the constraint's
   structure every iteration, so the list never stabilizes (the symptom is the process spinning at
   100% CPU inside `Row.solve`/`process_constraint`). The sanctioned way to wait for more
   information is `apply_row_constraint`/`apply_rows_constraint`, which store the (reduced)
   constraint on the row variable's `Bounds_row` entry and return nothing on repeats (the
   `stored`/`updated` flags). Additionally, `close_row_terminal` and `process_shape_row` consult the
   stored `constr` — a row variable carrying a stored constraint is protected from the generic
   final-stage close-to-empty arms, which would otherwise race the deferred consumption.

2. **Every constraint form must have a consumption path that provably fires by Stage 7.**
   `finish_inference` asserts the unsolved list is empty after Stage 7. A match-arm coverage gap —
   for example, an arm guarded by `coeff > denom` when reduction can fold closed axes into `denom`,
   leaving `Strided_var`-against-resolved-GLB unmatched — does not fail loudly: the constraint just
   sits stored forever, the variables it marked via `mark_total_elems_vars` stay unguessable, their
   `Terminal_dim`s keep being re-emitted, and the Stage 7 assertion fires far from the cause. When
   adding a guard to an arm (e.g. to defer a premature guess), pair it with a Stage 7 escape, and
   check the arm inventory: for each syntactic shape of the stored constraint (fresh, reduced,
   variable-solved, GLB-resolved), which arm consumes it, and at which stage?

A practical debugging note: the per-module tracing gates (`OCANNL_LOG_LEVEL_ROW=9` at preprocessing
time, `--ocannl_log_level=9 --ocannl_debug_backend=flushing` at run time — see AGENTS.md) remain
the fastest way to find which arm consumed, deferred, or dropped a constraint; grepping the trace
for the constraint's `dim_var` id reconstructs its lifecycle.

### Stage overview

| Stage | When | Dim vars | Row vars |
|:-----:|------|----------|----------|
| **1** | Online | Unify, propagate | Unify, propagate |
| **2** | On demand | Force precision coefficients | — |
| **3** | On demand | — | Terminal → GLB; one axis if constrained |
| **4** | On demand | Terminal → GLB; propagate `Total_elems` | Terminal → no-further-axes |
| **5** | On demand | Terminal → guess 1 (or 0 if discardable) | `Total_elems`/`Exact` → resolve |
| **6** | On demand | — | All remaining → no-further-axes |
| **7** | On demand | All remaining → LB or 1 (or 0 if discardable) | — |

### Stage details

* **Stage 1** is online as tensors are composed, and conservatively performs unification and constraint propagation. Stages 2–7 are only performed once necessary: when projections or dimensions are requested.
* **Stage 2** forces coefficients coming from precision byte sizes.
* **Stage 3**, when solving the constraints, sets yet-unknown row variables in terminal shapes to their greatest lower bounds GLB (if any), but only if they don't have a `Total_elems 1` constraint and the rank facts allow it: a GLB `flanks.<w>` with non-empty flanks is out of reach of a variable already bounded by `w`, so such a GLB is ignored and the variable's other constraints decide it. For example, a batch-norm statistic over `..c..` is an operand of a tensor over `h, w, ..c..`; that bound is true, and the statistic's row still must not take its axes. It substitutes row variables in terminal shapes that do not have a GLB by one axis if that's required to satisfy the variable's constraint. In `Total_elems` constraints with multiple row variables, it substitutes row variables originating from axes of non-output kind, and which do not have a GLB, by no-further-axes — otherwise these constraints can be too hard to unlock.
* **Stage 4** sets yet-unknown dimensions with >1 upper bounds from direct accesses, or terminal ones, to their GLBs if they have any. It substitutes row variables in terminal shapes that do not have a GLB by no-further-axes. (This is generalized at Stage 6 to all variables.) At this stage, we inject `Shape_row` constraints into the inequalities, so that we can re-process the variables of interest without traversing the whole environment. After row variables are resolved to concrete axes, `Total_elems` constraints with `Num_elems` numerators become simple equations that can be solved deductively — e.g., a row variable resolved to one axis with `Total_elems { numerator = Num_elems n }` yields `dim = n` for that axis.
* **Stage 5** guesses terminal dimension variables without a GLB to dim 1 (or dim 0 if the variable is in `discardable_vars`), **except** when the variable has `has_uniq_constr_unless` set (indicating it's in the numerator of a `Total_elems` constraint) and none of the denominator variables are also prevented from guessing — this prevents premature guessing that would make `Total_elems` constraints unsatisfiable. It also addresses `Total_elems` and `Exact` constraints with yet-unknown row variables heuristically. For `Total_elems` and a single row variable: if the constraint can be satisfied by assuming the row variable is no-further-axes, it sets the row variable to `Broadcastable`, otherwise it sets it to one axis of the required dimension. For multiple row variables, if one is of the Output kind, sets the other variables to no-further-axes, and retries. **Importantly**, when resolving `Total_elems` constraints with `Strided_var` numerators, Stage 5 now looks up the GLB from the row environment even for non-terminal shapes (if the GLB wasn't provided from context). This is critical for cases where shape information flows through intermediate operations (like `pointmul` broadcasting) — the GLB computed from `Row_ineq` constraints becomes available for constraint resolution. When a `Strided_var { coeff; var; denom }` constraint is resolved using a GLB with known total elements `n`, both the row variable and the dimension variable `var` are set: `var = n * denom / coeff` (rounded up for a `round_up` constraint; this arm fires for any `coeff`/`denom` ratio, since reduction folds closed axes into `denom`). For round-up numerators, Stage 5 guessing additionally distinguishes pending from absent bounds — see "Bounds-aware guessing for round-up totals" above.
* **Stage 6** sets row variables in the remaining inequalities and updated shapes to no-further-axes values; it also extends GLB processing to non-terminal shapes. This can unlock further between-axis inequalities because of row variables sandwiched between leftmost axes from their side of the inequality and rightmost axes from the other side of the inequality. In row constraints, this also unlocks inference for the embedded dim variables.
* **Stage 7** sets all dim variables remaining in updated shapes to the upper bound if they have any, otherwise to dimension-1 (or dimension-0 if the variable is in `discardable_vars`).

Let's explain the shape inference functions.

* `s_dim_one_in_entry` / `s_row_one_in_entry`: substitutes the given dim / row variable in one dim / row env entry. Generates new inequalities if the variable was in one of the sides of a `Bounds` entry. Updates the constraint `constr` if the variable appears in it.
* Visiting a solution's entries (gh-ocannl-1904): a solution substitutes itself only into the entries it can change, not into the whole environment. The environment indexes, per variable, the entries mentioning it (written by `set_dim` / `set_row`, through which every write goes), and keeps the entries a visit by an unrelated dimension solution can still change or make emit as pending: a written entry stays pending until such a visit leaves it unchanged and silent. That covers the normalizations `s_dim_one` applies whatever the variable (summing a `Concat` of solved parts, collapsing a window) and `Total_elems` constraints, which re-emit at every dimension solution. `Utils.Tree_map.sparse_mapi` visits them in the whole map's order on the whole map's tree shape, so the environment and the emitted constraints are what the whole map produced; the `shape_substitution_cross_check` setting checks this at every solution.
* `subst_dim` / `subst_row`: substitutes out a variable in a dim / row value, if any.
* `unify_dim`: solves a single equation between two values of type `dim`, and recursively all `dim` equations that this entails, but not other constraints.
* `unify_row`: solves a single equation between two rows, and recursively all `dim` and `row` equations that this entails, but not other constraints.
  * This is a depth-first component of an otherwise breadth-first overall constraint solution process, a "simplify early" optimization.
* `apply_dim_constraint` resp. `apply_row_constraint`: if they cannot make any progress on the constraint, they return `None`. Otherwise, they return a list of derived constraints, and an updated `dim_constraint` resp. `row_constraint`.
* `solve_dim_ineq`: solves a single inequality between two values of type `dim`; returns derived equations and inequalities. It maintains the between-variable bounds and the greatest-lower-bound (GLB). But there can only be one GLB (a dimension > 1) without forcing the bound variable itself to a solved form (with dimension = 1).
* `solve_row_ineq`: solves a single inequality between two rows; returns derived equations and inequalities. It derives between-`dim` inequalities from the known parts of the compared rows. It maintains between-row-variable bounds (when known parts of the rows match) and the GLB. It forces the `res` side to have at least the number of axes of the `opnd` side (via a variables-only `template`). It updates the GLB by computing dimensions-wise GLBs.
* `mark_total_elems_vars`: when a `Total_elems` constraint with `Strided_var { var; _ }` in the numerator and non-empty `divided_by` list is encountered, this function marks `var` with `has_uniq_constr_unless = Some (Set.of_list divided_by)`. This tracking ensures that numerator variables aren't prematurely guessed to 1, which would make the constraint unsatisfiable.
* `can_guess_dim_to_one`: checks if a dimension variable can be guessed to 1. A variable with `has_uniq_constr_unless` can only be guessed if at least one of the "unless" (denominator) variables is also prevented from guessing. This cycle-breaking condition prevents infinite prevention chains where both numerator and denominator would block each other.
* `close_dim_terminal` and `close_row_terminal`: produce equal-to-GLB constraints from `Terminal_dim` and `Terminal_row` constraints produced for shapes of leaf tensors in tensor expressions. Closing to a GLB is a choice rather than an entailment, so `close_row_terminal` and `eliminate_row_constraint` read a row's GLB through `rank_refutes_glb`, which asks the rank graph without recording anything. For dimensions, terminal variables with a GLB close at Stage 4; unconstrained terminal variables without a GLB are guessed at Stage 5, after `can_guess_dim_to_one` checks whether pending `Total_elems` constraints should defer the guess; constrained terminal variables without a GLB are re-emitted until later stages can resolve them. Rows have analogous GLB and no-further-axes stages.
* `eliminate_row_constraint`: resolves row constraints, including `Total_elems` constraints with `Strided_var` numerators. When the `glb` parameter is not provided from context (i.e., for non-terminal shapes), it now looks up the GLB from the row environment. If the GLB has all known dimensions (no unresolved variables after substitution), it uses the GLB to resolve the constraint. For `Strided_var { coeff; var; denom }` constraints with a known GLB of total elements `n`, it emits both `Row_eq` (setting the row variable to the GLB dimensions) and `Dim_eq` (setting `var = n * denom / coeff`). This ensures that dimension variables shared between constraints (e.g., between `Exact [Var var]` on a backbone shape and `Total_elems` on a derived shape) get properly resolved.
* `solve_inequalities`: solves equations, inequalities, and row constraints, until only row constraints remain. Row constraints can "pass" if there is not enough information, rather than reflecting their effect in the environment. Calls `close_dim_terminal` and `close_row_terminal` as appropriate.

The rationale behind only closing leaf (terminal) tensor shapes to their GLBs, while closing the remaining ones to dim-1:

* the composite tensors will get their shapes forced "from below" by their components;
* the leaf tensors cannot have their shape forced as they can always be broadcasted -- the only way they acquire shape information is downstream of `close_row_terminal`.

This leaf-downward policy is deterministic, not complete as a satisfiability procedure. A satisfiable residual dimension store can still be rejected if satisfying it would require relaxing a capped leaf upward instead of committing it to its GLB. For example, with terminal dimensions `alpha` and `beta` and an interior dimension `gamma`, the constraints `3 ⊑ alpha`, `5 ⊑ beta`, `gamma ⊑ alpha`, and `gamma ⊑ beta` are satisfiable by broadcasting one or both terminals to `1_(bcast_if_1)`. The closing policy instead commits `alpha = 3` and `beta = 5`, then re-solving pins `gamma` below two incompatible atoms and reports a shape error. This is intentional policy behavior: closing chooses the least leaf shapes and does not backtrack to larger broadcastable leaves.

## Session consistency: closure, taint and rewind (gh-ocannl-1301)

Shape inference is session-global. `finish_inference` is its only commit point: it solves every active constraint, applies the solution to every active update step, derives their projections, and empties the open state. A tensor whose step it committed is **closed**: its shape carries no variables, and every later step treats it as committed.

**Closed means committed by a successful `finish_inference`, not "compiled".** A closed shape's rows (compared modulo projection ids, which every projection derivation re-mints), its paddings and its padding neutral element never change again. A later operation whose inference would change them is refused before anything is written, naming the closed shape. Writes of an equal value stay allowed: re-applying the environment to a closed operand, or a padded consumer whose margins the operand already carries. Concretely, and this is a behaviour change from earlier releases:

- **A margin-demanding (padded) consumer of a closed tensor is refused even when the tensor was never compiled.** Earlier, an uncompiled tensor's padding silently grew to fit; a compiled one was already refused, because its buffer layout is committed. Build such consumers before closing the tensor (before compiling it, `Shape.to_dims`-ing it or printing it), or consume a materialized copy.
- **A closed operand takes no new top-down precision links**, as a forced one did not already, and an operation that would change a closed operand's precision (the `uint4x32` bit operations) is refused.
- **A closed tensor cannot become a parameter** (`Tensor.param` refuses an initializer that returns one).

Reading a closed shape's committed dims or padding (and a committed step's projections) needs no finalization, so those reads never run the session-global finalizer.

**Taint.** A construction that fails after mutating the inference session taints it. Mutations are the solver's state, active steps and constraints, delayed variable references, the solver's inference sets (`unused_shapes`, the safe-to-guess, use-site-resolution and rank tables), static-symbol role claims, top-down precision links, and graph-root changes (counted by `Row.mutation_serial`, which a write bumps only when it changes something; a repository scan holds every write to `Row`'s and `Shape`'s module-level state to that count, gh-ocannl-1506). Such failures include a shape error in `register_update_step`, an `op_asn` that fails after an inner construction, a `grad_asn` failure, and any failure of `finish_inference` itself. A construction that fails before mutating anything does not taint: a stale operand, a refused `set_dim`, an `op_asn` that fails at once. While the session is tainted, every construction, `finish_inference` (and so forcing an open tensor's dims), code handout (`consume_forward_code` / `consume_backprop_code`) and every `Context` compile (and analyze-only lowering: `lowered_for_decisions`, `decision_surface`) raises:

> the session is inconsistent after an earlier shape error at \<provenance of the first failure\>; call Tensor.rewind_to_last_closure () or Tensor.unsafe_reinitialize ()

**`Tensor.rewind_to_last_closure ()`** discards everything opened since the last successful `finish_inference`: the failed construction, and every construction since that closure, successful or not. It empties the solver's open state and the role claims not yet committed. It restores the graph-root maps as they were at the closure, with the handout markers of the restored roots reset. It restores the cached random seed to the closure's (dropping one created or replaced since), and clears the taint. Tensors, nodes, update steps, and the variable references the discarded work bound or set (captured dimensions, `Shape.get_variable_ref` references) are **discarded**: using one as an operand, handing out or compiling its code, printing it, or transferring, copying or lowering its node raises "… discarded by the rewind after \<provenance\>; re-run its definition". Each `Context` entry point checks before it forces anything of the node, so a discarded node whose dims the closure would have settled is refused by name rather than failing as a shape error (gh-ocannl-1505). The discarded nodes are exactly the ones the frontend allocated since the closure, tracked by uid: a node someone else created in that window (a hand-made `Tnode.create`, a `Persistence.load`) is not discarded, whatever its id. Counters are never reset. Closed and compiled work is untouched: contexts, routines and buffers survive, and nothing executed is undone; code already handed to a caller stays handed out. A rewind without a taint simply discards the open work. Rewinding to a point other than the last closure is an explicit checkpoint's job (below).

**Explicit checkpoints (gh-ocannl-903).** `Tensor.checkpoint ()` snapshots the *open frontier*: the solver's and the graph's module-level session state (the environment, active steps and constraints, the inference sets and rank graph, the pending role claims, the root maps, the seed, the open-node list -- all persistent values, recorded as pointers), and every mutable field of each open object: the shapes and update steps of the active steps, every live capture reference, and every node the open work allocated. `Tensor.rewind ck` puts all of it back, clears the taint, and discards what the window created, with the same stale-handle errors as above; the checkpoint stays valid (rewind to it again to try another continuation), and those taken after it do not. `Tensor.with_checkpoint f` rewinds only when `f` raises (re-raising `f`'s exception); `Tensor.with_rewind f` always rewinds -- a trace that leaves nothing behind, read off inside `f` (a shape scheme's, gh-ocannl-404). A checkpoint costs time linear in the frontier, so take one per phrase, cell or trace, not per operation. The last closure is itself the base checkpoint, with an empty frontier: `rewind_to_last_closure` is a rewind to it.

The rewind refuses, before writing anything, a checkpoint that

- a closure has committed past -- a closure is irreversible;
- was abandoned: a rewind to an earlier checkpoint, `rewind_to_last_closure` or `unsafe_reinitialize` ran since;
- holds memoized state of the window that no rewind can reset: a read of the committed dims, padding or projections of a shape open at the checkpoint that raised (forcing a node's dims while the session is tainted, say: its lazy keeps the exception), or a precision of an open node that began settling.

`rewind_to_last_closure` is always available. The completeness of the snapshot is held by construction: each object's snapshot destructures its record exhaustively (a new field is a compile error until the snapshot accounts for it), and a repository scan (`mutation_serial_scan`) requires every module-level binding of `row.ml`, `shape.ml` and `tensor.ml` whose writes are session mutations to be captured by its file's `capture_globals`, or classified as kept (a registry a rewind extends: the discard registries, external handouts, the closure's record). A tensor's handout marker is restored for the checkpoint's roots -- only a root is ever taken -- so a `take_forward_code` called directly on a non-root in the window keeps its mark.

Construction-time writes on operands' tensor nodes, audited for this contract:

| Write | Verdict |
|---|---|
| top-down precision links | deferred until the operation is registered; skipped on closed operands; every precision write that changes a node's precision counts as a session mutation |
| `uint4x32` precision on operands (`Operation`) | refused when it would change a closed operand |
| memory mode, context ownership, gradient observability (`Tensor.param`) | `param` over a closed tensor is refused |
| memory mode, `host_constant` (literals), `slice_of` (`@\|`) | written on the new node only |
| `alias_of` | written at lowering, not at construction |
| `observable` (Train's loss) | only ever turned on; can pessimise placement, never values |
| static-symbol roles (`used_as_extent` / `used_as_slice`) | claims are deferred to a successful closure, dropped by a rewind; only `Shape` can write the flags |
| any write to a node the open work allocated (precision, memory mode, ownership, observability, ...) | undone by an explicit rewind: the checkpoint snapshots every mutable field of the open nodes |
| a static symbol's declared range (`static_range`) | a user declaration, not inference state: not restored |
| host-init data and registry entries of discarded nodes | unreachable garbage (memory only) |


### Shape schemes

`Tensor.Scheme` (gh-ocannl-404) gives a tensor function a shape *scheme*. This is the explicit, low-level layer; the automatic `%op` integration (gh-ocannl-1751, [syntax extensions](syntax_extensions.md#automatic-shape-schemes)) wraps it in checking mode: a `%op` closure's scheme is traced when the closure is built, and each application checks it, in a rewound window, before the body registers as usual.

- `Tensor.Scheme.trace ~label n f` applies `f` to `n` tracing tensors with fresh row variables, inside `Tensor.with_rewind`. It reads the constraints `f` registered off the open session and leaves nothing behind.
- `Tensor.Scheme.instantiate s ~args ~results` adds those constraints, renamed, for one application to the given argument and result shapes, *without running `f`*. The next closure closes the arguments and results as an inline application of `f` would have.
- `Tensor.Scheme.traced_by build` returns the automatic schemes the `%op` closures built by `build` traced, the ones their applications are checked against (gh-ocannl-1801). An automatic scheme's results are what the traced body returns, found by physical identity among the tensors it made and its arguments (a tuple's components each); its checks relate the arguments only.
- `Tensor.Scheme.to_string s` prints the scheme's boundary like a type: the argument and result rows under the trace's solution, its variables named by first appearance (`'a` generalized, `'_a` fixed), and the broadcasting inequalities among them and the fixed variables, with the function's intermediate variables eliminated. Other constraints (totals, concatenations) are not printed.

What a scheme holds:

- the constraints of the trace's window, in registration order;
- their variables' *solution equations* under the trace's final environment. The solver mints variables while solving and writes them into shapes, and later constraints mention them, so renaming the constraints alone would come apart;
- the boundary rows, the internal rows the closure finalizes (an intermediate's too, as for an update step), and the rows of the pre-existing shapes `f` used, all substituted under that environment;
- the policy marks the trace added (resolve-at-use, concatenation components, and so on), which the rewind takes back.

**Generalization follows ML's value restriction.**

- **Generalized** (renamed per application): the variables minted since the trace began.
- **Fixed:** older ones, from a shared parameter lifted to the function's `()` scope or any tensor made before `trace`.
- A generalized variable the trace tied to a fixed one is re-tied at every application by its solution equation.
- *Anchors* re-tie the fixed variables to their shapes' current rows, so a scheme stays valid across closures.

**Errors.**

- A shape error inside `f` that does not depend on the arguments raises at `trace`. A trailing `set_dim` is covered too: the window is solved once more at Stage1 at the end.
- A window kernel nothing can size raises at `trace` too, because `Shape.propagate_shapes` refuses it for every einsum step, schemed or not, before writing anything (gh-ocannl-1803, gh-ocannl-1983). `Shape.unsized_padded_kernels` reads it off the step's spec and captures: a kernel that occurs only as the kernel of padded (`=+`) windows, and that no capture binds, has no size in any application. Every derivation re-reads the spec with fresh variables, and unification drops a padded window's kernel, so no shape can supply one. Any capture of the label leaves the verdict to the closure, set or not, and so does an axis carrying the kernel.
- One that depends on the arguments raises at `instantiate`, before any closure. The instantiated constraints carry an origin naming the scheme and the application, so a closure-time failure names them as well.

**Refused, by design:**

- forcing dims during a trace: `finish_inference` raises before committing anything;
- a total-elements constraint whose coefficient is a lazy of unknown provenance;
- `Shape.set_dim`, `set_sym_dim`, `set_equal` or `set_scale` on a capture reference made outside `f`;
- after a closure, a scheme that depends on open state no shape it used holds.

**Capture references made outside `f`** (gh-ocannl-1791). A reference made before the trace that `f`'s operations bind (`~capture_dims`) is an input of the scheme. The trace sees it as unbound and unsolved, so the scheme does not depend on its state at trace time. Each application relates the variable of its first binding in `f` to the reference's state at that application, exactly as the body's own first binding would: an open binding (dimension, row, or the product of a row and a dimension), or a solution held across a closure. A reference shared by several applications therefore keeps them consistent, and an application that conflicts with what an earlier one bound it to is refused at `instantiate`. An explicit `instantiate` also binds the reference, so its solution is published, after the application's Stage-1 solve and at the closure. The scheme's printout lists each input as `capture <label> = <its first binding>`.

**Random draws in `f`** (gh-ocannl-1890). A packed uint4x32 conversion (`uniform`, `uniform_at`, dropout's mask, a default-initialized `{ w }` declared inside `f`) registers a total-elements constraint whose coefficient, the values per 128-bit block, depends on the conversion result's precision. That coefficient is a lazy over the result node's own `storage_prec` (`Tensor.op` passes it to `Uint4x32_to_prec`). The node's consumers set the precision top-down (`update_infer_prec`) as they register, and only Stage 2 and later stages read a lazy coefficient, so it is forced at the closure and reads its call site's precision with no step of its own. A scheme never reads it: its trace, checks and instances solve Stage 1 only. The scheme therefore carries a hole in its place, holding none of the trace's nodes (the trace's final environment, kept for printing, is scrubbed too), and the conversion node each application's body registers fills it. An automatic `%op` scheme checks the shapes around the draw, and its body then registers the draw against its own precision. An explicit `instantiate` has no body and no conversion node, so it refuses a scheme with draws.

A capture reference bound both as a dimension and as a row inside `f` is carried as well: the product tie between the two is a constant (`Utils.safe_value`).

A failed application taints the session, as a failed construction does.

#### What schemes buy, measured

gh-ocannl-404 claimed two benefits for schemes: errors reported earlier, and cheaper inference on repeated blocks. gh-ocannl-1752 measured both. The second claim does not hold. Schemes are worth keeping for the errors alone: they check an application, and the body registers its own shapes.

**Inference cost.** `test/operations/scheme_payoff.ml` builds three stacks of depth N and forces their closure, with nothing compiled:

- `distinct`: N blocks, each its own closure, `ln (x + ffn x)` from the schemed `mlp_layer` and `layer_norm`;
- `shared`: one such closure applied N times (a weight-tied stack);
- `decoder`: `Nn_blocks.decoder_only`, today a schemed stack of schemed blocks (gh-ocannl-1792, gh-ocannl-1814). At the table's commit its blocks were unschemed, while their feed-forward layers and layer norms were schemed.

Checking mode costs a constant factor, about 2x on the block stacks and 5x on the decoder, whose scheme traces the whole stack (two thirds of its `check` time at N=16). The extra time is its traces plus a rewound instantiation per application. It leaves the closure's constraint store exactly as it is with the schemes off.

**Which applications are checked** (gh-ocannl-1814). The outermost schemed ones. A trace runs the schemed applications in its body plain, so the outer scheme already holds their constraints, and checking them while the body runs re-solved a renamed subset of what the outer check had just found consistent. So the body of a checked application runs with its nested applications unchecked: one `block` is one check of 127 + 29 + 15 (constraints, solutions, boundary) instead of three checks of 215 + 53 + 33, and a transformer block one check instead of eight. This moves no error, because the outer check always ran first: a nested argument error was already reported naming the outer function, and a nested check could only speak after the outer one had passed. `scheme_error_locality`'s second table pins it, against a control that checks the nested applications too. A nested application is still checked where nothing vouches for it: under an opted-out function, a refused one, or any other application that did not run a check. And a function's first application still traces its presence patterns when it has several, since the outer window holds only the one applied. A body breaking the determinism premise (its graph depending on anything but its closure and its arguments' shapes) still registers inline, so its error surfaces in the body or at the closure.

This is what lets `Nn_blocks`' stacks carry schemes: `decoder_only` at depth N is one check, instantiating the same N windows of constraints the N block checks did. What a stack scheme adds is its traces, one per presence pattern, each under one build (below), and what it buys is the whole model's signature and one refusal naming the model. Each layer's own trace at its `()` stage stays, though no application of it is checked: a closure built and never applied has no outer window to report its contradiction.

**Why a scheme cannot stand in for the body's registration.** Instantiating a scheme costs about what registering the body does. Per block here, an instantiation carries the trace's constraints and their solution equations (127 + 29), against the 183 constraints the block's inline registration produces. Instantiating one application takes 2.7 ms, while registering the whole body inline takes 2.3 ms. So a design that instantiates the scheme and then skips the body's own derivation is slower than inline registration even at depth 1, and the constraints it leaves pending beside the body's ties multiply the solver's work with depth. Schemes therefore only check.

Without schemes, inference was superlinear in depth (`decoder` went from 455 ms at N=4 to 2,046 ms at N=8). The rank-cycle check was not what drove it at those depths (gh-ocannl-1802): even walking everything a new rank edge's target reaches, it took a few percent of the run. Most of the time went to substituting each solution into every entry of the environment, and to the garbage collector behind it. Building each entry's provenance only when it yields an inequality, together with a level-bounded search, cut schemes-off inference to 0.67-0.83x, and indexing the entries each solution can change (gh-ocannl-1904) made substitution's work double per depth doubling (`registration_counts.subst_visits`). That left the rank-cycle search the largest solver term: 4x visits per doubling, and 18.3 s of a 42.9 s `check` run at decoder depth 64 once a whole-stack trace could reach that depth. A rank potential now answers it (gh-ocannl-1891): an edge that already satisfies `p v >= p w + k` needs no search, and one that breaks it moves only what must move. Its work (`registration_counts.rank_search_visits`) doubles per depth doubling, at 182 against 318,161 visits for `decoder` at N=16 with schemes off. At N=16 that takes `decoder` from 536 to 329 ms off and from 1,875 to 1,462 ms under `check` (median of 5 on cc, mac-studio M4 Max, in an exclusive window, against `939ee9731`), and `distinct` and `shared` from 113 to 87 ms and from 100 to 72 ms off. Allocation still grows above 2x per doubling in deep stacks, with schemes off too: 2.1-2.9x from depth 2 to 64 for `decoder`, and a profile points at tensor construction's per-op set unions.

**Tracing a whole stack.** The cost above is per-block traces, which is all that `decoder_only` had before it was schemed: its `tracing` column stayed about what it was (799 against 825 ms at N=16). A trace of the whole stack is a different computation. It leaves every dimension unsolved, its end validation repeats every inequality, and that used to be exponential: the dimension-cycle check of `Dim_ineq` walked every path of the bounds graph, and every residual connection multiplies them, so a decoder of depth 4 took over a minute, nearly all of it in that one validation (gh-ocannl-1891). The check now visits each variable once and skips an edge already recorded. `scheme_payoff.exe --stacks 5 decoder=2,4,8,16,32,64 resnet=2,4,8,16,32` measures one trace, with the closure built outside its window, against one build of the model without schemes:

| --- | --- | --- | --- |

| contradicting parameters | no | application (body) | definition |

| window kernel nothing sizes | no | closure | definition |

| cyclic row permutation, abstract argument | yes | closure | closure |

The mode-independent facts are claimed:

- every mode accepts and refuses the same programs;
- no error surfaces later under a scheme.

Three kinds of error move earlier. An argument-independent contradiction moves to the definition, or to the first application for a function without a `()` stage. So does a window kernel nothing can size, which no contradiction shows: the spec and its captures decide it. An argument-dependent error is reported at the application before the body runs, naming the function and the argument. That includes a concatenation that Stage 1 alone leaves to the closure without schemes.

The classes that stay late all need what a trace deliberately does not run, namely the closing stages. The trace validates at Stage 1 only, because the closing stages would default the generic arguments.

- *Undetermined components*: the free dimension reaches the result, so a consumer of the result can still determine it. It must stay late.
- *Underspecification: a forgotten hidden dimension, a parameter sized by a fixed index.* Reported at the closure by design (gh-ocannl-1803). Reporting anticipated underspecification early is too ambitious for the core calculus in the general case, and the fixed-index case alone does not justify an analysis: if one is ever done, it should cover the whole class. The closure's messages already name the cause. Do not re-file either as a missing scheme check. The unsized kernel above is not part of this class: the spec decides it, so no analysis is involved.
- *The abstract cyclic permutation*: an incompleteness of the closing policy, not a contradiction. A trace must not report it.

## Projections inference

Unlike shape inference proper, constraints that participate in projections inference pertain to a single assignment, and projection equations only tie individual instances of tensor accesses in the assignments. In particular even if the same tensor repeats in the assignments, the distinct instances will have different projection ids and participate in disjoint equations, so that they can be indexed differently.


```ocaml
type proj = Var of dim_var | Proj of { proj_id : int; d : int } | Solved of axis_index
type proj_to_index = Ir.Indexing.axis_index Map.M(Int).t
type proj_classes = int Map.M(Int).t

type proj_env = {
  proj_to_index : proj_to_index;
  proj_classes : proj_classes;
  product_dim : int Map.M(Int).t;
  non_product : Set.M(Int).t;
}
```

The projection inference functions.

* `get_proj_equations inequalities proj_axis_env env` converts both equations and inequalitites to projection equations. For inequalities, it takes broadcasting into account, and equates a potentially-broadcasted dim-1 projection to `Fixed_idx 0`. `proj_axis_env` originates from the `Shape` module, holds projections from the slice operator and the einsum syntax.
* `solve_proj_equations` unifies the projection equations, using union-find to maintain a representative for equal projections. Projections that already have an `axis_index` are `non_product` (not to be iterated over). The remaining projections have a `product_dim`, and get a fresh iterator. A projection variable is bound to the projection an equation pairs it with, and the bindings stay acyclic, since every reader follows them without a visited set: an equation that already holds through the bindings (`b = a` after `a = b`) is dropped, and one under which the variable would occur inside a window of its own projection (`v = 2*v`, directly or through other variables) is refused with a `Shape_error` naming the variables of the cycle (gh-ocannl-1790). An equation no binding can carry -- a window or concatenation equated to a solved index (a slice's), or two windows of different strides -- is verified once every index is assigned, against the environment returned: the two sides must index alike, or the solve is refused with a `Shape_error` (gh-ocannl-1889; the verification used to swallow every error, so such a program lowered with one side's index dropped). A window's target gets its index in dependency order, so a window over another window's target reads the index that target ends up with; windows that range over each other's targets are an unknown projection (gh-ocannl-1971). A concatenated tensor axis with a variable component closes to a plain dimension of the summed extent, so a later step's slice, fixed index or window treats it as a plain axis and never reaches the verification with a concatenation side. Two rows keep the concatenation, as substitution is what sums the components: a component with a symbolic extent, which `get_proj_equations` refuses, since where the segments after it start would depend on the launch-time extent; and integer components alone (`=> 2^3`), whose own step does not derive.
* `get_dim_index` gets an `axis_index` for a `dim` based on the representative of its `proj_id`; and `Fixed_idx 0` for dim=1. A window (`Affine`) axis is indexed through its projection (`dim_to_proj`), whose kernel extent (which sizes a padded window's margins) is read off the dim as the row holds it: a solved kernel directly, a kernel variable through the projection environment, as `get_proj_index` reads one; a kernel it does not size is the `get_proj_equations` refusal naming the kernel, and a symbolic kernel is refused the same way (gh-ocannl-1734). An iterated axis without a `proj_id` is refused with a `Shape_error`: the projection environment never saw it, and no route through `Shape` reaches it, because `derive_projections` freshens the `proj_id`s of every shape it indexes first (gh-ocannl-1790).

### Dim-1 projections are pinned — route load-bearing projections around them

Several rules pin the projection of a dimension-1 axis to `Fixed_idx 0` (a broadcasted dim-1
operand axis is not iterated). A consequence for anyone *emitting* projection equations: never pair
a semantically load-bearing projection with an axis that may be dim-1, because the `Fixed_idx 0`
pinning will win in the union-find and the projection collapses **silently** — there is no
contradiction error, just wrong (typically constant-zero) indices in the generated code.

The concrete instance (gh-ocannl-509): the packed `uniform` conversion's strided store projection
`stride * counter` carries the entire flat offset of the result, and was paired with the innermost
axis unconditionally. A result with a trailing dim-1 axis — a conv kernel with a single input
channel — lost the stride: every 128-bit block stored at flat offset 0, leaving all later cells
uninitialized (NaN-filled parameters, with no shape error anywhere). The arm now pairs the strided
projection with the innermost axis of dimension greater than 1 and maps the skipped trailing dim-1
axes to `Sub_axis`, which multiplies the row-major offset by 1 and leaves store offsets unchanged.
The general lesson: a projection equation is only as strong as its weakest (most-pinnable) side,
and misrouted projections manifest as wrong values, not as inference failures — executed-value
tests (materialized-vs-virtual parity, distinct-value counts) are the effective guard, not
structural checks.

### Symbolic extents: cells past a bound extent

A symbolic dimension (`Row.Sym`, set with `Shape.set_sym_dim`; design record
`archive/docs/proposals/gh-ocannl-490.md`) is materialized at its declared maximum: `Tnode.dims`, buffers,
product spaces and loops all span the maximum. When the extent's symbol is among a routine's
bindings it is a launch parameter, and lowering guards the body of every loop over a symbolic axis
with `iterator < extent` (`extent_guard` in `Assignments.to_low_level`). An extent left unbound keeps
the maximum-shape semantics: the program is the one the maximum, written as a concrete dimension,
would give. For a run with the extent bound to `e`, a cell is *past the extent* when its index along
a symbolic axis is at least `e`, and the contract about those cells is (gh-ocannl-928):

- **Reads.** No in-extent result depends on a cell past the extent: a reduction over the symbolic
  axis accumulates its first `e` rows, and every other accumulation over it computes in-extent cells
  only, so what an operand holds past the extent cannot reach an in-extent result.
- **A non-initializing accumulation leaves the cells past the extent untouched.** An accumulation that
  reads its target's prior content (`=+`, `=-`, ...: every backprop contribution, an optimizer's
  `p =- lr * delta`) writes in-extent cells only. This is what makes state carried across runs at
  DIFFERENT extents well defined: a parameter does not move where its rows were out of extent, and
  a gradient accumulated over micro-steps (`Train.grad_update ~accum_steps`) holds in each row
  exactly the micro-steps that row was in extent for.
- **An initializing accumulation leaves them unspecified.** An initializing accumulation (`=:`,
  `=:+`, ...) never reads its target's prior content, so whatever it leaves past the extent cannot
  reach an in-extent result of this run, and a later run re-initializes before it reads. Today
  those cells are untouched: when lowering emits an initialization pass (the target is not covered
  one-to-one, e.g. a reduction onto the symbolic axis), that pass carries the body's
  `iterator < extent` guard on every target axis a bound extent indexes, so it stores to the
  in-extent cells only (the guarded loop itself still spans the maximum, as the body's does). This
  is not promised: lowering to symbolic loop bounds, or a schedule that rewrites the pass, may
  change it. Read the valid prefix on the
  host.
- **A fill covers the materialized buffer.** A `Fetch` (constant fills, the `zero_grads` of every
  gradient, ranges) carries no projections and so no extent: it writes every cell up to the
  maximum, even in a routine whose extent is bound. The guarded initialization pass above is not a
  `Fetch`. This half IS promised, because the second rule relies on it: `zero_grads` clears every
  gradient row, including the rows a later, larger extent brings into scope.
- **A maximum-one axis cannot be guarded, so it is refused.** The guard is per iterator, and a
  dimension-1 axis has none (it is indexed at `Fixed_idx 0`, see above), so lowering refuses a bound
  maximum-one extent in both of `Accum_op`'s roles — the ordinary one and the `Rev_sides` scatter
  that a concatenation's gradient lowers to (gh-ocannl-878). A packed vector store (`Set_vec_unop`)
  refuses any bound extent (gh-ocannl-817).

`test/operations/symbolic_extent_contract.ml` pins the first three rules on executed values, for
both flavours of one accumulation record, with an unguarded control; `symbolic_extent_backward.ml`
pins the gradient side through `Train.grad_update`, `Train.sgd_update`, accumulation across two
extents and the `Rev_sides` scatter, executed where it is guarded and refused where it is not.

### Convolutions

There is an important and intentional difference between `dims` in the `arrayjit` part of the project: tensor nodes, `Ndarray` buffers, code generation -- they include padding in the dimension sizes; and on the other hand shape types, shape inference and tensors exclude padding from the dimension sizes. There is a tension: once the delayed computations of padding, projections and dims (dimension sizes) are forced for a particular node, the padding can no longer be updated (the underlying `Ndarray` buffer might already be created). Since during inference we update the padding incrementally without variables standing in for insufficient information, this unfortunately causes observability of the during-inference and post-inference distinction for the padding of a tensor node.

### Concatenation

Projections inference for `Concat` variants is significantly more than deriving the `Concat` constructors of the `axis_index` type: concatenation affects how the `components` field is computed. Without any use of `Concat`, `components` would be an array of singleton lists. With occurrences of `Concat`, we need to build a hypergraph where vertices are the symbols (or canonical `proj_id`s), and hyperedges are the `Concat` axis indices. We decompose this graph into connected components. Then, each `components` entry is one connected component, pairing each of its symbols with the size of the corresponding dimension.

Importantly, dim-1 projections that participate in `Concat` axes are not converted to `Fixed_idx 0` expressions; we need symbols for all `Concat` participants for book-keeping during lowering.

## Deriving the constraints

Other important functions in the `Shape` module.

* `einsum_slot_spec_to_dims_bio` parses an einsum spec for a single shape, returns the three rows and a mapping from axis (`dim`) variables to indices where the einsum specifies fixed indexing.
* `get_inequalities` builds row inequalities by pairing the rows of the current shape (as `res`) with the rows of sub-shapes (as `opnd`). It also derives a batch row constraint for terminals initialized with `Constant_fill values`. For `Batch_slice` (the `@|` operation) it waits till the batch row variables (if any) are solved, and derives row equations (not inequalities) between the current shape and the sub-shape, with `cur_sh.batch.dims` expanded to account for the slicing / indexing. For einsum specs, it derives equations (not inequalities), equating the current shape with the lhs spec shape, and the rhs spec shapes with the sub-shapes. This means einsum operations do NOT permit broadcasting, unlike pointwise and compose operations which use inequalities.
* `propagate_shapes` gets and then solves the inequalities, using a global state for the environment. It udpates the shapes in-place with the partial solution. It is invoked twice for each `update_step`: first during the bottom-up process of building tensors, and then in reverse order from `finish_inference`.
* `finish_inference` is called right before some projections or array dimensions are required (typically, because of jitting). It performs a second round of `propagate_shapes`, and then once again attempts to solve any remaining constraints that `propagate_shapes` didn't solve. Then it "closes the shapes": substitutes out remaining shape variables by their GLBs if any, or dimension-1 / `Broadcastable` (no-more-axes). Then it resets the environment state, since the shapes are now guaranteed to not have variables.
* `derive_projections` starts by giving every repeated occurrence of one shape among the step's operands its own shallow copy (`dealias_operands`: freshening happens in place, so without the copy the occurrences would share `proj_id`s, contrary to the distinct-instances rule above), then freshens the `proj_id`s in the `update_step`. Then it generates and solves shape inequalities, and then generates and solves projection equations, and constructs the `projections` record.
* `of_spec` constructs a shape record from an einsum slot spec. If `deduced = Input_equals_output`, it adds the corresponding equation to the global environment.
