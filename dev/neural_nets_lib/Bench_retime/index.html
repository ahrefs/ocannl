Module Bench_retime

Re-timing a shipped routine with a stated, measured spread (gh-ocannl-1524).

A runner that compiles a routine (a tuned winner, a model pick, an untuned default) and then reports how fast it runs used to time it min-of-N synchronized runs, once. On a kernel under ~50 us that single minimum is noise-dominated: on cc, gh-ocannl-1397's unchanged control site read 0.69x between two builds and a changed site 1.44x the wrong way, while the search's own best_ms (the tuner's queued protocol) agreed with itself to a few percent. Two things were missing, and this module supplies both:

  • The tuner's protocol. Each reading is one Autotune.time_routine call under the configured autotune_timing and autotune_repeats -- warmup, calibration to a ~10 ms batch (on cc and Metal up to 200 launches per synchronization), and a minimum over a top-up window -- so a re-timing measures the quantity a search ranked its candidates by, with the submit/sync round trip amortized rather than paid per reading.
  • A spread. A routine is read calls times, each call independent (its own warmup, calibration and window), and the report is the median of those readings with their range. Several routines are read in one session, interleaved in Bench_design's spread mirrored rotation, so a drift over the session lands on every routine alike; their ratio is PAIRED, call by call, and reported as the median paired ratio with its range. A ratio is resolved only when every pair agrees on its side of 1 -- with the default six calls, the exact two-sided sign-test p of that outcome is 2/64 = 0.031.

Below min_readings admitted readings a spread is not stated: its bounds are NaN and a ratio over it is never resolved. A reading the tuner's admission gate refuses (Autotune.admitted_timing_ms: host contention, an unbatched calibration, a clock that resolved nothing) is counted as refused and left out, never ranked.

Boundary: the spread is the session's -- what this process measured about routines it compiled. Two builds compared across processes (a base and a head) carry, on top, whatever differs between the processes (code placement, the tuned arm's crown); pair them through benchmarks/ab.py or benchmarks/bin_cells.py, round by round, and read each process's own spread beside the paired ratio.

val min_readings : int
val calls_of_env : unit -> Base.Int.t

calls_of_env (): BENCH_RETIME_CALLS (default 6), the timing calls per routine. Even, because Bench_design mirrors every batch, and at least min_readings.

type spread = {
  1. ms : Base.float;
    (*

    The median admitted reading; NaN with none.

    *)
  2. lo_ms : Base.float;
    (*

    The least admitted reading; NaN below min_readings.

    *)
  3. hi_ms : Base.float;
    (*

    The greatest admitted reading; NaN below min_readings.

    *)
  4. admitted : Base.int;
  5. refused : Base.int;
}

One routine's re-timing: per-launch milliseconds, each reading one Autotune.time_routine call.

val median : Base.Float.t Base.Array.t -> Base.Float.t
val sorted_admitted : Base.Float.t option Base.Array.t -> Base.Float.t Base.Array.t
val spread_of : Base.float Base.option Base.array -> spread

spread_of readings: the summary of one routine's readings, None for a refused call.

val rel_spread : spread -> Base__Float.t

rel_spread s: (hi - lo) / median, the spread as a fraction of the reading; NaN unstated.

type ratio = {
  1. ratio : Base.float;
    (*

    The median of the paired ratios; NaN with no pair.

    *)
  2. ratio_lo : Base.float;
    (*

    The least paired ratio; NaN below min_readings pairs.

    *)
  3. ratio_hi : Base.float;
    (*

    The greatest paired ratio; NaN below min_readings pairs.

    *)
  4. pairs : Base.int;
    (*

    The calls at which both routines' readings were admitted.

    *)
  5. resolved : Base.bool;
    (*

    At least min_readings pairs and every paired ratio on one side of 1: the two routines differ by more than the session's noise. Unresolved is "within the spread", not "equal".

    *)
}
val paired_ratio : num:Base.float Base.option Base.array -> den:Base.float Base.option Base.array -> ratio

paired_ratio ~num ~den: num's readings over den's, call by call. The two arrays are two routines' readings from one retime session, index i of each taken in the same mirrored batch, so a drift common to the batch divides out.

val bounds_fields : name:string -> spread -> string

bounds_fields ~name s: name_lo=<ms> name_hi=<ms> name_retimed=<admitted>/<calls>, for a line that prints the median name=<ms> elsewhere.

val spread_fields : name:string -> spread -> string

spread_fields ~name s: name=<ms> then bounds_fields, the one spelling every runner's line uses.

val ratio_fields : name:string -> ratio -> string

ratio_fields ~name r: name=<r> name_lo=<r> name_hi=<r> name_resolved=<bool>.

val configured_timing : unit -> Autotune.timing_mode

The configured objective, read as Autotune.tune reads it.

val retime : ?calls:??? -> (Context.t * Context.routine) Base.list -> Autotune.timing_mode * Base.float option Base.Array.t list

retime ?calls routines: every routine's readings, calls (default calls_of_env) per routine, in Bench_design.orders' visiting order, each reading an independent Autotune.time_routine call under configured_timing and the configured autotune_repeats, admitted through Autotune.admitted_timing_ms. The result is in the input's order, one array of calls readings per routine, index i taken in batch i.

Timing dispatches each routine many times against its live buffers (Autotune.time_routine restores nothing), so a caller checking a routine's output runs it once more afterwards from inputs that are not its own outputs, as an exactness oracle must anyway.
