The arms

val arm_entry : plan -> arm -> Base.String.t -> SC.entry -> SC.entry

What arm replays for one of the control's entries.

val spliced_segments : plan -> Base.Int.t
val differing_targets : plan -> Base.Int.t
val write_arm : ?cache_dir:??? -> plan -> arm:arm -> unit -> (Base__Int.t, Base.String.t) Base.result

Writes arm's cache into cache_dir -- by default the configured autotune_cache_dir, the directory the runner's tuning call then replays (Autotune.resolve_cache_dir) -- which must be absent or an empty directory: every schedule entry the control holds (the targeted ones spliced for the treatment arm) and the control's placement decisions, so both arms ship the control's placement. Refused when nothing is spliced, and when the cache refused a store (read back from SC.recording_cache_io, since SC.store absorbs refusals). Returns the number of entries written.

The listing

val ops_summary : SC.saved_schedule -> Base.String.t

The plan as lines for stderr: every entry present in both caches, with a row per segment of a fissioned one -- position, kind, units, digest, how many segments share it, whether the two winners' schedules agree, whether a target selects it, and both schedules' operations.

The runner mode

val env : string -> Base.String.t Base.Option.t
val fail : ('a, unit, string, 'b) Stdlib.format4 -> 'a
val from_env : tune:Base.bool -> plan option

The splice mode of a runner, from the environment: None when BENCH_SPLICE_CONTROL is unset. Otherwise it needs BENCH_SPLICE_TREATMENT (both schedule-cache directories, read and never written), and then either BENCH_SPLICE_LIST=1 -- print describe on stderr and exit 0, before any fixture is read -- or BENCH_SPLICE_TARGET (a comma-separated list of digest prefixes and [<entry>]#<index>) and BENCH_SPLICE_ARM=control|treatment, in which case it writes that arm's cache into the configured autotune_cache_dir, which must be set explicitly and absent or empty, and returns the plan: the runner's compile, inside replay_guarded, then replays it from there. BENCH_SPLICE_ADOPT_VERSION=<n> adopts the control's entries stored at entry version n: a treatment that adds a search branch bumps Schedule_cache.entry_version without changing what a saved schedule means (across a bump that changed the saved format the entries fail to decode; one that changed the canonical rendering fails the replay's segment-digest check). A replay arm must not search, so it is refused unless tune is on and autotune_search is off: a key the arm's cache lacks then ships the untuned default, which replay_guarded turns into a failed run. Every refusal exits 2 with its reason on stderr.

val replay_verdict : plan -> looked_up:Base.string Base.List.t -> arm_reports:int -> (unit, string) Base.result

Whether a compile that looked up the cache keys looked_up and reported arm_reports placement arms measured the splice: it must have replayed the control's placement decision, which decides which candidate ships (one arm reported per decision lookup), replayed at least one routine the plan splices -- inputs holding several workloads or profiles can splice one routine while the run replays another, untargeted one, whose two arms are then the same control schedule -- and no routine a target was left unspliced in, which replays only off the control's placement decision (a forced tune_ship_arm, say). Other untargeted routines replay the control in both arms, which is the method.

val replay_guarded : plan option -> counts:(unit -> int * int * int * int) -> (Base.unit -> 'a) -> 'a

replay_guarded session ~counts compile runs a runner's compile -- directly without a splice session -- and otherwise records the schedule-cache lookups it makes, then exits 1 when the step did not come entirely from the arm's cache (counts reads the runner's searches, replays, untuned fallbacks and placement-arm reports after the compile), or did not replay the control's placement decision and a spliced routine (replay_verdict).
