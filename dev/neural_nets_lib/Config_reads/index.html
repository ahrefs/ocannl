Module Config_reads

What ocannl_read_config writes, and what each value it writes MEANS (gh-ocannl-1581).

The reader resolves a configuration key the way a test run will and writes the answer to ocannl_<key>.txt, which rules elsewhere read back through %{read:…}: a per-backend golden's name, an emitted-code artifact's suffix. Its decisions about the backend live here rather than in its executable, so that a scan reading such a pform back can say which backend a value stands for by asking the code that wrote it: cu means CUDA because written says a CUDA build writes cu to ocannl_backend_extension.txt, not because a second table in the scan agrees with the reader today. The inverse (backends_meant) is that same function run over every backend.

val file_of_key : Base.String.t -> Base.String.t

The file --read=<key> writes, in the working directory of the rule running it.

val deprecated_aliases : (string * string) list

The deprecated spellings the backend selector still accepts, each with the backend it names: the entries of Backends.accepted_names that are not a backend's own name. test/operations/marker_backend_vocabulary holds the two equal, so an alias added to the parse table alone fails there rather than resolving here to a name no backend has. Restated rather than read because this library links base alone, for the tests and scans that link no backend.

val canonical_backend : Base.String.t -> Base.String.t

A backend setting as the backend's own name: lower case, a deprecated alias resolved. A stream or log file is named after the canonical backend (e.g. log_files/micrograd_demo_logging/cc-0-0.log), so an alias-spelled run must not leak the raw string into the paths dune reads.

val code_extension : string -> string option

The extension a backend's emitted code carries, without the dot, for a canonical backend name; None for a name this reader was never taught. marker_backend_vocabulary holds it equal, for every backend OCANNL has, to the source_extension fact the backend's artifact writer appends (Ir.Backend_intf.backend_facts); restated for the same reason as deprecated_aliases.

val backend_keys : string list

The keys whose value the backend setting alone decides.

val written : key:string -> Base.String.t -> Base.String.t option

What --read=<key> writes when the backend setting resolves to setting, for each of backend_keys; None for any other key, which the reader answers with the key's raw text. An unknown backend emits C, the default backend's dialect.

val backends_meant : backends:Base.String.t Base.List.t -> pform:Base.String.t -> value:Base.String.t -> Base.String.t Base.List.t Base.Option.t

The backends, among backends, whose build writes value into the file the pform pform reads: Some when pform is a read: of a file this reader writes for one of backend_keys, matched by its base name, and None for any other pform, whose value says nothing about the backend. Some [] is a value no backend's build writes -- a golden only it names is compared by no run at all.
