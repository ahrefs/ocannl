Module Ocannl.Calibrate

Memory-bandwidth calibration (gh-ocannl-578): STREAM-style streaming kernels whose byte counts are exact by construction — one access site per tensor node and direction, no guards — so the calibration rows they append under config autotune_calibration_file satisfy the fitter's per-leg exactness rule and can constrain the envelope's memory leg (model_peak_memory_bandwidth). Matmul-family tuning data cannot: its rows are compute-bound (their bytes-over-time understates achievable bandwidth no matter how exactly counted) and typically carry guards-taken/union upper bounds, so the fit of the memory leg needs exactly this kind of calibration diversity — see tools/calibrate_bandwidth.ml for the command-line entry point and Ir.Cost_model.Calibration for the fit semantics.

val stream : ?elems:??? -> ?repeats:??? -> Context.t -> (Base.string * Autotune.report) Base.List.t

stream ?elems ?repeats ctx times the four STREAM kernels — copy c =: a, scale b =: 0.5 *. a, add c =: a + b, triad a =: b + 0.5 *. c — over 1-D single-precision tensors of elems cells each (default 2^26, 256 MiB per tensor: well past any last-level cache, so the measured rates are main-memory rates). Each kernel goes through Autotune.tune with seed candidates only (~rounds:0) and the schedule cache disabled, so every timed candidate appends a calibration row through the ordinary emission path; the search is forced on (~search:true) — timing is the point of a calibration pass, whatever profile the config picked. Choose elems a power of two: an extent every workgroup size divides evenly keeps the parallelized candidates free of range guards, hence their rows bytes-exact.

Returns the kernels' tuning reports in order, (name, report). Raises Utils.User_error when config autotune_calibration_file is not set — the pass would time kernels with nowhere to record them.

Cache-capacity calibration (gh-ocannl-1253)

The ranking score (Ir.Cost_model.ranking_seconds) charges an untiled contraction's operand re-reads once its working set — per-block global read bytes times resident blocks — exceeds a capacity. That capacity is a fitted constant of the proxy, not the device's L2 size, so it is calibrated the way the bandwidth leg is: by a sweep whose kernels sit on both sides of it.

val working_set : ?m:??? -> ?n:??? -> ?ks:??? -> ?repeats:??? -> Context.t -> ws_point Base.List.t

working_set ?m ?n ?ks ?repeats ctx times the untiled weight-gradient contraction dw[o,i] = sum_k dy[k,o] * x[k,i] — m rows of output (default 256), n columns (default 1024: a gpt2_mini_train layer's l*_ffn_w2 gradient) — at each reduction extent of ks (default 256 to 65536 in powers of two, batch 2 to 512 at sequence 128), on the plain default pipeline (Context.compile: the plan whose re-reads the score charges, never a seeded or tuned one). The inputs are explicitly initialized host arrays (a standalone fixture: nothing upstream of the kernel is timed or left lazily initialized); the time is the whole routine's, synced, best of repeats (default 10) after one warm-up run. Each point carries the contraction kernel's working set and byte charges as the cost model reads them off the scheduled code.

type capacity_fit =
  1. | Transition of {
    1. cached_ws : Base.int;
      (*

      The largest working set still served at the cache rate.

      *)
    2. spilled_ws : Base.int;
      (*

      The smallest working set served at the DRAM rate.

      *)
    3. capacity : Base.int;
      (*

      Their geometric mean: the fitted model_cache_capacity.

      *)
    4. monotone : Base.bool;
      (*

      Every cached point's working set is below every spilled point's. false means the sweep's rates do not split cleanly by working set, and the capacity is a guess.

      *)
    5. cache_rate : Base.float;
      (*

      The median requested rate of the cached points, bytes/s: the fitted model_cache_bandwidth.

      *)
    }
  2. | All_cached of {
    1. largest_ws : Base.int;
    2. cache_rate : Base.float;
    }
    (*

    Every point is served at the cache rate: the capacity is at least largest_ws, and the sweep says no more than that (no capacity is invented; extend ks to find one).

    *)
  3. | All_spilled of {
    1. smallest_ws : Base.int;
    }
    (*

    Every point is served at the DRAM rate: the capacity is below smallest_ws.

    *)
  4. | No_transition of {
    1. contrast : Base.float;
    }
    (*

    Without a DRAM rate to compare against, the fastest and slowest requested rates differ by contrast < 2: the sweep cannot tell which side of the capacity it sits on.

    *)
  5. | Too_few_points
val fit_capacity : ?dram_rate:??? -> ws_point Base.list -> capacity_fit

The capacity and cache bandwidth the sweep implies. A point's requested rate is its per-block read bytes over its time: within capacity, re-reads are served from cache and the rate sits far above DRAM bandwidth; past it, the rate falls to it. Points with a smaller working set than the fastest one are dropped first: a kernel too short to amortize its launch shows a LOW rate for a reason that is not the cache (tuf's 0.4 ms floor at the smallest extent read as spilled and made the first fit non-monotone). Over the rest, a point is cached when its rate is at least the geometric mean of the fastest rate and dram_rate (bytes/s, the calibrated DRAM bandwidth) — or, without one, of the fastest and the slowest rates, which needs a contrast of at least 2 to mean anything. The capacity is placed at the geometric mean of the working sets either side of the split — the model's decision boundary, between the shapes that demonstrably sit on each side of it — and the cache bandwidth is the cached points' median rate.
