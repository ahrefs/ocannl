Module Test_scan.Verdict_scan

Scanning test sources for claims a test decides itself and prints outside Verdict, where a failing one is dune promote-able into the golden.

Finding self-decided verdicts that a test prints itself instead of routing through Verdict.

gh-ocannl-601 established the rule and swept the sites that existed then: a claim the test decides — <label>: <bool> — must go through Verdict, so that a failure exits the process nonzero. Printed and exited 0, the same line is gated only by the golden diff, and the natural next move on a failing diff is dune promote, which records <label>: false as the expected output. In a golden that is nothing but verdict lines, a blessed regression and a deliberately recorded negative fact are the same text.

That sweep was one-time and left no mechanical trace, so the population regrew: a test written afterwards (bandwidth_calibration, gh-ocannl-578) came in with four fresh Stdio.printf "…: %b\n" claims, and nothing failed or warned. This module is the reader behind the ratchet that stops that (gh-ocannl-668).

What shape is recognised

A format whose LAST argument-consuming conversion is a bare %b at the end, behind a label that ends in one of the separators a claim is written with — a colon, an equals sign, or an arrow. Two kinds, told apart by whether anything else in the format consumes an argument:

  • Literal_label: the %b is the only conversion, so the label is written out. "k-blocks fused: %b\n", "round-trip identity = %b\n", "hoisted -> %b\n".
  • Computed_label: the label is built from arguments. "%s fused: %b\n", "Epoch %d, loss below threshold=%b\n".

Both are recognised now. The literal form was gh-ocannl-668's; the computed one is gh-ocannl-624, which the sweep of that issue converted onto Verdict.pf and Verdict.claimf — entry points that did not exist when this reader was written, which is why the shape was out of scope then and is not now. The separator vocabulary is the other thing that widened: a reader that accepted only a colon was blind to the whole "… = %b" population, and that is how the claims in data_parallel, shard_transfer and test_buffer_loc sat outside a check written to catch exactly them.

The escape hatch is narrower as a result, and deliberately so. A descriptive print used to escape by carrying a second conversion; a computed label carries one by construction, so that no longer distinguishes it. What is left is a named exemption in the test that consumes this — one per site, with the reason it is not an assertion. The population that needs one is small (a handful of census rows and tables), because a print whose boolean is not a verdict usually does not end on the boolean.

Why it reads the parse tree

Same argument as Config_key_scan, whose parse helpers this shares, and the same conclusion: this module parses, it does not match text. A text scan reads prose as code — this file's own documentation quotes the shape it hunts — and cannot tell a format written over a line continuation from one written on a line. On the parse tree a string literal carries its decoded value whatever escapes or delimiters produced it.

Attribute payloads are the one thing deliberately skipped. A documentation comment becomes an @@@ocaml.doc attribute holding a string, so a comment quoting the shape arrives as a literal to flag; that is prose, and prose is not a print. Extension payloads are not skipped — a %cd or %expect payload is code, or is the golden text of one.

Every claim-shaped literal, not only those applied to a printf

What the check fails on is the literal, wherever it sits; which function receives it is reported but decides nothing. The alternative — flag only what is applied to a printing function — is evaded by any wrapper, including the let p name b = Stdio.printf "%s: %b\n" name b helpers several tests defined before Verdict existed. Those helpers are the exact population this ratchet exists to keep from regrowing, so a claim-shaped format string in a test source is either an assertion or, by exemption, a documented exception.

Success trailers (gh-ocannl-1449)

The trailer reader reserves a literal line starting with OK: for Verdict.success_trailer. It checks decoded string literals passed as the format or text argument of a direct stdout call spelled printf (bare, Stdio.printf, or qualified by Printf or Format with optional Stdlib), or print_string and print_endline (bare or qualified by Stdlib or Stdio). It also reads fprintf (bare, Stdio.Out_channel.fprintf, or qualified by Printf with optional Stdlib) and output_string (bare, Stdlib.output_string, or qualified by Out_channel, Stdlib.Out_channel or Stdio.Out_channel) with a direct stdout channel path. The channel may be bare or qualified by Stdlib, Stdio, or those same Out_channel paths. A line starts at the literal's beginning or after a decoded newline. The spelling controls the check even if shadowed. Channel and printer aliases, computed strings, format-generated line breaks, and non-OCaml output are outside the model.

A conversion directive as the format spells it: where the '%' is, where the conversion character is, and what it is. A bare %b has stop = start + 1; anything wider carries flags, a width or a precision between the two.

val consumes_nothing : char -> bool

Directives that consume no argument, so a format carrying one still takes however many arguments it took: %% (a literal per cent), %! (flush), %, (a separator that prints nothing). Everything else counts as consuming — including the nested-format spellings %\{…%\} and %(…%), whose presence therefore takes a format out of the recognised shape rather than into it. Erring that way costs a report that was never made, never a false one.

val directives : Base.String.t -> directive Base.List.t

The conversion directives of a format string, in order. Scans for '%', then flags, width and precision, then the conversion character. A trailing '%' with nothing after it is not a directive and ends the scan.

val printed_text : Base.String.t -> string

What a reader sees printed by a stretch of format text, with the arguments left out: %% is a per cent sign, every other directive contributes nothing this reader can know, and the rest is itself. Applied to the text before and after the %b.

It removes each directive by the SPAN directives found, flags and width included, rather than by a fixed two characters — otherwise %-22s leaves "22s" behind and a claim's rendered label reads as that debris. The span is also what keeps the tail check honest, since a directive there prints nothing whatever its width.

val claim_of : Base.String.t -> (Base.String.t * kind) Base.Option.t

claim_of format is the label of the claim format prints and which kind it is, when it prints one.

Three things must hold at once:

  • the LAST argument-consuming conversion is a bare %b — a width or a flag means the print is laying out a column, which is formatting rather than asserting;
  • what follows it prints as whitespace, or as nothing: a newline, a blank line, a %! flush;
  • what precedes it ends in one of separators, with a non-empty label before it.

So "k-blocks fused: %b\n" yields Some ("k-blocks fused", Literal_label) and "%s fused: %b\n" yields Some ("fused", Computed_label) — the second's label is what survives rendering the head, which drops the conversions it cannot fill in, so it is a report's hint rather than the site's identity; an exemption for a computed site is keyed by the head.

A computed label may render to NOTHING and still be a claim: "%s: %b\n" is the wrapper the pre-Verdict tests defined for themselves, and the whole of its label is the argument. Only a LITERAL label has to be non-empty, because there the residual is all there was. "fused: %b (expect false)\n" and "fused? %b\n" yield None: neither is the bare claim form, and a reader cannot take their boolean at face value.

A gated claim reported in two dialects (gh-ocannl-997)

Verdict.skipped prints <label>: true — Verdict.p's line — so that a leg one host cannot evaluate leaves the golden exactly as a host that evaluated it does. A claim whose evaluated branch reports through Verdict.pass_fail instead prints <label>: PASS there, and the golden promoted on a machine that evaluates it breaks on the first machine that skips: silently, until the gate actually fires, on whichever host is least likely to be the one promoting. Verdict.gated removes the trap by picking the dialect itself; this reader keeps the mixed spelling from regrowing.

What it pairs is a LABEL that reaches both a PASS/FAIL claim and a skipped call in one source. The dialect includes the Verdict.Claims names pass_fail and pass_fail_*. The label is the first positional argument, keyed three ways: a string literal by its value; a name by the literal it is bound to, in its lexical scope through Lexical_scope (the let claim = "…" shared by the two branches is the shape both sightings had), otherwise by the name itself; anything else by its printed expression, so a label computed the same way on both sides is still one label. A literal pairs across the whole source; a name or an expression pairs only within one top-level item, since equal names in two functions need not be one label. Named and computed keys retain their bindings' identities. The callees are matched by their last path component, which is how an opened Verdict.Claims and the per-test let skipped = Verdict.skipped ~backend:backend_name both read.

Fail-loud boundary: unknown or shadowed labels stay named/computed rather than borrowing a literal elsewhere. Unknown opens bring in no values.

What it cannot see: a skip or a PASS/FAIL claim routed through a wrapper of another name, and one label computed by two different expressions. Those are the reason the remedy is an entry point rather than this check — Verdict.gated has no second dialect to pair.

A claim label written with a line break (post-wave task of staging#1134)

A claim is one row on each channel it prints to: tools/mutation-run.sh reads a run's FAIL: …: false lines off its log and counts its stdout rows against the golden's. A label with a newline in it used to split its claim into a FAIL: head that is no false claim and an unprefixed tail that is a row the golden lacks. Verdict now renders every claim line through Verdict.one_line (a control character becomes a space), which keeps a COMPUTED label on one row; a LITERAL one with a line break can only be a mistake -- a cosmetic blank line before the claim, as test_random_histograms had, belongs in a printf of its own -- so this reader refuses it where it is written rather than leaving the sanitizer to turn it into a stray space.

What it reads is the label argument of every claim form in labelled_claims that is Verdict's (see claim_calls): the first positional argument, keyed as dialect_census keys it, so a name bound to a literal is that literal. A pf/claimf/pf_all2 format is its label too, and a line break in the format is one in every rendered label. Verdict.fail is not read: its argument is a message, multi-line by design, and every line of it is printed with the prefix.

Where a label counts as LITERAL is a deliberate, closed list: a string constant, under any type constraints or coercions, or a name bound to one -- directly or through a chain of let renamings. Every other expression is a computed label, however statically it could be evaluated (if c then "a\nb" else "c", String.concat): that is the sanitizer's case, and Verdict prints it on one row whatever it holds. This reader is the lint for the label a person writes out; the sanitizer is what makes the run correct.

The CALL is read the same way: a claim applied by its path, under any constraints or coercions. A claim applied any other way -- through @@ or |>, or passed as a value -- is not read; its label, too, is the sanitizer's.

What it cannot see: a label computed from an expression (the sanitizer's case, by design), a claim reached through a wrapper the source binds (let skipped = Verdict.skipped ~backend), and an unqualified claim name brought in by an open this scan does not model (a module that re-exports Verdict.Claims under another name).

A claim name that reaches Verdict only past an open of a module Verdict_callee cannot read is Ambiguous: that module may export a function of the name, or a Verdict module of its own -- Verdict.p past an open Other is ambiguous as much as an unqualified p past one (gh-ocannl-1361). Such a site is READ, and a line break in its literal label is refused with the remedy of qualifying the call -- loudly, since the alternative, leaving it unread, is how a later open Ll_test would silently exempt every claim after it.

A literal floor below one (post-1-task-4 of staging#1578)

A quantified claim's ?min only RAISES its floor: Verdict.check_floor refuses a value below one with an Invalid_argument where the claim is evaluated, since ~min:0 reads as "emptiness passes" and no floor can grant that (gh-ocannl-729). That refusal fires only on a run that reaches the claim -- a claim in a leg whose gate is closed, or on a branch only another backend takes, carries its ~min:0 through every run that does not. A floor written as an integer LITERAL needs no run to judge, so this reader refuses it where it is written.

What it reads is the ~min argument of every claim of floor_claims that is Verdict's or Ambiguous (resolved as claim_calls resolves the callee), when that argument is an integer constant, under any type constraints or coercions: ~min:0, ~min:(-1) (which the parser folds into one constant), ~min:0x0, ~min:0_0, each by the value Int.of_string gives it. A floor COMPUTED from anything (~min:(List.length xs), a name bound to a literal) is left to the runtime refusal, which sees its value; so is a ?min:(Some 0) forwarding, and a claim applied through |> or @@ or named as a value, which claim_calls does not read. Verdict.within is no claim and is not read either: its floor is refused at run time, where its claim is.

A float tolerance hand-rolled into a claim (gh-ocannl-1224, gh-ocannl-1470)

Verdict.p_close name got want ~tol compares two float readbacks under a tolerance and, when a cell is out of it, names on stderr how many cells differ, the worst one with both values, and the reference's magnitude; Verdict.within is the same check as the predicate of an aggregate claim. The same comparison written as p_all2 name got want ~f:(fun a b -> Float.(abs (a - b) < 1e-3)) prints a bare false: gh-ocannl-1217's sweep recorded exactly that for fifteen seeds and it took a reproduction round on a remote box to learn that every seed was off by the same five ulps of reference rounding. This reader keeps the hand-rolled spelling from regrowing, in two shapes.

A PARITY PREDICATE: the ~f of every Verdict p_all2, pf_all2 and pass_fail_all2 call (parity_callees), resolved as claim_calls resolves the callee, is a hand-rolled tolerance when it is a function whose body applies an abs (any path ending in it: Float.abs, or abs under Float.( … )) to a subtraction (- or -.) -- written in the argument, or a name the predicate's lexical scope binds to such a function (directly, through a chain of renamings, or partially applied: ~f:(close ~tol:1e-4)).

A HELPER REACHING A CLAIM (gh-ocannl-1470): every other argument of every other Verdict claim (helper_claim_callees: the label aside) is a hand-rolled tolerance when it holds a function that BOUNDS an abs-of-difference -- an abs of a subtraction on the small side of <, <= (or the large side of >, >=) inside a fun -- or a name its scope binds to anything holding one: a helper (let approx a b = Float.(abs (a - b) < 1e-3)) or a value computed through one (let ok = Array.for_all2_exn got want ~f:approx), through any chain of such bindings. So p "x" (Array.for_all2_exn a b ~f:(fun x y -> Float.(abs (x - y) < 1e-5))) and p_all "x" runs ~f:(fun (got, want) -> approx got want) are both read. Only a BOUND difference counts here. An unbounded abs-of-difference helper, or a fold containing one, is tracked through name bindings and arithmetic until an upper comparison bounds it (gh-ocannl-1837). Merely printing a maximum or requiring it to EXCEED a margin does not count. Ordering two error metrics is also a scalar comparison, not parity under a tolerance. The reduction reader recognizes calls ending in fold, foldi, fold2, fold2_exn, fold_left, fold_right, max_elt, reduce and reduce_exn, applied or piped (x |> f, f @@ x), over an abs-of-difference written in the call or a name holding one; it does not prove which reducer the callback implements. A name holding an abs-of-difference that is neither a function nor a reduction -- one cell's error, or the errors of a collection mapped cell by cell -- is no tolerance when a bound applies to it, but a reduction over it is.

LOOP-CARRIED REFS (gh-ocannl-2122): what the source writes into a let-bound name with x := e is read into that binding, by lexical identity (a shadowed name is another binding), through any let alias = x renaming. A write inside a for or while body or a function body the binding encloses (a callback of iter) runs once per cell: an error it carries makes the ref a reduction over the cells (max_err := Float.max !max_err (Float.abs (a -. b)), or worst := err for an err holding one), and a bound it applies to an abs-of-difference makes it a tolerance (ok := !ok && Float.(abs (a - b) < tol), or Float.(err < tol) for an err holding one, where the other side holds no error). A write at the binding's own depth is one value, read as a binding's right-hand side is. A write is read wherever it sits, before or after the claim. The reader runs in passes, each reading what the previous ones found written: first the metrics alone, until a pass finds no new one, then the bounds over those settled metrics, so an ordering of two refs is never read as a bound while only one is known to hold a metric.

What it does not read, by design: a scalar comparison written in the claim itself or in a value binding outside any function (p "x" Float.(abs (got - 2.) < 1e-6)) -- one value against one reference, no cell to locate (its p_close spelling is still the better one); the argument of in_leg, in_legf and case, whose closures hold claims of their own, read where they are written; and the p_close family, whose ~tol answers a bound rather than hand-rolling one. What it cannot see: a predicate reaching the call as a function PARAMETER, a tolerance written without abs (a -. b < t && b -. a < t), a lambda parameter shadowing a tolerance name inside the claim's argument, and a comparison routed through a helper of another module. Of writes, it reads := into a name alone: not a ref a function parameter holds, a record field, an array cell (errs.(i) <- …), a write a condition controls without carrying the error (if Float.(abs (a - b) > tol) then ok := false), nor an abs of a name holding a difference (let d = a -. b in Float.abs d); nor a cell-by-cell mapped error bounded element-wise (List.for_all diffs ~f:(fun d -> Float.(d < tol))), a sum or min_elt. These are reader boundaries, not evidence that the tree contains no such comparisons; the remedy for a tolerance claim using one is p_close or within.

A gate that reads the population it quantifies (gh-ocannl-1289)

Verdict.gated_all ~when_ ~on label xs ~f (and gated_alli, gated_exists) skips its claim where when_ is false. A gate computed from the values under test turns the regression the claim exists to catch into a skip: had the population emptied or lost its interesting members, the gate closes, the skip prints p's passing line, and the golden stays green. That is the gh-ocannl-1115 trap, and it shipped twice in one wave through these very forms — a gate asking whether the claim's own results were non-empty (staging#1049), and one asking whether the real seeds results was mapped from held a tensorized one (staging#1063). Verdict.gated ~when_ ~on label b carries the same trap when b quantifies: placement_store gated (not (List.is_empty stores)) && List.for_all stores ~f:refused on stores being non-empty until gh-ocannl-1361. A gate comes from an invariant — the backend, an advertised capability, the configuration — never from the population.

What is read

Every application of gated, gated_all, gated_alli or gated_exists that carries its ~when_ and both positional arguments, where Verdict_callee -- the resolver every Verdict reader shares -- reads the name as Verdict's, Ambiguous (reported as such, with the remedy of qualifying the call) or Free: a gated name nothing binds is read too, since it exists nowhere but in Verdict.Claims. A file's own gated_all, and another module's, are not Verdict's; a name a structure of the file exports is followed to its definition there, so module Checks = struct let gated_all = Verdict.gated_all end opened is Verdict's. A partial application bound by let to a name, under any number of further partial applications, is completed at each application of that name, and x |> f and f @@ x are read as f x; so the let check = Verdict.gated_all ~when_ ~on in check label xs wrapper is one site per use. The two sides are then compared by LEXICAL identity, a name plus the binding it resolves to through Lexical_scope, so a shadowed name is a different value; a name no binding of the source gives (a global, or one an unmodelled open brought in) is one identity, the same on both sides:

  • the GATE is every value identifier the ~when_ expression spells, and transitively every one spelled by the right-hand side of a let it resolves to (function bodies included), or by what the source writes into that binding (below), in any position; a collection-module function collection_functions does not list, applied anywhere the gate reaches, is reported as unlisted;
  • the POPULATION of a gated_* claim is the identifier the quantified argument spells, and the collections it is BUILT from: following a let-bound name into its right-hand side, the branches (not the condition) of an if, the cases of a match (the scrutinee only through a name a case pattern binds and the case returns -- and of that name, only the component it takes apart, where the scrutinee is, through let-bound names, a literal tuple, record or constructor application: see parts), the body of a function in data position (a ~default:(fun () -> ...) thunk), the body and handlers of a try, the body of a let, let module, local open or sequence, the elements of a list, array or tuple literal or constructor payload, the operand of ! and of ref and both operands of @ (where the source does not bind the operator itself), and the arguments that carry the collection into a function of a standard collection module (List, Array, Hashtbl, Map, Option, String, ... — see collection_modules), reached by name, through a module alias (module Rows = List) or a value alias (let map = List.map in map raw ~f, a renaming followed through any number of lets, though not a partial application), and not under a name a local module took over (module Map = Custom); an unqualified List is Stdlib's until an open Base in scope rebinds it. Which arguments carry it is the role collection_functions gives the function by its exact name (builds): every positional one for a transformation, constructor, conversion or quantifier, the collection alone for a Base-ordered selector (find, nth, take, remove, ...), the value filled in for make/create and not the count, what the callback returns for init, and nothing for range, plus the data-bearing labels ~default, ~init, ~data, ~sep, ~with_, ~replacement. A function of a collection module the table does not list is REPORTED (unlisted_call), never read by a guess (gh-ocannl-1303);
  • the body of a binding operator (let+ x = e in body), where x is a part of e;
  • the POPULATION of a gated claim is what its boolean's quantifiers range over, each followed as above: the boolean is read through a name into its right-hand side and what the source writes into it, not, && and || (bare where the source does not bind them, or qualified by a standard library), ! and ref where unbound too, the branches of an if (never the condition), the cases of a match, the body and handlers of a try, the body of a let, let module, local open or sequence, type constraints, pipelines, and a quantifier's own arguments, its predicate's body included (a quantifier nested there ranges over a population of its own, the predicate's parameters none); a quantifier is a collection-module function collection_functions marks quantifies (for_all, exists, is_empty, mem and their indexed and pairwise forms, and the predicates of a collection's elements as a whole: contains, is_sorted, is_some, ...), whose collection is its first positional argument in Base's order (the first two for a pairwise one) and every positional argument in Stdlib's; a collection-module function the table does not list is reported here too;
  • and, for a name it reaches, whatever the source writes into that binding, directly or through a let alias = name renaming: the right-hand side of x := e and of x.field <- e, and what a function of a mutable collection module (mutable_modules) that collection_functions marks as writing (writes: Queue.enqueue x e, Hashtbl.set x ~key ~data, Hashtbl.filter_keys_inplace x ~f, ...) is handed with x, where x is the first positional argument in Base's order and any of them in Stdlib's. A function of a mutable collection module the table does not list, handed x, may write into it: a claim that reaches x is reported as unlisted. So is a writer handed x alone (Queue.enqueue x) or whose value a let binds to a name (let put = Array.set x 0): a possible partial application whose later call this reader does not follow. A partial writer that escapes otherwise (returned, or handed to another function) is not followed. A field write x.f <- e reaches x whole, and the f a pattern takes apart from x's literal, not its other fields. x is a name the source binds; a container only an open brought in is not tracked. Only a write that may run before the claim counts (precedes): one placed after it, in code that cannot run again before it, is not followed.

The claim is refused when the two share a binding. The asymmetry is the point: a gate may read what the population is COMPUTED from (the site, the hardware limits, the backend steering an if), which is how a capability judgment over the same program reads, and must not read the population or a collection it is mapped, filtered or appended from.

Leg claims (gh-ocannl-1794)

A leg claim, in_leg ~leg label make or in_legf ~leg fmt ... make (leg_claims), is a gated claim too. Its GATES are the ~when_ of the qualified Verdict.leg or Verdict.sub_leg application (Verdict_callee.leg_constructors) its ~leg reaches, read as a gate is above, and then of each sub_leg's outer leg; ~leg is followed through a name into its let right-hand side, a type constraint, the body of a let or a sequence, both branches of an if and every case of a match -- whose condition, scrutinee and guards pick the leg and are gates too -- and the body of a local function it applies; an ancestor two branches share is read on each path. Its POPULATION is what the claims its make function makes in place range over, each read by leg_population_slots: a boolean as a gated boolean's, collections as a gated_* claim's. Beside them, every argument the make function hands a helper -- a function of the source or another module, not an operator, a standard_functions name, a standard or collection module's function, or Verdict's own -- is the population of the claim that helper makes, on every path where no claim read in place runs: where each such claim sits in another branch of some if, match or function than the helper. A helper applied in make's place is such a helper. The loud direction. On both sides, and for the gated_* forms too, a lazy e is e's and Lazy.force x (or Base's force) is x's: a leg's evidence lives in lazies only its claims force.

The same model of what runs bounds the population: a function value or lazy inside the make function is deferred, and its claims are no population, unless a collection-module function calls it back, or the make function itself runs it (gh-ocannl-1893): a function defined inside the make function and applied there by its name, or a lazy defined there and forced there by its name (Lazy.force, Base's force), is walked again where it runs (replay), its claims the make function's. A leg claim nested in a make function is a claim that make function makes: its population is every enclosing leg's too. Anything else the reader cannot follow is outside the model: such a leg is counted as UNCOMPARED (below), never refused.

A leg or make function passed as a parameter (gh-ocannl-1893)

A parameter of a named function of the source -- a let, top-level or local, recursive or not, whose right-hand side is a function; a labelled, optional or positional parameter whose pattern is a name, or a record or tuple pattern (below) -- is RESOLVED AT THE APPLICATIONS of that function in this source and in its callers (below): the argument each application supplies for it, by label or by position among the positional ones, in the scope the application is written in, or, where an application omits an optional one, its default. A ~leg reaching such a parameter is followed into each application's argument, through any number of calls (a parameter reached again on its own path, a function passing its leg back to itself, adds no gate). Each choice of the applications on the way is one RESOLUTION (leg_resolution), and the claim is compared once per resolution, under that choice: there a parameter of a chosen function, on either side, is the chosen application's argument alone, so one call's gate never meets another call's population. Every claim inside a named function -- a leg claim, under each of its resolutions, and a gated_* claim -- is also compared once per CALL CHAIN reaching that function (call_chains: an application of it, then one of the function that application is written in, and so on up to code no function encloses, at most 256 chains), so a leg a helper builds from its own ~when_ parameter, and let check ~when_ label xs = gated_all ~when_ ~on label xs ~f, are read at their callers, one call at a time, through forwarding helpers too. A parameter of a function no resolution or chain chose is followed into every application's argument (the loud direction). A make function given by name is followed through a let to its definition, and through a parameter to each argument as a ~leg is, and the function found is walked again with the claim's collector (replay); a helper applied in its place keeps the helper rule above. A local function's application on a ~leg's way binds its parameters to that application's arguments.

Applications in other sources (gh-ocannl-2286)

The applications are this source's and those of the other sources handed in as ?callers: the ratchet's cross-source index gives each source the sources that spell its module, M (the file name up to its first dot, capitalized, so each arm of a (select) is the module dune copies it to). Each caller is walked after this source, as a structure of its own under the one module binding M -- this source's top-level structure -- with its character positions placed past every earlier source's (structure_at), so no binding identity or position-keyed table is shared and a caller's rows is never this source's. What the walk records there -- call sites, parameters, writes, its own helpers and their call chains -- is read as this source's is; the claims it makes are its own reader's and are not compared here. An application there is M.f args, f args under an open M (M.( ... ), let open M in), or one through an alias module X = M or an include M the walk follows; M.f is resolved the same way in this source for a structure M of its own, and spelled other than as an applied callee it escapes as a name does. A caller's applications are read only where this source has a claim to compare. Outside this: a caller spelling M packed, as a functor's argument or under a constraint, or inside another module's path (Lib.M.f, open Lib.M, a wrapped library's spelling); one re-exporting M through a structure-level alias or include where a third source spells the caller's module; and one that does not parse -- each leaves every function of M, its submodules' included, UNCOMPARED, naming the caller (module_spelled_otherwise). A source outside the corpus the ratchet globs is not read.

A leg another source's function returns (gh-ocannl-2336)

A ~leg that is the result of M.f args -- M a structure of the source, or, in a caller's walk, this source itself, or a module name nothing in scope binds -- is f's body read as a local function's is: each parameter bound to the argument this application supplies, in the scope the application is written in, through the same bounds on choices, with the function's own result passing back through it uncompared. Where M is no structure in scope, its definitions are the other sources the ratchet's index gives as compiled under M (?definitions, asked with the source M is spelled in -- None for this one, else a caller or another definition: the source of that name in the speller's own directory where there is one, else every source of the name, each an alternative compared in its own right). Each is read once: a caller as it was walked, any other source parsed past every source walked before it, so it shares no positions, and walked as a caller is, so what it writes into its bindings and its own applications are read as a caller's are; its Verdict resolutions join this source's. A destructured parameter of f is the parts of what the application supplies (parts), and ?l:None for a parameter with a default is the default. A module path inside M (M.Sub.f), an f that is no fun its body follows, an f whose body writes into a binding, or whose own gate reads a binding the walk saw written anywhere (writes this reader does not time against the claim), an f handed ?l:e for a parameter with a default, e no literal None or Some _, an f exported -- itself or through a submodule -- before a later include in M's structure, this source's or another's, of a module whose exports the reader does not know (one it cannot read, or a struct ... end holding such an include), which may rebind it, a source that does not parse, and a module name no source is compiled as each leave the leg UNCOMPARED, with the reason; so does L.f under a module alias of another source (module L = Ll_test), which binds no structure in scope. A module name an open of a module this reader cannot read rebinds is read as the corpus's source of that name, as a caller's M.f is.

A leg taken out of a value (gh-ocannl-2286)

A leg read from a record field (case.leg), or bound by a record or tuple pattern of a named function's parameter (let run { rows; leg } = ...), is the part of the value reached that the field or pattern names: the reader carries the projections along the leg's way -- through names, lets, branches and parameters as above -- and takes them at the record or tuple literal it reaches, or at a { base with ... }'s base where the field is not given. The parameter of an anonymous callback an element_iterations function is handed in place (List.iter cases ~f:(fun case -> run case)) is each element of the collection where that is a list or array literal (through names no write reaches, let bodies and sequences): one resolution per element, each compared with that element chosen, on both sides, as an application is -- so one element's gate never meets another element's population; a claim written inside such a callback, or in a function an application inside one reaches, is compared once per element of each such callback too. A destructured parameter is likewise, on the gate and population sides, the part of each argument its pattern takes apart (parts), with what the source writes into that field before the claim; a field a { base with ... } leaves is taken from the base where that is a literal too.

Where this stops, the leg is UNCOMPARED, with the reason: the function's name is spelled other than as the callee of an application (handed on as a value, piped), so not every application is seen; no application of this source or of a caller supplies the parameter; a caller spells the module in a way that may hide one (above); an application omits it, or passes an optional one as ?leg:; the parameter belongs to an anonymous function no element_iterations function is handed, or the collection it iterates is no literal; a pattern binds the leg other than through record fields and tuple components (a constructor's payload, an or-pattern); a field is taken of a value that is no record literal, or of a binding the source writes into; or a make function is taken out of a value that way, which the reader does not follow.

A leg claim applied in part -- without its ~leg, its label and its make function in place, an in_legf with exactly as many arguments as its literal format takes before the make function (format_arity) -- or named as a value is reported unread. A complete one whose ~leg or make function the reader cannot resolve as above -- a pattern, a field, another module's value, an unqualified leg (an open Verdict's) -- is reported UNCOMPARED: counted, named, and not refused.

What is not read

The forms above are a closed list: any other expression form ends the population side there, and a population reached only through one is not compared. The exception is a collection-module function, which is never outside the list: collection_functions enumerates the ones the reader reads, and any other is reported. The ones known to matter:

The population is not followed through a call to any other function (a file-local gpu_seeds pre stops at the call), through a record field, through a parameter of an anonymous function no element_iterations function is handed over a literal collection, or of a function no application read supplies (a named function's parameter is its applications' arguments, above), or through an unqualified name under an open of a collection module (List.(permute raw)) that collection_functions does not list: such a name is read as whatever else binds it, and is not reported as unlisted, since without the module's signature it cannot be told from a function of the source (a listed name there is the module's, resolve_callee); a destructured let binds names that are followed no further, and a value reached through a module path (M.rows) is an identity on neither side. A gate threaded into a wrapper as its own parameter is read at the wrapper's applications, in this source and its callers, as above; a wrapper no application read applies is read at its definition, where the gate is a parameter and reads nothing. A gated boolean that quantifies nothing has no population: its comparisons and other calls are operands this reader does not read, so gated ~when_:(xs <> []) label (sum xs = want) passes, and so does a gate folded into a value (p "…" ((not on_cpu) || ok)), which folded_gate_census reads instead. Each of these is a place a population gate can hide from this reader; none is a place it reports one that is not there.

A gated application the reader cannot complete — a partial application no let binds, a let-bound one that no use the reader resolves completes (reached only through a module path, say), or a claim (or a let-bound wrapper of one) named as a value, handed to List.iter say — is reported as unread rather than counted as clean, so the boundary is loud there.

Which writes may precede a claim (gh-ocannl-1303)

A write into a binding the population or the gate reaches is followed only when it may run before the claim is evaluated: Queue.enqueue queue v written after the claim, in code that cannot run again before it, cannot have shaped the claim's population, and a gate reading v is not refused on its account. Lexical order alone is not the answer -- a write later in a loop body precedes the claim's next iteration, and so does a write in a function called again -- so the reader places both points in the program's control structure, conservatively: every construct whose body may run more than once, or at a time the reader does not know, is a frame of each point inside it.

  • A while loop, a for loop's body (not its bounds), and a function handed directly to a function of a collection module in a position that module calls before it returns (a List.iter callback: calls_back) -- on Seq or Sequence, a function the table marks as consuming (runs_callback), not a lazy map -- run synchronously, possibly many times: a Loop. A function handed in any other position (List.singleton (fun () -> ...)) may be stored and called later, like any other function value.
  • Any other function may run whenever it is called. It is ONCE when it is the right-hand side of a non-recursive local let whose name the source spells exactly once, as the callee of a full application outside the function's own body: then its body runs exactly where that call runs, and a point in it is placed at the call. A top-level function is never once, since another module may call it.
  • lazy, a binding operator's body, an object or class, a functor's body and an extension's payload (let%expect_test included) run at a time the reader does not model: Deferred.

A write may precede a claim when, at the outermost level where the two are not inside the same call of a once function, (a) both are inside one frame that may repeat (a loop, a function that is not once, a deferred construct), (b) the claim is inside such a frame of its own that may run at any later time (a function that is not once, or a deferred construct) the write is not in, or (c) the write starts before the claim ends, or (d) the two sit in different operands of one expression whose operands OCaml evaluates in an unspecified order -- an application's callee and arguments (&& and || apart), a tuple, array or record's components, the bindings of one let ... and ..., a binding operator's operands -- so consume (claim; ()) (write ()) may run the write first. (A write in a function defined before the claim is before it; one in a function defined after it cannot run before it unless the claim runs again, which (a) and (b) cover.) Inside one call of a once function the same question is asked of the two points within it. A claim's own arguments are before its end, so a write there precedes it.

What this does not model, each erring toward following the write: a function value stored and called later is placed where it is defined; a once function's name passed anywhere but a call is not once.

A hand-written skip list (gh-ocannl-1794)

A claim sequence only some backends can evaluate is written ONCE, as a leg (Verdict.leg, Verdict.in_leg): where the leg is closed each claim skips under its own label, in the order the same code reaches it. The two-branch form the legs replaced kept the off-gate side in a second copy -- the evaluating branch's claims, then List.iter claims ~f:skipped over a hand-written list, or a run of literal skipped calls -- whose order nothing tied to the first: grid_launch_floor appended two claims to its list while the CPU branch made them mid-sequence, and Metal, CUDA and HIP went red (gh-ocannl-1668). gh-ocannl-1703 migrated about thirty such tests; this reader keeps the form from regrowing.

The model (the boundary, stated once)

This reader decides skip lists under a BOUNDED, static model of what runs. It reads exactly the constructs listed below; anything else is outside the model and is read CONSERVATIVELY: as no skip list, never refused. A construct outside the model can hide a skip list from this reader; it is never a reason to report one. Widening the model is a change to this header first.

  • A SKIP is a skipped Verdict_callee reads as Verdict's (Verdict.skipped, an opened one), or a name of any spelling a let of the source binds to a skip or its application (the per-test let skipped = Verdict.skipped ~backend:backend_name, or let skip = ...), through opens of the standard libraries; never a parameter or other binding of the name, nor another module's. A skip RUNS where it is applied to its label (a positional argument); a partial skip is a callback, read only where a collection function is handed it.
  • An EVALUATING claim is an application of any other Verdict_callee.members name but fail and case that the resolver reads as Verdict's.
  • What RUNS: the code written in place. A function value and a lazy are DEFERRED -- their bodies are not read as run -- except a function a collection-module function calls back, and a DEFERRED SKIP VALUE where it is run (gh-ocannl-1893).
  • A DEFERRED SKIP VALUE is a function or a lazy a named let of the source binds (or a let renaming one), resolved lexically, so a shadowing binding is not it. Its run code is its body read as above, down to the branches nested in it, which are judged where they are written. It RUNS where a complete application of its name supplies every positional and required labelled parameter of the function, or where its name is forced (Lazy.force, Lazy.force_val, Base's unqualified force) -- a lazy once per branch, being memoised. There it runs its run code: a SKIP WRAPPER (one whose body evaluates no claim, its nested branches included) its skips, through wrappers of wrappers (a cycle runs nothing); any other its evaluating claims, so a branch calling a function that evaluates a claim evaluates one. A skip wrapper's name, or its partial application, handed where a collection function calls it back is a skip handed there.
  • A STORED ITERATION is a name a let binds to a partial application of a collection iteration (one not applied_fully), or to a renaming of one: an application of the name completes it, the stored arguments followed by the new ones, and is read as that iteration.
  • A COLLECTION ITERATION is a complete (applied_fully) application of a function of collection_modules -- the module resolved through the source's own module aliases and structures, Option and Result excluded (at most one run), Seq/Sequence only through the functions collection_functions marks as consuming (runs_callback) -- written directly or through |>/@@; its argument is CALLED BACK where calls_back says so, in either library's order. A complete application of a consuming function also calls back the callbacks of a lazy sequence handed to it positionally: a Seq/Sequence function that does not consume (Seq.map skipped s) carries its callback, through the names it is bound to and the sequences it is built from, to the consumer that runs it.
  • A BRANCH is one branch of an if, or one case of a match or function.

Two shapes are refused:

  • an ITERATED skip: a called-back argument of a collection iteration that is a skip itself, partially applied or not (List.iter labels ~f:skipped, ~f:(Verdict.skipped ~backend)), or a function written there whose run code makes a skip and no evaluating claim (~f:(fun l -> skipped (tag ^ l))); and the body of a for or while loop whose run code makes a skip and no evaluating claim. A loop whose callback evaluates the claim on one side of its gate and skips it on the other is one claim written once, and passes;
  • a SKIP RUN: a branch whose run code applies two or more skips, read down to the branches nested in it, which are judged on their own. A run is counted up to 64 skips, as each deferred skip value's summary keeps at most that many, so a chain of wrappers that each run the previous one twice stays linear.

Outside the model

Known examples, each read as no skip list: labels iterated by a function of the source rather than a collection module's; a run of single skips spread across nested branches; a deferred value reached other than by its name -- stored in a container or a field, handed as an argument and run through the parameter, or another module's; a stored iteration completed through a parameter or a container; and a lazy sequence consumed by a function of the source.

What is read

The VALUE of every Verdict claim this source applies directly by its path (under any type constraints), whose callee Verdict_callee reads as Verdict's or ambiguous:

  • the boolean of p, claim, pass_fail and gated (the second positional argument), and of pf and claimf (the last positional argument, after the format's);
  • the predicate ~f of a quantified claim -- p_all, p_alli, p_exists, p_all2, pf_all2, pass_fail_all2 and the gated_* forms, whose element passes where it returns true, and p_none, whose element passes where it returns false -- when it is a function written there or a name bound to one: its body, under its parameters.

folded_slots is that table; folded_unread_members the members with no boolean to read (fail, skipped, case, p_empty, p_pairwise_distinct), and verdict_ratchet holds the two equal to Verdict.Claims together.

The value is split into the DISJUNCTS whose truth alone passes the claim: through || (and, under a not, &&), not (which swaps the two), a name into its let right-hand side, type constraints, a let body and a sequence's last expression; and through an if one of whose branches is the passing constant -- if on_cpu then ok else true is (not on_cpu) || ok. The For a nonrecursive let with a flat tuple pattern of variables and wildcards, each variable sees only its position in a same-arity tuple literal. A tuple can be returned through an if with two arms, match, local let (including let%op and let%cd) or a sequence; every terminal value must be a tuple literal of that arity. The enclosing condition and branch scopes survive projection. A branch can return the passing Boolean after a diagnostic or local binding. The claim is refused when one disjunct is RUN-CONSTANT and another is computed by the test: the gate decides the verdict wherever it is closed. For a gated claim, a disjunct that makes its own ~when_ false -- a conjunct of the gate, negated -- is dropped first: the claim is never evaluated where it holds. A disjunct that is a constant -- a literal, a library value -- is neither, so a claim over the configuration and constants alone is no fold.

Run-constant

A value fixed by the run's configuration, not computed by the test: what a configuration reader returns (configuration_readers: Utils.get_global_arg, Utils.get_global_flag, Sys.getenv/getenv_opt, Context.backend_name, Context.hardware_limits, Context.backend_facts -- an applied path ending in one of these names, or an unqualified one the source does not bind), a value of Sys (Sys.win32, Sys.os_type, Sys.big_endian, Sys.argv, ...), the settings record Utils.settings (its fields being the configuration), and what is computed from those and constants alone: an application of a function from outside the source to run-constant and constant arguments, at least one of them run-constant (Context.backend_facts_of_name backend_name, String.equal backend_name "metal", not on_gpu); an if, match or try over such parts; a field, a lazy or a constructor of one, a field of a record the source writes out being that field's value; a name bound to one by let, anywhere in the source, a qualified path into a module of the source (Gates.on_cpu) being that module's binding of the name -- or, for a cell the source assigns into with :=, to a run-constant value in its initializer or in any write, whatever their order. A constant is a literal, a constructor of constants, or a library value.

So on_cpu, on_gpu, is_metal, seeds_here = Autotune.seeded_default_backend facts and a lazy hardware probe are gates; a value computed from the program under test -- a census, a readback, a query's answer, a seed list -- is not, though it read the backend along the way, because it also reads something that is not run-constant (a parameter, a pattern variable, a function value, a call over constants alone such as Context.auto ()). The distinction is the one Verdict's gates draw: the backend, an advertised capability, the configuration.

What is not read

A claim reached through a wrapper the source binds (let check label ok = p label ok), applied through |> or @@, or partially applied; a function's result where the function is the source's own (has_mma () is not run-constant, whatever its body reads); destructuring outside the flat tuple form above (including values bound by a match case), qualified access to a projected component, and a gate folded below a conjunction (census_ok && ((not on_metal) || dialect_ok)), which the claim checks partly everywhere -- the label then promises both halves, and only the reader of the label can tell that the second is vacuous off Metal. Each is a place a folded gate can hide; none is one this reader reports where the fold is not there.

The other direction has three known places, each loud -- a refusal of a claim that does not fold: a cell's writes are not ordered against its reads (above); a configuration reader is run-constant whatever it is handed (Context.hardware_limits ctx of an element's own ctx); and Sys, Utils.settings and the reader names are recognized by spelling, so a module the source binds under one of those names is read as the standard one, unless the path names a binding of that module of the source.

Leg-gate independence and ambient-policy alignment (gh-ocannl-2434)

A Verdict.leg or Verdict.sub_leg condition (~when_) must derive from an invariant independent of the code or capability value under test, and must read the same numerics policy that its in_leg/in_legf claims execute under. Otherwise a regression in the function or capability under test — or a policy switch applied only after the leg was constructed — closes the gate and turns every claim in the leg into SKIPPED while the golden stays green (gh-ocannl-2434: dominant_kernel_mma_ceiling gating on Autotune.mma_peak_leg, compiled_workgroup_bytes gating on workgroup_allocation_alignment/workgroup_reporting_granule, and winner_fixture_replay calling Ll_test.advertised before Test_utils.with_policy enabled tf32_matmuls).

What is read (closed fail-closed allowlist)

Every Verdict.leg and Verdict.sub_leg application whose callee Verdict_callee resolves as Verdicts or Ambiguous, and every in_leg/in_legf application resolved the same way:

  • Disallowed external calls and capability fields (disallowed_calls): walks each leg's ~when_ expression, following local let bindings (including destructured tuple/record bindings, lazy, functions, := writes, local helper call-site arguments, immediately applied anonymous functions and List/Array iterator callbacks) in lexical scope (Lexical_scope) and resolving local module aliases (module A = Path) and known re-export opens (open Ir, open Test_utils). Every external qualified value path (M.x) and qualified record field projection (e.M.field), as well as every unqualified field projection or record pattern over a value bound from Context.codegen_capabilities, Context.hardware_limits, Context.backend_facts or Context.backend_facts_of_name, must belong to the closed allowlist of standard-library modules (leg_gate_stdlib_modules) or independent platform, backend, configuration and capability queries (leg_gate_allowed_paths). A gate parameter with no resolvable local call site is reported as <unresolved-param:name> rather than counted clean. Any other external path is reported; legitimate sites that call a production module for an independent reason belong in verdict_ratchet.ml's exempt_leg_gate_calls with that stated reason.
  • Ambient-policy mismatch (policy_mismatches): tracks the enclosing calls to Test_utils's policy wrappers (?policy_wrappers, derived by verdict_ratchet from Policy_invariance_scan.wrappers on test/support/test_utils.ml), scoping only the wrapper's callback (including named callbacks and local helpers) and not its policy-adjuster argument. A leg whose ~when_ reaches an ambient-policy reader — Ll_test.advertised at full application (accumulated across partial-application aliases) without a supplied pinned ~policy (missing, ?policy:None, or an unchanged Ir.Numerics.get ()), Ll_test.tensorized_capability, Ll_test.tensorized_matmul_capability, or Ir.Numerics.get outside an adjusted ~policy argument to Ll_test.advertised — is refused when an in_leg/in_legf using that leg (directly or through local let bindings, per-invocation helper results and sub_leg parents, including inline parent legs) runs inside a policy-wrapper callback that did not enclose the ambient read's evaluation (the binding site for eager reads, or the first force site for sub_leg lazy reads; each named lazy binding replays only on its first force).

What is deliberately not read

  • Unqualified identifiers imported by an open of an external production module (e.g. open Autotune) that does not appear in a qualified path or module alias;
  • Functor parameters, first-class modules, or legs passed across module or file boundaries (cross-file leg construction is handled by gate_census);
  • Imperative Ir.Numerics.set_policy ordering outside structured Test_utils.with_* scopes;
  • Capability-descriptor queries (Ir.Backend_intf.advertises_mma_format_in_scope, Ir.Backend_intf.mma, Ll_test.advertised) are allowlisted because GPU execution legs legitimately gate on hardware ISA capability, so a leg gated on the descriptor it claims about (without an independent hardware-floor claim) is not refused by this reader;
  • Verdict.gated / Verdict.gated_* claims (this reader governs Verdict.leg and Verdict.sub_leg legs; population-reading gates on both forms are checked by gate_census).
