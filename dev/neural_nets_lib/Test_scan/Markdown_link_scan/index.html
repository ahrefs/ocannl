Module Test_scan.Markdown_link_scan

Checking the closed inline-link dialect against repository source paths.

Closed dialect: single-line inline links and images with unnested labels and literal relative file/directory destinations, angle destinations and optional titles, through Agent_notes_scan.links_of. Reference links, HTML links, code spans, fences and comments are outside the destination reader. Schemed and protocol-relative URLs are ignored; root-relative paths, escapes, percent encoding, queries, entities, colons and parentheses are refused.

Nonempty fragments on Markdown targets in in_corpus, including same-file fragments, are checked. Non-Markdown and out-of-corpus fragments are ignored (including source #L line links), but their files must exist. Empty fragments mean the top of the file.

Heading dialect: ATX (one to six hashes, up to three leading spaces), outside fences, comments and code spans; top-level indented code is ignored. Container heading candidates (quote/list-prefixed ATX or Setext and indented continuations, including code-like candidates) refuse the target because container block contexts are not interpreted. ASCII text plus U+2014 em dash (removed), unpadded inline code and asterisk emphasis are supported: lowercase, spaces become hyphens, punctuation is removed except underscores and hyphens. Duplicate IDs use GitHub's first unused -1, -2, ... suffix, including collisions with literal suffixed titles. Setext headings, links/images, HTML, entities, escapes, other Unicode, controls, padded code spans and underscore emphasis in headings refuse the linked file rather than guessing its IDs. Raw HTML block openers also refuse the file: allocating their contents would require HTML block context, which this reader does not interpret.
