Module Test_scan.Forced_decline_sort

Sorting a forced-decline sweep's failures into the census claims the leg predicts and the anomalies it does not, against the census scan's census-judging tests (gh-ocannl-1308).

Sorting a forced-decline sweep's failures (gh-ocannl-1308's leg; the post-wave sorter of lukstafi/ocannl-staging#2233).

Under OCANNL_TOOL_TEST_FORCE_TILE_MMA_DECLINE=1 every Tile_mma declines to the lane-0 scalar fallback, so a sweep over the census-judging stanzas is red by design: its census claims are expected to fail and its parity claims are expected to hold. This reader takes such a sweep's log -- a tools/test-run.sh run record's log, or any dune output of the same runs -- and sorts each failure into what the leg predicts and what it does not:

  • a census failure (expected): a failed claim, in a stanza running a census-judging test, whose label asserts no parity and speaks the census's vocabulary (names_census);
  • an expected value failure: a failed claim asserting parity that decline_sensitive lists, each with the reason its reference is one rendering's numerics or its label conjoins a census judgment (build-and-test.md#verdict-claims names them);
  • an anomaly, with its stanza: a failed parity claim nothing lists, a crash, a stanza whose failure count the reader cannot account for, a failure in a stanza that runs no census-judging test, and any failure dune reports on a file other than a dune file (a golden diff, a build error).

What it reads

  • The census-judging tests are tensorized_census_ratchet's own reading (Tensorized_census_scan.judged_paths): the caller hands them in, never a list of its own.
  • "Asserts parity" is asserts_parity: the census scan's own vocabulary (Tensorized_census_scan.asserts_parity) widened by the agreement words a tolerance claim uses (agree, equal, identical, within, same as), applied to the label as the FAIL: line renders it. Wider than the scan, which decides what needs a census, because here a word missed is a value regression read as an expected census failure.
  • Lines are read with their ANSI SGR escapes removed, so a colorized dune log (CLICOLOR_FORCE=1) sorts as a plain one.
  • A failing action is a dune header, File "<dir>/dune", line(s) ..., with the excerpt dune prints under it. The stanza is the (name X) it highlights, or the (target X.actual) of a rule; the test is the executable the excerpt runs (%{dep:Y.exe}), else X itself, so a variant rule sorts against its program's source <dir>/Y.ml.
  • Inside a block: FAIL: lines (claims; the trailing : false dropped), the teardown line FAILED: <n> check(s) did not hold ..., and the crash markers STOPPED EARLY, Fatal error: and Uncaught exception. A block is sorted only when it has a teardown line whose count equals its FAIL: lines and dune truncated nothing (...TRUNCATED BY DUNE...); anything else is an anomaly, so a failure the reader cannot see is never counted as a census one.
  • The aliases the run asked for, read off the line naming the most @<dir>/runtest-<name> targets, so the report can list the stanzas that held; and a run record's closing exit: <n> line. A run that ended other than 0 or 1 (a cap, a cancellation, a refused slot) did not finish its stanzas: that is an anomaly, and no stanza is reported held.

What it deliberately does not read

  • A claim is read by its rendered label alone, as the census scan reads claims. So a failed claim whose label asserts no parity yet names the census vocabulary sorts as a census failure even if it was in fact a value claim; one naming neither is an anomaly (unread), so a new census wording is a loud red until names_census learns it, never a silent pass.
  • It does not decide which stanzas SHOULD have run: a judged test missing from the sweep is the leg's own boundary (tensorized_census_ratchet holds every running stanza to declaring the variable), not something a log shows.

val names_census : Base.String.t -> Base.bool

Whether a rendered label speaks the census's vocabulary: tensorization by the census scan's own words (Tensorized_census_scan.names_tensorization), or a word of the rendering a census claim describes -- a stem of render, register-til, register til, label, structure, census, declin, fallback, fragment, intrinsic, simdgroup, micro-kernel, emit, tile, tiling, pack, panel, geometry, bridge, splat, lane. A closed list read off every census claim the saved sweeps fail; a census claim worded outside it reads as an anomaly (see the header).
