  • Recognised forms (closed boundary)

Recognised forms (closed boundary)

  • Table structure: Markdown pipe-table lines (stripped line starting and ending with '|'), skipping the first header row and any separator row whose cells contain only '-', ':', and whitespace. Every data row must have exactly four pipe-delimited cells (Seam | Failure mode | Status and acceptance evidence | Remaining leg).
  • Inline code tokens: single-line, single-backtick spans (`...`) inside table data rows. Unclosed backticks on a row are refused; double-backtick fences and prose outside the pipe table are deliberately not read.
  • Point coverage: the complete constructor set is derived directly from Ir.Resource_fault_injection.all_of_point (never a copied list). Every constructor must appear as a backticked token (`<Point>` or `Resource_fault_injection.<Point>`) in at least one table data row.
  • Qualified fault-injector references: every backticked token starting with Resource_fault_injection. or FI. in a table row must name a live constructor of all_of_point or a full qualified exported path of arrayjit/lib/resource_fault_injection.mli.
  • Cited repository paths: every backticked token in a table row containing '/' and ending in ".ml", ".mli", ".md", or ".sh" must exist in the repository's Source_inventory.
  • Covered-row test requirement: every data row whose Status and acceptance evidence cell starts with "Covered" must cite at least one existing ".ml" test file under "test/" or "arrayjit/test/" in that cell.
  • Cited Autotune.* hooks: every backticked token starting with "Autotune." in a table row must name a full qualified value, module, type, or exception path (including nested submodules such as Autotune.Seam.<name>) declared in arrayjit/lib/autotune.mli (parsed via Ppxlib.Parse.interface).

Deliberately out of scope: relative Markdown links (enforced by markdown_links), prose outside the pipe table, bare unbackticked identifiers, and runtime test execution.
