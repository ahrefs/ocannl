Module Test_utils.Kernel_exec_scan

Deciding which tests compile or execute kernel text they built themselves -- a staged callback, a ?prelowered compile, or a support value reaching either -- the population a codegen change breaks without any of it pinning text (gh-ocannl-1685).

The tests that compile or execute kernel text they built themselves (gh-ocannl-1685).

Codegen_text_scan finds the tests that PIN emitted text. A second population breaks on a codegen change without pinning anything: the tests whose kernels did not come out of the Assignments pipeline. gh-ocannl-1338 renamed every GPU node identifier to t_<name> and ran all 103 text-pinning tests on CUDA and HIP; master still went red on CUDA, because shipped_kernels_alone's staged callback writes sk_staged[0] = 2.0f; verbatim -- text no renderer renames -- and nothing listed it.

A test reaches such text three ways, and the scan names which:

  • a staged callback: it CONSTRUCTS a Low_level.Staged_compilation, whose document the C-family renderers emit verbatim, invisible to every analysis and renamed by nothing. A pattern matching the constructor builds nothing and is not a member. Whether the callback then reaches a compiler is not decided here: its text is opaque by design, so the scan does not guess from the surrounding syntax, and a test that only renders one costs a run, not a miss.
  • a prelowered compile: it hands Context.compile or Context.compile_outcome a lowering of its own through the ?prelowered seam (gh-ocannl-562) -- an IR shape the pipeline never emits, compiled as written. Context.link_delta's ~prelowered:true links nothing and is not the seam.
  • through a harness: it calls a value of a support module that does either of the above, directly or through further values -- Ll_test.execute reaches Ll_test.link's seam call, and Bench_harness.time_shipped_kernels compiles each shipped kernel alone through it.

The harness values are DERIVED, not listed: harness reads the support modules handed over and closes the set under reference, so a new executing helper is on the frontier the day it is written. A support module's include passes its included module's values on, and a test reaches a harness module by a qualifier, an alias of one, an open or an include.

The reading is syntactic and errs toward listing: a name that resolves to a harness value counts whether or not the binding in scope is that value, and an open counts file-wide. A spurious member costs one run; a missing one is the gh-ocannl-1338 red.
