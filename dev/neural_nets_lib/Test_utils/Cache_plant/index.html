Module Test_utils.Cache_plant

Planting schedule-cache entries by hand from a few named arguments, and the waiver for claims resting on cache I/O the filesystem refused.

Planting schedule-cache entries by hand, and waiving the claims a cache operation rests on where the filesystem refused it.

A test that needs an entry the tuner no longer writes (a corrupt or stale winner, a fissioned winner built from a chosen segmentation, a synthetic entry for a pure-filesystem exercise) builds it here rather than spelling out the Ir.Schedule_cache.entry record, so a field added to the entry reaches every planted one through these defaults. Every entry built here records no default-pipeline measurement, tensorized best, default fingerprint or search trajectory: the shape of an entry written before those fields existed, which replays as "nothing is known".

The backend name is an explicit argument wherever a key or a codegen tag is derived (as Ir.Schedule_cache.codegen_tag takes it), never read off the limits record.

plant ~cache_dir ~backend ~timing_identity ~limits ~capabilities canon stores, under key, an entry for canon's routine self-described the way Autotune.tune describes one it stores (the codegen tag and timing objective of this process, canon's digest), carrying saved and segments. Returns the store's cache I/O (SC.recording_cache_io): what a claim resting on the planted entry is waived by (unless_refused). Without a concrete timing identity the key is None, nothing is stored, and the record is empty.

The cache-I/O refusal waiver

The cache absorbs a filesystem refusal by design (gh-ocannl-1040): a refused store or lookup leaves a claim about a store or a replay false for a reason none of its own predicates observes. Such a claim is waived, as an environment skip and never as a pass, where an operation it rests on was refused. A deterministic refusal (a rejected filename, a commit that always fails) would waive it on every run, so a test using the waiver also keeps one claim no refusal waives: not every store it attempted was refused (not_every_store_refused).

val refused : SC.cache_io -> bool

Whether the filesystem refused the operation.

val refused_on : string

The waiver's skip reason.

val refused_in : SC.cache_io Base.List.t -> string -> Base.bool

refused_in ios label: whether any of ios was refused, naming on stderr, for the claim label it waives, what refused and why.

val unless_refused : SC.cache_io Base.List.t -> Base.String.t -> Base.bool -> Base.unit

unless_refused ios label b claims b where none of ios was refused, and skips label as an environment skip (refused_on) where one was.

The claim no refusal waives

Over the stores a test attempted, per cache directory and per kind of entry (placement, under the "placements-" namespace, or schedule, every other key), not all were refused. Grouping keeps a refusal local to one leg -- one directory refused for its path or its ACL, or schedule entries refused while placement entries commit -- from hiding behind another's successes. A group with fewer than two attempts is outside the claim, so one transient refusal cannot fail it.

The claim is gated, but never on the stores themselves (gh-ocannl-1115): a gate that closed when no store was attempted would turn a regression that stops attempting them into a skip. The caller states instead whether stores were bound to be attempted, from what the attempt rests on -- a timing identity to key them under, clean evidence to record -- and where they were, a run that judged no group fails the claim.

val store_kind : SC.cache_io -> string

The kind of entry a cache operation is on, for the grouping above.

val not_every_store_refused : expected:bool -> Base.String.t -> SC.cache_io Base.List.t -> Base.unit

not_every_store_refused ~expected label ios: the claim label that, of the stores among ios, in each cache directory and kind with two or more attempts, not every one was refused -- and that there is such a group. expected is whether the caller's run was bound to attempt two or more stores of a kind in one directory, derived from what the attempts rest on and never from ios; where it is false the claim is an environment skip. Each group's count goes to stderr.

The timing-identity gate

Without a concrete timing identity the cache key is None: nothing is stored or looked up, so a claim about a store or a replay is vacuous. Such a claim is skipped, as an environment skip on unkeyed_on, where the identity of the context the store keys on -- the run's OWN context, never a reference context's -- is missing. The first such skip in a process says so on stderr.

val unkeyed_on : string

The identity gate's skip reason.

val unless_unkeyed : identity:Base.bool -> Base.String.t -> Base.bool -> Base.unit

unless_unkeyed ~identity label b claims b where identity (whether the context the claim's cache operations key on has a concrete timing identity), and skips label as an environment skip (unkeyed_on) where it is false.

val unless_unkeyed_or_refused : identity:Base.bool -> SC.cache_io Base.List.t -> Base.String.t -> Base.bool -> Base.unit

unless_unkeyed_or_refused ~identity ios label b is unless_unkeyed where identity is false, and unless_refused ios where it is true: a claim resting on the cache operations ios of a keyed run.
