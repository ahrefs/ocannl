Module Test_utils.Verdict_scan

Scanning test sources for claims a test decides itself and prints outside Verdict, where a failing one is dune promote-able into the golden.

Finding self-decided verdicts that a test prints itself instead of routing through Verdict.

gh-ocannl-601 established the rule and swept the sites that existed then: a claim the test decides — <label>: <bool> — must go through Verdict, so that a failure exits the process nonzero. Printed and exited 0, the same line is gated only by the golden diff, and the natural next move on a failing diff is dune promote, which records <label>: false as the expected output. In a golden that is nothing but verdict lines, a blessed regression and a deliberately recorded negative fact are the same text.

That sweep was one-time and left no mechanical trace, so the population regrew: a test written afterwards (bandwidth_calibration, gh-ocannl-578) came in with four fresh Stdio.printf "…: %b\n" claims, and nothing failed or warned. This module is the reader behind the ratchet that stops that (gh-ocannl-668).

What shape is recognised

A format whose LAST argument-consuming conversion is a bare %b at the end, behind a label that ends in one of the separators a claim is written with — a colon, an equals sign, or an arrow. Two kinds, told apart by whether anything else in the format consumes an argument:

  • Literal_label: the %b is the only conversion, so the label is written out. "k-blocks fused: %b\n", "round-trip identity = %b\n", "hoisted -> %b\n".
  • Computed_label: the label is built from arguments. "%s fused: %b\n", "Epoch %d, loss below threshold=%b\n".

Both are recognised now. The literal form was gh-ocannl-668's; the computed one is gh-ocannl-624, which the sweep of that issue converted onto Verdict.pf and Verdict.claimf — entry points that did not exist when this reader was written, which is why the shape was out of scope then and is not now. The separator vocabulary is the other thing that widened: a reader that accepted only a colon was blind to the whole "… = %b" population, and that is how the claims in data_parallel, shard_transfer and test_buffer_loc sat outside a check written to catch exactly them.

The escape hatch is narrower as a result, and deliberately so. A descriptive print used to escape by carrying a second conversion; a computed label carries one by construction, so that no longer distinguishes it. What is left is a named exemption in the test that consumes this — one per site, with the reason it is not an assertion. The population that needs one is small (a handful of census rows and tables), because a print whose boolean is not a verdict usually does not end on the boolean.

Why it reads the parse tree

Same argument as Config_key_scan, whose parse helpers this shares, and the same conclusion: this module parses, it does not match text. A text scan reads prose as code — this file's own documentation quotes the shape it hunts — and cannot tell a format written over a line continuation from one written on a line. On the parse tree a string literal carries its decoded value whatever escapes or delimiters produced it.

Attribute payloads are the one thing deliberately skipped. A documentation comment becomes an @@@ocaml.doc attribute holding a string, so a comment quoting the shape arrives as a literal to flag; that is prose, and prose is not a print. Extension payloads are not skipped — a %cd or %expect payload is code, or is the golden text of one.

Every claim-shaped literal, not only those applied to a printf

What the check fails on is the literal, wherever it sits; which function receives it is reported but decides nothing. The alternative — flag only what is applied to a printing function — is evaded by any wrapper, including the let p name b = Stdio.printf "%s: %b\n" name b helpers several tests defined before Verdict existed. Those helpers are the exact population this ratchet exists to keep from regrowing, so a claim-shaped format string in a test source is either an assertion or, by exemption, a documented exception.

type directive = {
  1. start : Base.int;
  2. stop : Base.int;
  3. conversion : Base.char;
}

A conversion directive as the format spells it: where the '%' is, where the conversion character is, and what it is. A bare %b has stop = start + 1; anything wider carries flags, a width or a precision between the two.

val consumes_nothing : char -> bool

Directives that consume no argument, so a format carrying one still takes however many arguments it took: %% (a literal per cent), %! (flush), %, (a separator that prints nothing). Everything else counts as consuming — including the nested-format spellings %\{…%\} and %(…%), whose presence therefore takes a format out of the recognised shape rather than into it. Erring that way costs a report that was never made, never a false one.

val directives : Base.String.t -> directive Base.List.t

The conversion directives of a format string, in order. Scans for '%', then flags, width and precision, then the conversion character. A trailing '%' with nothing after it is not a directive and ends the scan.

val printed_text : Base.String.t -> string

What a reader sees printed by a stretch of format text, with the arguments left out: %% is a per cent sign, every other directive contributes nothing this reader can know, and the rest is itself. Applied to the text before and after the %b.

It removes each directive by the SPAN directives found, flags and width included, rather than by a fixed two characters — otherwise %-22s leaves "22s" behind and a claim's rendered label reads as that debris. The span is also what keeps the tail check honest, since a directive there prints nothing whatever its width.

type kind =
  1. | Literal_label
    (*

    The %b is the format's only conversion: the label is written out.

    *)
  2. | Computed_label
    (*

    Something else in the format consumes an argument: the label is built.

    *)
val separators : string list

The separators a claim is written with, longest first so that a head ending in "->" is not read as ending in "-" by a shorter match. A colon is what the gh-ocannl-601 sweep normalised to; the other two are what the sites it could not convert used, and a reader blind to them is blind to most of the population.

val claim_site : Base.String.t -> (Base.String.t * kind * Base.String.t) Base.Option.t

claim_of together with the verbatim head, which is what names a computed site.

val claim_of : Base.String.t -> (Base.String.t * kind) Base.Option.t

claim_of format is the label of the claim format prints and which kind it is, when it prints one.

Three things must hold at once:

  • the LAST argument-consuming conversion is a bare %b — a width or a flag means the print is laying out a column, which is formatting rather than asserting;
  • what follows it prints as whitespace, or as nothing: a newline, a blank line, a %! flush;
  • what precedes it ends in one of separators, with a non-empty label before it.

So "k-blocks fused: %b\n" yields Some ("k-blocks fused", Literal_label) and "%s fused: %b\n" yields Some ("fused", Computed_label) — the second's label is what survives rendering the head, which drops the conversions it cannot fill in, so it is a report's hint rather than the site's identity; an exemption for a computed site is keyed by the head.

A computed label may render to NOTHING and still be a claim: "%s: %b\n" is the wrapper the pre-Verdict tests defined for themselves, and the whole of its label is the argument. Only a LITERAL label has to be non-empty, because there the residual is all there was. "fused: %b (expect false)\n" and "fused? %b\n" yield None: neither is the bare claim form, and a reader cannot take their boolean at face value.

val claim_label : Base.String.t -> Base.String.t Base.Option.t

claim_of without the kind, for a caller that only wants to know what the line asserts.

A gated claim reported in two dialects (gh-ocannl-997)

Verdict.skipped prints <label>: true — Verdict.p's line — so that a leg one host cannot evaluate leaves the golden exactly as a host that evaluated it does. A claim whose evaluated branch reports through Verdict.pass_fail instead prints <label>: PASS there, and the golden promoted on a machine that evaluates it breaks on the first machine that skips: silently, until the gate actually fires, on whichever host is least likely to be the one promoting. Verdict.gated removes the trap by picking the dialect itself; this reader keeps the mixed spelling from regrowing.

What it pairs is a LABEL that reaches both a pass_fail/pass_fail_all2 call and a skipped call in one source. The label is the first positional argument, keyed three ways: a string literal by its value; a name by the literal it is bound to, in its lexical scope through Lexical_scope (the let claim = "…" shared by the two branches is the shape both sightings had), otherwise by the name itself; anything else by its printed expression, so a label computed the same way on both sides is still one label. A literal pairs across the whole source; a name or an expression pairs only within one top-level item, since equal names in two functions need not be one label. Named and computed keys retain their bindings' identities. The callees are matched by their last path component, which is how an opened Verdict.Claims and the per-test let skipped = Verdict.skipped ~backend:backend_name both read.

Fail-loud boundary: unknown or shadowed labels stay named/computed rather than borrowing a literal elsewhere. Unknown opens bring in no values.

What it cannot see: a skip or a PASS/FAIL claim routed through a wrapper of another name, and one label computed by two different expressions. Those are the reason the remedy is an entry point rather than this check — Verdict.gated has no second dialect to pair.

A claim label written with a line break (post-wave task of staging#1134)

A claim is one row on each channel it prints to: tools/mutation-run.sh reads a run's FAIL: …: false lines off its log and counts its stdout rows against the golden's. A label with a newline in it used to split its claim into a FAIL: head that is no false claim and an unprefixed tail that is a row the golden lacks. Verdict now renders every claim line through Verdict.one_line (a control character becomes a space), which keeps a COMPUTED label on one row; a LITERAL one with a line break can only be a mistake -- a cosmetic blank line before the claim, as test_random_histograms had, belongs in a printf of its own -- so this reader refuses it where it is written rather than leaving the sanitizer to turn it into a stray space.

What it reads is the label argument of every claim form in labelled_claims that is Verdict's (see claim_calls): the first positional argument, keyed as dialect_census keys it, so a name bound to a literal is that literal. A pf/claimf/pf_all2 format is its label too, and a line break in the format is one in every rendered label. Verdict.fail is not read: its argument is a message, multi-line by design, and every line of it is printed with the prefix.

Where a label counts as LITERAL is a deliberate, closed list: a string constant, under any type constraints or coercions, or a name bound to one -- directly or through a chain of let renamings. Every other expression is a computed label, however statically it could be evaluated (if c then "a\nb" else "c", String.concat): that is the sanitizer's case, and Verdict prints it on one row whatever it holds. This reader is the lint for the label a person writes out; the sanitizer is what makes the run correct.

The CALL is read the same way: a claim applied by its path, under any constraints or coercions. A claim applied any other way -- through @@ or |>, or passed as a value -- is not read; its label, too, is the sanitizer's.

What it cannot see: a label computed from an expression (the sanitizer's case, by design), a claim reached through a wrapper the source binds (let skipped = Verdict.skipped ~backend), and an unqualified claim name brought in by an open this scan does not model (a module that re-exports Verdict.Claims under another name).

A claim name that reaches Verdict only past an open of a module Verdict_callee cannot read is Ambiguous: that module may export a function of the name, or a Verdict module of its own -- Verdict.p past an open Other is ambiguous as much as an unqualified p past one (gh-ocannl-1361). Such a site is READ, and a line break in its literal label is refused with the remedy of qualifying the call -- loudly, since the alternative, leaving it unread, is how a later open Ll_test would silently exempt every claim after it.

A float tolerance hand-rolled into a parity claim's predicate (gh-ocannl-1224)

Verdict.p_close name got want ~tol compares two float readbacks under a tolerance and, when a cell is out of it, names on stderr how many cells differ, the worst one with both values, and the reference's magnitude. The same comparison written as p_all2 name got want ~f:(fun a b -> Float.(abs (a - b) < 1e-3)) prints a bare false: gh-ocannl-1217's sweep recorded exactly that for fifteen seeds and it took a reproduction round on a remote box to learn that every seed was off by the same five ulps of reference rounding. This reader keeps the hand-rolled spelling from regrowing.

What it reads is the ~f predicate of every Verdict p_all2, pf_all2 and pass_fail_all2 call (parity_callees), resolved as claim_calls resolves the callee. The predicate is a hand-rolled tolerance when it is a function whose body applies an abs (any path ending in it: Float.abs, or abs under Float.( … )) to a subtraction (- or -.) -- written in the argument, or a name the predicate's lexical scope binds to such a function (directly, through a chain of renamings, or partially applied: ~f:(close ~tol:1e-4)).

What it cannot see: a predicate reaching the call as a function PARAMETER, a tolerance written without abs (a -. b < t && b -. a < t), and a comparison routed through a helper of another module. Those are spellings nobody in the tree uses; the remedy for each is the same p_close.

A gate that reads the population it quantifies (gh-ocannl-1289)

Verdict.gated_all ~when_ ~on label xs ~f (and gated_alli, gated_exists) skips its claim where when_ is false. A gate computed from the values under test turns the regression the claim exists to catch into a skip: had the population emptied or lost its interesting members, the gate closes, the skip prints p's passing line, and the golden stays green. That is the gh-ocannl-1115 trap, and it shipped twice in one wave through these very forms — a gate asking whether the claim's own results were non-empty (staging#1049), and one asking whether the real seeds results was mapped from held a tensorized one (staging#1063). Verdict.gated ~when_ ~on label b carries the same trap when b quantifies: placement_store gated (not (List.is_empty stores)) && List.for_all stores ~f:refused on stores being non-empty until gh-ocannl-1361. A gate comes from an invariant — the backend, an advertised capability, the configuration — never from the population.

What is read

Every application of gated, gated_all, gated_alli or gated_exists that carries its ~when_ and both positional arguments, where Verdict_callee -- the resolver every Verdict reader shares -- reads the name as Verdict's, Ambiguous (reported as such, with the remedy of qualifying the call) or Free: a gated name nothing binds is read too, since it exists nowhere but in Verdict.Claims. A file's own gated_all, and another module's, are not Verdict's; a name a structure of the file exports is followed to its definition there, so module Checks = struct let gated_all = Verdict.gated_all end opened is Verdict's. A partial application bound by let to a name, under any number of further partial applications, is completed at each application of that name, and x |> f and f @@ x are read as f x; so the let check = Verdict.gated_all ~when_ ~on in check label xs wrapper is one site per use. The two sides are then compared by LEXICAL identity, a name plus the binding it resolves to through Lexical_scope, so a shadowed name is a different value; a name no binding of the source gives (a global, or one an unmodelled open brought in) is one identity, the same on both sides:

  • the GATE is every value identifier the ~when_ expression spells, and transitively every one spelled by the right-hand side of a let it resolves to (function bodies included), or by what the source writes into that binding (below), in any position; a collection-module function collection_functions does not list, applied anywhere the gate reaches, is reported as unlisted;
  • the POPULATION of a gated_* claim is the identifier the quantified argument spells, and the collections it is BUILT from: following a let-bound name into its right-hand side, the branches (not the condition) of an if, the cases of a match (the scrutinee only through a name a case pattern binds and the case returns -- and of that name, only the component it takes apart, where the scrutinee is, through let-bound names, a literal tuple, record or constructor application: see parts), the body of a function in data position (a ~default:(fun () -> ...) thunk), the body and handlers of a try, the body of a let, let module, local open or sequence, the elements of a list, array or tuple literal or constructor payload, the operand of ! and of ref and both operands of @ (where the source does not bind the operator itself), and the arguments that carry the collection into a function of a standard collection module (List, Array, Hashtbl, Map, Option, String, ... — see collection_modules), reached by name, through a module alias (module Rows = List) or a value alias (let map = List.map in map raw ~f, a renaming followed through any number of lets, though not a partial application), and not under a name a local module took over (module Map = Custom); an unqualified List is Stdlib's until an open Base in scope rebinds it. Which arguments carry it is the role collection_functions gives the function by its exact name (builds): every positional one for a transformation, constructor, conversion or quantifier, the collection alone for a Base-ordered selector (find, nth, take, remove, ...), the value filled in for make/create and not the count, what the callback returns for init, and nothing for range, plus the data-bearing labels ~default, ~init, ~data, ~sep, ~with_, ~replacement. A function of a collection module the table does not list is REPORTED (unlisted_call), never read by a guess (gh-ocannl-1303);
  • the body of a binding operator (let+ x = e in body), where x is a part of e;
  • the POPULATION of a gated claim is what its boolean's quantifiers range over, each followed as above: the boolean is read through a name into its right-hand side and what the source writes into it, not, && and || (bare where the source does not bind them, or qualified by a standard library), ! and ref where unbound too, the branches of an if (never the condition), the cases of a match, the body and handlers of a try, the body of a let, let module, local open or sequence, type constraints, pipelines, and a quantifier's own arguments, its predicate's body included (a quantifier nested there ranges over a population of its own, the predicate's parameters none); a quantifier is a collection-module function collection_functions marks quantifies (for_all, exists, is_empty, mem and their indexed and pairwise forms, and the predicates of a collection's elements as a whole: contains, is_sorted, is_some, ...), whose collection is its first positional argument in Base's order (the first two for a pairwise one) and every positional argument in Stdlib's; a collection-module function the table does not list is reported here too;
  • and, for a name it reaches, whatever the source writes into that binding, directly or through a let alias = name renaming: the right-hand side of x := e and of x.field <- e, and what a function of a mutable collection module (mutable_modules) that collection_functions marks as writing (writes: Queue.enqueue x e, Hashtbl.set x ~key ~data, Hashtbl.filter_keys_inplace x ~f, ...) is handed with x, where x is the first positional argument in Base's order and any of them in Stdlib's. A function of a mutable collection module the table does not list, handed x, may write into it: a claim that reaches x is reported as unlisted. So is a writer handed x alone (Queue.enqueue x) or whose value a let binds to a name (let put = Array.set x 0): a possible partial application whose later call this reader does not follow. A partial writer that escapes otherwise (returned, or handed to another function) is not followed. A field write x.f <- e reaches x whole, and the f a pattern takes apart from x's literal, not its other fields. x is a name the source binds; a container only an open brought in is not tracked. Only a write that may run before the claim counts (precedes): one placed after it, in code that cannot run again before it, is not followed.

The claim is refused when the two share a binding. The asymmetry is the point: a gate may read what the population is COMPUTED from (the site, the hardware limits, the backend steering an if), which is how a capability judgment over the same program reads, and must not read the population or a collection it is mapped, filtered or appended from.

What is not read

The forms above are a closed list: any other expression form ends the population side there, and a population reached only through one is not compared. The exception is a collection-module function, which is never outside the list: collection_functions enumerates the ones the reader reads, and any other is reported. The ones known to matter:

The population is not followed through a call to any other function (a file-local gpu_seeds pre stops at the call), through a record field, through a function parameter (the caller's argument is not substituted), or through an unqualified name under an open of a collection module (List.(permute raw)) that collection_functions does not list: such a name is read as whatever else binds it, and is not reported as unlisted, since without the module's signature it cannot be told from a function of the source (a listed name there is the module's, resolve_callee); a destructured let binds names that are followed no further, and a value reached through a module path (M.rows) is an identity on neither side. A gate threaded into a wrapper as its own parameter (let check ~when_ label xs = gated_all ~when_ ...) is read at the wrapper's definition, where it is a parameter, and not at its callers. A gated boolean that quantifies nothing has no population: its comparisons and other calls are operands this reader does not read, so gated ~when_:(xs <> []) label (sum xs = want) passes, and so does a gate folded into a value (p "…" ((not on_cpu) || ok)), which folded_gate_census reads instead. Each of these is a place a population gate can hide from this reader; none is a place it reports one that is not there.

A gated application the reader cannot complete — a partial application no let binds, a let-bound one that no use the reader resolves completes (reached only through a module path, say), or a claim (or a let-bound wrapper of one) named as a value, handed to List.iter say — is reported as unread rather than counted as clean, so the boundary is loud there.

Which writes may precede a claim (gh-ocannl-1303)

A write into a binding the population or the gate reaches is followed only when it may run before the claim is evaluated: Queue.enqueue queue v written after the claim, in code that cannot run again before it, cannot have shaped the claim's population, and a gate reading v is not refused on its account. Lexical order alone is not the answer -- a write later in a loop body precedes the claim's next iteration, and so does a write in a function called again -- so the reader places both points in the program's control structure, conservatively: every construct whose body may run more than once, or at a time the reader does not know, is a frame of each point inside it.

  • A while loop, a for loop's body (not its bounds), and a function handed directly to a function of a collection module other than Seq or Sequence in a position that module calls before it returns (a List.iter callback: calls_back), run synchronously, possibly many times: a Loop. A function handed in any other position (List.singleton (fun () -> ...)) may be stored and called later, like any other function value.
  • Any other function may run whenever it is called. It is ONCE when it is the right-hand side of a non-recursive local let whose name the source spells exactly once, as the callee of a full application outside the function's own body: then its body runs exactly where that call runs, and a point in it is placed at the call. A top-level function is never once, since another module may call it.
  • lazy, a binding operator's body, an object or class, a functor's body and an extension's payload (let%expect_test included) run at a time the reader does not model: Deferred.

A write may precede a claim when, at the outermost level where the two are not inside the same call of a once function, (a) both are inside one frame that may repeat (a loop, a function that is not once, a deferred construct), (b) the claim is inside such a frame of its own that may run at any later time (a function that is not once, or a deferred construct) the write is not in, or (c) the write starts before the claim ends, or (d) the two sit in different operands of one expression whose operands OCaml evaluates in an unspecified order -- an application's callee and arguments (&& and || apart), a tuple, array or record's components, the bindings of one let ... and ..., a binding operator's operands -- so consume (claim; ()) (write ()) may run the write first. (A write in a function defined before the claim is before it; one in a function defined after it cannot run before it unless the claim runs again, which (a) and (b) cover.) Inside one call of a once function the same question is asked of the two points within it. A claim's own arguments are before its end, so a write there precedes it.

What this does not model, each erring toward following the write: a function value stored and called later is placed where it is defined; a once function's name passed anywhere but a call is not once.

A gate folded into the claim's value (gh-ocannl-1310)

p "…" ((not on_cpu) || ok) prints true on a GPU run: a pass, byte-identical to a CPU run that checked ok, where the honest report is a skip. The run's own transcript then says the claim held on hardware that never evaluated it -- the same invisibility Verdict.skipped exists to end, reached by folding the gate into the boolean instead of spelling the skip. Verdict.gated ~when_:on_cpu ~on:backend_name "…" ok (or a quantified gated_* form) is the spelling that reports it, and this reader refuses the folded one.

What is read

The VALUE of every Verdict claim this source applies directly by its path (under any type constraints), whose callee Verdict_callee reads as Verdict's or ambiguous:

  • the boolean of p, claim, pass_fail and gated (the second positional argument), and of pf and claimf (the last positional argument, after the format's);
  • the predicate ~f of a quantified claim -- p_all, p_alli, p_exists, p_all2, pf_all2, pass_fail_all2 and the gated_* forms, whose element passes where it returns true, and p_none, whose element passes where it returns false -- when it is a function written there or a name bound to one: its body, under its parameters.

folded_slots is that table; folded_unread_members the members with no boolean to read (fail, skipped, case, p_empty, p_pairwise_distinct), and verdict_ratchet holds the two equal to Verdict.Claims together.

The value is split into the DISJUNCTS whose truth alone passes the claim: through || (and, under a not, &&), not (which swaps the two), a name into its let right-hand side, type constraints, a let body and a sequence's last expression; and through an if one of whose branches is the passing constant -- if on_cpu then ok else true is (not on_cpu) || ok. The claim is refused when one disjunct is RUN-CONSTANT and another is computed by the test: the gate decides the verdict wherever it is closed. For a gated claim, a disjunct that makes its own ~when_ false -- a conjunct of the gate, negated -- is dropped first: the claim is never evaluated where it holds. A disjunct that is a constant -- a literal, a library value -- is neither, so a claim over the configuration and constants alone is no fold.

Run-constant

A value fixed by the run's configuration, not computed by the test: what a configuration reader returns (configuration_readers: Utils.get_global_arg, Utils.get_global_flag, Sys.getenv/getenv_opt, Context.backend_name, Context.hardware_limits -- an applied path ending in one of these names, or an unqualified one the source does not bind), a value of Sys (Sys.win32, Sys.os_type, Sys.big_endian, Sys.argv, ...), the settings record Utils.settings (its fields being the configuration), and what is computed from those and constants alone: an application of a function from outside the source to run-constant and constant arguments, at least one of them run-constant (backend_is_cpu backend_name, String.equal backend_name "metal", not on_gpu); an if, match or try over such parts; a field, a lazy or a constructor of one, a field of a record the source writes out being that field's value; a name bound to one by let, anywhere in the source, a qualified path into a module of the source (Gates.on_cpu) being that module's binding of the name -- or, for a cell the source assigns into with :=, to a run-constant value in its initializer or in any write, whatever their order. A constant is a literal, a constructor of constants, or a library value.

So on_cpu, on_gpu, is_metal, seeds_here = Autotune.seeded_default_backend backend_name and a lazy hardware probe are gates; a value computed from the program under test -- a census, a readback, a query's answer, a seed list -- is not, though it read the backend along the way, because it also reads something that is not run-constant (a parameter, a pattern variable, a function value, a call over constants alone such as Context.auto ()). The distinction is the one Verdict's gates draw: the backend, an advertised capability, the configuration.

What is not read

A claim reached through a wrapper the source binds (let check label ok = p label ok), applied through |> or @@, or partially applied; a function's result where the function is the source's own (has_mma () is not run-constant, whatever its body reads); a name a destructuring let or a match case binds; and a gate folded below a conjunction (census_ok && ((not on_metal) || dialect_ok)), which the claim checks partly everywhere -- the label then promises both halves, and only the reader of the label can tell that the second is vacuous off Metal. Each is a place a folded gate can hide; none is one this reader reports where the fold is not there.

The other direction has three known places, each loud -- a refusal of a claim that does not fold: a cell's writes are not ordered against its reads (above); a configuration reader is run-constant whatever it is handed (Context.hardware_limits ctx of an element's own ctx); and Sys, Utils.settings and the reader names are recognized by spelling, so a module the source binds under one of those names is read as the standard one, unless the path names a binding of that module of the source.
