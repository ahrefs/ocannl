Module Test_utils.Debug_name_scan

Holding every test's use of a node's debug name to display, never lookup (gh-ocannl-1606).

The reader behind test/operations/debug_name_scan (gh-ocannl-1606): a test, and the library code under lib/ and tensor/, reads a tensor node's debug name only to show it, never to find the node or to spell a name that outlives the moment it is shown.

Tnode.debug_name is a display name. Once a renderer has minted a code name for a node, the debug name IS that code name: a label two nodes of one routine share becomes n<id>_<label>, and with output_debug_files_in_build_directory the .cd/.ll printers mint names the C emitter never asks for. batch_norm_running found its owner's running_mean_parallel by debug name and raised Not_found_s once debug files were on (gh-ocannl-1552). A node is found by Tnode.label_name, the name its label spells, which no renderer changes. The same holds for a name the library stores rather than shows -- a tensor label (Parallel.shard_along's shards), a block comment that lands in generated code (Train.forward), an ndarray's debug description, a shape-constraint origin: those take label_name too, so they do not depend on what a renderer minted first. This scan refuses a debug name used any other way than the closed list below.

What it reads

The parse tree (ppxlib's) of every .ml of the corpus the driver hands it, a quotation's payload ([%expr ...] in a ppx) included and read as the code it is: a debug-name read a ppx generates is held to the rule of one written by hand.

  • A reference is any value identifier whose last component is debug_name or debug_grad, under any module path: Tn.debug_name, Ir.Tnode.debug_name, Tensor.debug_name, Tensor.debug_grad, a bare debug_name after an open. Shadowing by a let is NOT resolved: a value a let names debug_name is read as the library's, the loud direction, which is also what makes an alias's callers references. A bare name a parameter or a pattern binds (Shape.of_rows ~debug_name, a punned { debug_name }) is not a reference: it is not the library's function, and the value it holds was judged where it was produced.
  • An accepted use is an application of a reference to exactly one positional argument (the node), directly or through f @@ x / x |> f, whose value sits in one of these positions:
  1. printed or raised: any argument of printf, eprintf, print_endline, prerr_endline, failwith, failwithf, invalid_arg or invalid_argf, unqualified or under Stdio, Printf, Stdlib, Stdlib.Printf, Base.Printf or Stdio.Out_channel; the payload of a Failure or Invalid_argument constructor (unqualified); the message (a tuple's first component) of a Session_error payload, the framework's session exception, under any module path;
  2. a claim label: the FIRST positional argument of a Verdict.Claims member, as Verdict_callee resolves it to Verdict. A callee that reaches Verdict only past an open of a module the resolver cannot read (Ambiguous) is read as Verdict's, as the other Verdict readers read it: refusing it would refuse every claim of a test that opens Verdict.Claims before its DSL modules, and such a module exporting its own p whose label is a lookup is outside what this scan guards against;
  3. a needle: the ~substring argument of String.is_substring (or Base.String.is_substring) -- a claim that some text names the node;
  4. marked: the application carries [\@rendered_name "<reason>"], whose payload is one string literal of at least two words. It is for a comparison with text a renderer of the same process produced under the display name (a census row, a refusal message), which no position above can express;
  5. marked message-only: the application, or a [%string] whose interpolations apply a reference, carries [\@message_only "<reason>"] (the same payload rule). It is for a debug name that reaches a message by a road no position above follows -- a refusal message a function returns for its caller to raise, a log line through a local formatter, an autotune arm's name on the progress stream -- and that is composed when it is shown, so it names the node as the code emitted by then does;
  6. an alias: the body of a one-parameter function bound to a reference name (let debug_name t = Tn.debug_name t.value in Tensor), whose callers this scan reads as references in turn.
  • Transparent forms, whose value takes the position the form itself sits in: an operand of ^; any argument of sprintf (unqualified, or under Printf, Stdlib.Printf or Base.Printf); any argument of String.concat (or Base.String.concat, Stdlib.String.concat); List.map (or Base.List.map) whose ~f is a reference itself, unapplied; a type constraint or coercion; a local open's body (Tn.( ... )); a partial application standing for the whole one; and each %{...} interpolation of a [%string ...], which the scan parses out of the literal as ppx_string v0.17 splits it (from %{ to the next }, the value before the last #). Its lines are counted in the decoded literal, so within a literal with escapes or line continuations a finding's line can be early.
  • Trust in the names above: a sink, transparent function, operator or module head spelled unqualified is trusted only when no binding of the source is in scope for it (resolved by Lexical_scope: a let printf = ..., a parameter named printf, a module String = ... all make it untrusted, and an untrusted name is an ordinary function). An open of a module brings no names in, so a sink name an opened module redefines is read as the standard one.
  • Refused: every other reference -- used as an argument of any other function (String.equal, List.find, Map.find, a local helper), bound by a let, returned from a function, put in a tuple, list, record or array, compared with =, referenced without being applied (~f:Tn.debug_name anywhere but List.map in an accepted position), or applied to anything but one positional argument. Also refused: a [\@rendered_name] marker that is malformed or attached to anything but a reference's application (an accounting check over every attribute of either name in the file), and a [%string ...] payload that mentions a reference name in an interpolation that does not parse.

What it deliberately does not read

  • Flow beyond the positions above: a message raised through failwith and caught, or a needle check written as a List.find predicate, is accepted. The rule is "the debug name reaches display or a claim about rendered text", not a data-flow proof.
  • Tnode.get_debug_name (a pure function of an id and a label, no node), a record field named debug_name (Shape.t's, spelled from the label when the shape is made), a ~debug_name: argument label, string literals and comments.
  • Exception constructors the source redefines (exception Failure of string), which are read as the standard ones.
