Module Test_utils.Slot_kind

Reading dune files for the stanzas that run a test executable, and whether they declare the shared ocannl_config.

Which backends a dune invocation can run a stanza on whatever the configuration says, and whether the configuration counts at all (gh-ocannl-1004, gh-ocannl-1066, gh-ocannl-1227).

tools/batch-backends.sh resolves the backends a tools/test-run.sh batch can hold, and from them both the dune width the batch runs at and the fleet slot it takes (--cpu only when it holds no GPU). The resolved configuration answers that for every stanza that selects its backend from it -- the ones declaring (env_var OCANNL_BACKEND) -- but not for the ones that NAME theirs: a stanza carrying ; ocannl-backend: cuda -- … goes at the CUDA backend by name, and its select arm follows the library's availability, not the environment. Those markers are complete by construction -- env_var_deps fails a stanza that runs an executable and carries neither the variable nor a marker (gh-ocannl-659) -- so the stanzas a run can reach, and their markers, answer for what it names. Every backend a reached marker names is reported, a CPU one included: the width a batch runs at is the tightest any of its backends meets on the box.

Whether the configuration counts is a policy, not a proof (gh-ocannl-1227, the maintainer's decision of 2026-10-18). Two argv shapes leave it out, and every other one counts it:

  • every target is on config_free_aliases, a closed, short list of aliases whose whole closure reads no configuration -- which slot_kind_live checks on the repository's own tree (refusals), so a reader joining such an alias fails the scan rather than passing as backend-free;
  • or a plain compilation product: build [./]<dir>/<name>.exe (or .bc) of an executable or test stanza declaring <name> there, or <dir>/<name>.cma/.cmxa of such a library. A plain build compiles and links and runs nothing; what it builds first -- every compilation, every rule producing a source-like file, and the files they need -- reaches no reader and names no backend, which slot_kind_live checks too. gh-ocannl-1095 had instead taken the configuration off any batch it could PROVE read none, which needed an exact model of every dune construct a batch could build; each review round found another (response files, pforms in command positions, %{bin:env}). The allow-list needs none of that: no argv outside it is ever proven unread.

What a run reaches is read from a CLOSED set of argv shapes, the ones the runner is used with; any other word is unmodelled, and answered as Unknown -- every backend. (Codex review rounds 3-4 on PR #803 found a new corner of dune's CLI each round, so this stopped trying to model the CLI.)

  • build with alias targets: @dir/alias builds alias in dir and every directory below it, @@dir/alias in dir alone, dir plain (no ., .., leading or trailing /). An alias reaches what its stanzas attach to it -- the runtest-<name> dune generates for a (test)/(tests) stanza and an inline-test library included -- closed under what those build first (the section on what a batch builds, below). No target at all is the default alias everywhere, taken as reaching every stanza. And build with plain compilation products, above.
  • runtest/test with plain directories runs @runtest under each, and with none under the root.
  • Options only from the listed harmless ones, and no --.
  • promote and clean build nothing and reach nothing; any other subcommand is unmodelled (install builds what it installs). exec is answered before this is asked (its program may pick any backend), and so is a command-line backend flag.

A dune file this cannot read is itself an Unknown answer, for the same reason.

What a batch builds

The closure collecting the named backends, seeded by the argv's aliases. It is an OVER-approximation with a stated boundary, not a proof: nothing is taken off a batch because the closure missed it -- the configuration counts outside the allow-list anyway -- and a construct it cannot follow inside a checked closure is refused by refusals.

  • an (alias …)/(alias_rec …) anywhere in a dependency field (a stanza's deps, an inline-test library's (inline_tests (deps …)), link_deps, ...), resolved against the stanza's directory, through the same attached-alias inventory the seeds use, generated per-test aliases included; one whose path does not resolve, and an included dependency file, is unplaced -- a batch reaching one is Unknown, every backend, since what it builds there is unread;
  • a file: every atom anywhere in the stanza, and the payload of every path pform (%{dep:…}, %{read:…}, …), taken as a file it may need -- matched by BASENAME against every rule's targets in any directory, a pform elsewhere in the atom read as a wildcard, a glob_files pattern matched as a glob (a character class or an alternative matching everything). A copy keeps the basename, so this follows it to the original producer without modelling it;
  • compilation, for every batch that builds anything: every library, executable, test program, lexer, parser and env in the tree, its files followed the same way (a test's deps and action are its run, not its compilation), and every rule producing a source-like file. Which program links which library is not read, so all of them are. A directory target, and a rule naming neither a target nor an alias whose action writes no file this reads, are taken as producing every file. A backend fixed past the configuration -- a setenv, an env-vars, a --ocannl_backend flag -- is the marker's to name: env_var_deps fails a stanza whose action pins a backend its marker does not name, a pin it cannot read, and an env-vars binding of the backend (gh-ocannl-1518, Dune_stanza_scan.backend_pins).

val refusals : ?config_free:??? -> config_files:string Base.List.t -> (Base.String.t * Base.String.t) Base.List.t -> Base.String.t Base__List.t

Keeping the list honest

What slot_kind_live checks of the repository's tree, so that the two configuration-free answers above stay true (gh-ocannl-1227, gh-ocannl-1249). Each refusal names what failed and where; an empty list is a tree the answers hold for. The checks read markers over closures and never analyse an action: a backend an action fixes is its marker's to name, which env_var_deps enforces (gh-ocannl-1518).

  • Each listed alias's closure holds no stanza reading the configuration, and no alias dependency whose path the closure cannot follow -- a missing alias is refused too.
  • What every build reaches (every compilation, every source-like producer, and what they need) holds no reader and names no backend: a plain compilation runs nothing that opens a device.
  • Every stanza reading the configuration runs where the configuration it finds is one the runner resolves: in config_dirs, or copied from one of them or from ambient_config_dir -- whose producer has exactly ambient_augmentation's shape, and no other rule anywhere writes an ocannl_config. A reader with no configuration in reach of the checked-in tree would read the gitignored root one (gh-ocannl-1249).
  • The inventory is complete: no stanza head outside the modelled ones (an include brings in stanzas never read, a cram test runs commands no marker covers) and no dynamic-run.

config_files are the repository-relative paths of the ocannl_config files in the tree, as Config_dep_resolution.analyze reads them.
