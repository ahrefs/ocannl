Module Test_utils.Refusal_manifest_sync

Rewriting Refusal_control_manifest's stale rows, keys and labels after a diagnostic is reworded: tools/refusal-manifest-sync.sh's engine (gh-ocannl-1429).

The mechanical half of keeping Refusal_control_manifest in step with the scanners it catalogues (gh-ocannl-1429): after a diagnostic is reworded, its marker digest moves, and the row listing it, the raw_direct_evidence or raw_catalogue_only key naming it, and a raw_direct_evidence label naming a reworded control claim all go stale together. This module reads those three tables from the manifest's TEXT, works out what a rewording replaced, and writes the replacement text; tools/refusal-manifest-sync.sh runs it, reformats the file and re-runs the goldens.

What it decides mechanically is only what a rewording determines: a row is the extraction (Refusal_control_manifest.row's contract), and a key or label follows the diagnostic it named when the registered row and the extraction pair that diagnostic one for one (align). Anything else -- a key no rewording pairs, a control claim reworded into a format with substitutions, a direct failure that became a claim -- is reported as unresolved and left for a hand edit, never guessed: which control answers for a refusal is a judgment the tables record.

val align : equal:('a -> 'b -> Base.bool) -> before:'a list -> after:'b list -> ('a * 'b) Base.List.t * 'a Base.List.t * 'b Base.List.t

align ~before ~after: which elements of before the elements of after replaced. The two lists are compared through their longest common subsequence under equal; between two kept elements, a run of before elements dropped and a run of after elements inserted of the SAME length are paired one for one, in order -- a rewording keeps its place in the source -- while a run of unequal lengths pairs nothing, since which of them replaced which is no longer determined. Answers the pairs, then the unpaired before and after elements.

val plan : ?unpaired_claims:??? -> text:string -> diagnostics_of:(Base.string -> Scan.diagnostic Base.List.t option) -> renamed_claims:(Base.String.t * string) Base.List.t -> unit -> plan

The plan for the manifest text. diagnostics_of gives a row source's current diagnostics (None for a source that is gone), renamed_claims the control claims reworded outside the rows, old format to new, and unpaired_claims the old formats there that nothing replaced one for one (claim_renames).

One old diagnostic is followed only to ONE successor: an identity occurring twice in a row (two sites of one format) whose occurrences were reworded differently has no single successor for its key, label or golden marker, and is unresolved -- never the last pairing that happened to win.

val apply : Base.String.t -> (Base.Int.t * int * Base.String.t) Base.List.t -> Base.String.t

text with edits applied; they must not overlap.

val rewrite_golden : ?sources:??? -> plan -> Base.String.t -> Base.String.t

A golden's text as the rewording prints it: each replaced marker swapped for its successor, and each row <label>: true or <label>: PASS of a reworded claim -- the label's identity the old claim's, the new format free of substitutions -- swapped for the new label. Nothing else moves: a golden row the rewording changes in any other way is a diff the confirming run shows. Without this the audit could never pass on the first run: its coverage claims read the goldens for the NEW markers, which only a run that passes would print.

val touched_sources : plan -> Base.String.t Base.List.t

The sources a plan touched: rows rewritten, and the scanners of keys and labels it changed.
