Module Test_utils.Open_node_scan

Holding every tensor node a module of tensor/ creates to Tensor.note_open_node, the uid list a rewind discards by (gh-ocannl-1579).

The reader behind test/operations/open_node_scan (gh-ocannl-1579): every tensor node a module of tensor/ creates reaches Tensor.note_open_node.

A rewind discards exactly the nodes the frontend allocated since the last closure, tracked by uid in Tensor.open_node_uids (gh-ocannl-1505). A creation site that forgets the call leaves its node alive as a handle across a rewind; the id range the uid list replaced caught such a site by construction. Until this scan the pairing was documentation only.

  • What it reads
  • What it deliberately does not read

What it reads

The parse tree (ppxlib's), with names resolved lexically through Lexical_scope, so a parameter, a local binding or a local module spelled like the real thing is not the real thing.

  • The creators are derived, not listed. arrayjit/lib/tnode.ml's top-level values that mint a uid: those whose definition mentions its top-level fresh_uid (the one source of a node's identity, and the identity note_open_node records), closed over mentions of each other. A mention is any occurrence of the name resolving to that top-level binding, applied or not, so a wrapper or an alias of a creator is a creator. Refused: no top-level fresh_uid; a mention reaching fresh_uid from outside a top-level value binding with a variable pattern (a nested module, an extension payload, a tuple pattern, module initialization), since the scan would not know what to call it. Not read: the values an include in tnode.ml brings in (none reaches fresh_uid today), and any other module of arrayjit.
  • The corpus is every .ml under tensor/, subdirectories included, as a source tree holds it: the generated lexer and parser are not sources there and are not read.
  • A creation is an application of a creator through a path resolving to Ir.Tnode: Ir unbound by the file (the library), Ir.Tnode, a module alias of either (module Tn = Ir.Tnode), Tnode after an open Ir (or include Ir), and a bare creator name after an open of Ir.Tnode, local opens (Tn.( … ), let open Tn in …) included. Such an open brings in exactly tnode.ml's top-level value names, each shadowing a local name it spells. A creator referenced without being applied is refused.
  • Its node flows into a let-bound variable when the application is in a RESULT POSITION of that binding's right-hand side: the expression itself, through a type constraint or coercion, a let … in, module … in or exception … in body, the last expression of a sequence, every arm of a match or if, the body and every handler of a try, and the body of a local open. Every variable of the binding's pattern stands for its node (a creator returning a pair binds let tn, init = …; the types admit only the node to note_open_node). A variable in a result position of another binding flows on into it. Anything else -- an argument, a tuple or record component, a function's body, a let* operand, a match scrutinee -- is not followed, and a creation there is refused.
  • Noting is an application note_open_node x with x an identifier resolving to a variable its node flows into, anywhere in that variable's scope. Only tensor/tensor.ml's own top-level note_open_node counts, not a shadowing local one, not a same-named one in another file (tensor.mli does not export it), and a second top-level definition of it is refused.

What it deliberately does not read

  • Control flow: a note on one path counts for the variable on every path, and a node that escapes before it is noted passes. The rule is "the creation's variable is noted", not a dominance proof.
  • note_open_node reached any other way: under @@ or |>, as a function value, through an alias or a wrapper. Such a node is refused as never noted -- the loud direction.
  • Modules outside tensor/: lib/persistence.ml's load and the tile and scratch nodes the optimizer creates in arrayjit/lib are not open inference work and are not the frontend's to note (tensor.ml's checkpoint documentation says why).
