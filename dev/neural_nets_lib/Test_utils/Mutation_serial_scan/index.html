Module Test_utils.Mutation_serial_scan

Holding every write to the inference session's module-level mutable state to Row.note_mutation, or to an in-place classification (gh-ocannl-1506).

The reader behind test/operations/mutation_serial_scan (gh-ocannl-1506): every write to a module-level mutable binding of the inference-session modules (tensor/row.ml, tensor/shape.ml, and since gh-ocannl-1573 tensor/tensor.ml) advances Row.mutation_serial, or is classified in place as not needing to.

The serial is how a failed construction is told apart from one that failed before touching the session (gh-ocannl-1301): a write it does not count is a construction that fails after mutating the session without tainting it. Checkpoint rollback (gh-ocannl-903) leans on the same obligation for the session's module-level state. Until this scan it was documentation only.

What it reads

The parse tree (ppxlib's), with names resolved lexically through Lexical_scope, so a parameter or local binding spelled like a table is not the table.

  • Tracked binding: a let x = e of the file's own top-level structure whose e, under type constraints, is an allocation: ref _ (also Stdlib.ref, Base.ref), or M.create _ / M.make _ for M one of Hashtbl, Hashtbl.Poly, Hash_set, Hash_set.Poly, Queue, Stack, Array.
  • Tracked record value (gh-ocannl-1573): a let x = { … } of the top-level structure whose record literal, under constraints, resolves to exactly one record type the file declares at top level with a mutable field -- by a type constraint naming it (on the binding or the expression), or else by its labels (all of them, for a literal; a subset, for a { e with … } copy). Labels fitting several declared types are refused (constrain it). Each mutable field is then judged as a binding of its own, x.f: x.f is its read, x.f <- v its write, { x with … } a read; any other use of x -- an alias, an argument, a destructuring pattern -- is refused like any unclassified use.
  • Occurrences of a tracked name are classified by the application they are the first positional argument of, from closed lists (ref_reads, ref_writes, family_functions): !x reads a ref; x := _, incr x, decr x, Int.incr x, Int.decr x write it; a container is read or written by the listed functions of its own family (Hashtbl.find_or_add is a write, Hash_set.mem a read; a.(i) <- v is Array.set). A Stdlib. or Base. qualifier is dropped first. The function must be the library's: a name or head module the file binds in scope (a local module Hash_set, a let ( := )) classifies nothing, so the occurrence is refused as unclassified. A write must be saturated -- at least its listed arity in arguments -- since a partial application is a closure that writes later.
  • Accounting: a write is accounted for when its nearest enclosing let-bound function (any let f … = fun … at any depth; the top-level definition when none encloses it) contains a call note_mutation () in its own body, callbacks included -- a function literal passed as an argument is assumed to run during the call, so the ~default closure of a find_or_add counts -- but not inside a nested let-bound function or an escaping closure (one returned, stored or bound rather than passed), each a frame of its own. The call must reach the real one: Row.note_mutation with no module named Row bound in scope (a local module, functor parameter or unpack), or -- in the serial's own module alone (~serial_owner, row.ml) -- its top-level note_mutation, not a shadowing local. An open that brings a Row in is not modelled.
  • In-place classification, as attributes with a closed grammar; a reason is a string literal of more than one word:
  • [@@mutation_serial.exempt "<reason>"] on a tracked binding: its writes need no note (fresh-id counters, the serial itself, a solver pass's transient flags, user configuration). Also the only way to admit state the scan cannot read (below). On a record value it goes on the field instead -- [@mutation_serial.exempt "<reason>"] on the mutable label declaration of its type -- and exempts that field alone; on the record binding itself it is refused.
  • [@@mutation_serial.fingerprinted] on a tracked ref that Shape.fingerprint compares physically: held to the relationship, not to a reason -- the file's top-level fingerprint must capture !x as a field of the record it returns ({ f = !x } as its result), and its top-level mutated_since must hand that field and !x to the library's phys_equal (phys_equal fp.f !x) as an operand of its returned boolean, through ||, && and not.
  • [@@mutation_serial.boundary "<reason>"] on a let-bound function, at any depth, that is a session boundary (the commit, a rewind, a reset, or a scoped restore that puts back on return and on a raise what it saved at entry): its own writes need no note.

What it refuses

Each of these is a finding, never a silent pass:

  • a write not accounted for; a write at module initialization, under no function;
  • any other use of a tracked name: passed to a helper, aliased, a container function outside the lists, a ref given to a container function;
  • an allocation at a binding head outside the list above (Foo.create, Foo.make for any other Foo) -- unread, so name it or extend the list;
  • module-level state the scan does not resolve: an allocation bound by a non-variable pattern, one evaluated at module initialization but hidden under a local let of a top-level value (let fresh = let uid = ref 0 in fun () -> …) or in the body of a function the initializer invokes on the spot ((fun () -> …) ()) or binds locally (let make () = … in make (), conservatively whether or not it calls it) -- an unlisted constructor there too -- one inside a nested module, an included structure, a functor argument or a let%ext payload -- unless that binding is exempt;
  • a tracked binding the sibling .mli exports as a val, at top level or through an include sig … end, since its writers outside the file are not read (Row.mutation_serial is exported as a function for that reason) -- unless it is exempt: an exempt binding's writes need no note wherever they are, so the unread writers lose nothing, and the export is a use of the exemption (gh-ocannl-1573: Tensor's configuration refs); an interface include of any other module type, which the scan cannot read;
  • an attribute nothing consumes, a malformed one, two on one binding, a stale exempt (no write of the binding would be a finding without it), a stale boundary (no write in the function would be), a fingerprinted binding mutated_since does not compare.

What it deliberately does not read

  • Branch dominance: a function that notes on one path and writes on another passes. The rule is "the definition counts the session's writes", not a control-flow proof.
  • Values whose mutability comes from their type with no allocation call at the head, beyond the tracked record values above: a record literal of a type declared elsewhere (or with qualified labels), one hidden under a local let or in a nested module, array literals, objects, a mutable value some function returns. Mutable fields of records that are not module-level values -- a shape, an update step, a capture reference, a tensor's consumption -- are not read: the first three are private behind guarded setters (gh-ocannl-1506, gh-ocannl-1573), which the compiler holds every writer to.
  • Modules other than the three named.
  • Obj and other escapes from the type system.
