Module Stderr_capture

What a test reads back from its own stderr (gh-ocannl-1296): the capture, and the autotune-progress: lines the tuner writes there.

Five tests carried a capture of their own, and only one of them survived an exception inside it: the others left fd 2 pointing at a temporary file the run then deleted, so every later line -- the exception's own report, Verdict's teardown -- went nowhere, and a crash read as a silent exit. Three of them parsed the progress lines, each a little differently. This module is the one copy of both.

Base, stdio and unix only, like Fresh_process: reading stderr is not a reason to link a backend.

val capture : ?temp_dir:??? -> ?echo:??? -> (unit -> 'a) -> 'a * Base.string

capture ?temp_dir ?echo f runs f with file descriptor 2 routed into a temporary file, and answers f's result with everything written to fd 2 meanwhile -- by OCaml's stderr channel and by C code alike, since the redirection is of the descriptor (the one ppx_expect performs, which foreign_c_stderr relies on).

On every path out, whether f returned or raised: stderr is flushed and restored; the captured text is written back to the restored stderr when echo (the default), so nothing the run wrote is hidden from its log; the temporary file is removed; and the descriptors this opened are closed, even when setting the redirection up failed half-way. An exception from f is re-raised AFTER all of that, with its original backtrace, so it is reported on the real stderr with the captured text before it. ?temp_dir places the temporary file (default: the system's), which a test of this module uses to see that the file is gone.

val lines : ?temp_dir:??? -> ?echo:??? -> (unit -> 'a) -> 'a * Base.String.t list

lines ?temp_dir ?echo f is capture with the captured text split into lines.
