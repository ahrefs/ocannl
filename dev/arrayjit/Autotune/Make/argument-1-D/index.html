Parameter Make.D

type ctx

An execution context: a device stream with its compilation lineage (Context.t).

type routine

A linked routine of a ctx (Context.routine).

type program

What a compile compiles (Ir.Assignments.comp). The autotuner never inspects one: it hands it to the compiles and asks the two questions below.

type retained

Compiled code kept for a later relink_outcome (Context.retained).

type reuse

A lowering cell shared by one search's compiles (Ir.Lowering_reuse.t): the cell itself is the driver's, since what it is keyed on is the driver's program.

val routine_name : routine -> Base.string
val routine_id : routine -> Base.int
val routine_bindings : routine -> Ir.Indexing.lowered_bindings

The routine's live launch-parameter cells, not copies: timing assigns and restores them.

val routine_grid : routine -> Ir.C_syntax.grid_summary
val routine_segments : routine -> Ir.Low_level.optimized Base.list
val routine_mma : routine -> Ir.C_syntax.mma_summary

The routine accessors: the name, routine_id, bindings, grid, segments and mma fields of Context.routine.

val program_name : program -> Base.string Base.option

The name a compile given no ?name derives for the program's routine, or None where that derivation fails (the compile then refuses the program itself). Read lazily, as a diagnostic label only.

val program_nodes : program -> Base.Set.M(Ir.Tnode).t

Every node the program reads or writes; gates the bounds-blind cache rebase (gh-ocannl-1614), so it is cache-replay behaviour, not a diagnostic.

val reuse_create : Base.unit -> reuse
val reuse_reseed : reuse -> Ir.Low_level.optimized -> Base.unit

Ir.Lowering_reuse.create and Ir.Lowering_reuse.reseed.
