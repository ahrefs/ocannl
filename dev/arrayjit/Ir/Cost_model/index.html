Module Ir.Cost_model

Analytic cost model, the extraction half (gh-ocannl-491 task 1): per-kernel compulsory memory footprints, arithmetic-op counts, arithmetic intensity, and the roofline lower-bound time under advisory envelope constants (Backend_intf.hardware_limits's peak_flops / peak_memory_bandwidth).

The analysis is pure and backend-free: it reads a (typically optimized) Low_level.t through the affine-access artifacts of gh-ocannl-494 (Low_level.affine_accesses, Affine.fiber_cardinality) and returns numbers; envelope constants are plain floats supplied by the caller. The model ranks candidate schedules — it does not predict runtimes.

Approximation contract (each direction is explicit, all biases point the same way):

  • Byte counts are upper bounds on compulsory traffic (distinct cells touched, perfect-cache assumption): per-access image cardinalities are exact for injective interpretable maps, for non-injective interpretable ones whose coordinates' value ranges (span + 1 each, which also caps their count) meet Affine.image_cardinality_lb — overlapping convolution windows (gh-ocannl-1601) — and for vectorized runs whose bases are provably non-overlapping (Affine.vec_runs_disjoint); other non-injective maps, guarded (If) accesses (counted guards-taken), other vectorized runs, dynamic accesses (the known coordinates' image times the dynamic axis's extent, capped by the loop box — gh-ocannl-1174), and other unknown coordinates (Concat — whole-node fallback; a rank mismatch — the loop box over the unmentioned symbols' widths, never exact; a flattened Sub_axis run is interpretable, Affine.coord) only over-count, as does summing multiple same-direction accesses of one node (a union bound, capped by the node's size) — except that a direction whose accesses are all exact and pairwise provably disjoint (Affine.may_touch_same_cell) sums exactly (gh-ocannl-578). Conditional evaluation also over-counts: a read the renderers may skip — a Where arm's or a gated right operand's (&&/||/a gate) inline read — or any access under a dead loop keeps its direction approximate, since the image can exceed what executes; a read inside a Local_scope body under such an operand is certain, the body being hoisted out of the conditional (gh-ocannl-637). fp_approx is false only when the count is exact.
  • The op count is an upper bound in the same guards-taken sense, and counts every scalar Unop/Binop/Ternop evaluation as one "FLOP" regardless of precision or integerness — except the two-operation ternaries FMA/Mul3, which count two (matching peak_flops' FMA-counted-as-two convention, so an FMA-form kernel scores the same as its mul+add form); selection ops Arg1/Arg2/Identity count zero; Tile_mma counts its 2*m*n*k multiply-adds once per tile, not per cooperating lane.
  • The one under-counting escape hatch is opaque code — Staged_compilation statements and merge-buffer reads are invisible to the analysis — and it is flagged: when opaque is set, the upper-bound reading of the byte and op counts no longer holds.

val analyze : Low_level.t -> summary

The whole-kernel extraction: footprints from Low_level.affine_accesses image cardinalities, op counts from a loop-nest walk. Input is typically post-optimize code — the analysis charges whatever materialization the code actually performs, so virtual/inlined nodes never appear and recomputation is charged as ops, not bytes.

val total_bytes : summary -> int

read_bytes + write_bytes: the "bytes moved" denominator of arithmetic intensity — an accumulation's cells are charged once in each direction.

val arithmetic_intensity : summary -> float

FLOPs per byte moved, flops / max 1 (total_bytes).

val footprint_approximate : summary -> bool

true when any per-node footprint is an upper bound rather than exact (fp_approx) — the byte counts over-approximate while the op count may still be exact.

type floor = {
  1. fr_flops : int;
  2. fr_bytes : int;
  3. fr_exact : bool;
}

Lower bounds on arithmetic work and compulsory traffic — the dual extraction (gh-ocannl-514 phase 3), for bounding every completion of a partial placement vector where analyze upper-bounds one concrete candidate. fr_exact is false when some flooring occurred (a guarded body, a non-exact access image counted at its lower bound, opaque code): the floor is then sound but not tight.

val sexp_of_floor : floor -> Sexplib0.Sexp.t
val completion_floor : ?open_placement:(Tnode.t -> bool) -> Low_level.t -> floor

The floor of the roofline legs over placement completions, with every approximation biased down — the exact dual of analyze's contract:

  • fr_flops: guarded (If) bodies count zero (guards-never-taken, dual to guards-taken); the short-circuiting forms count only their certain part — Where its condition plus the cheaper arm's inline work (rendered as ?:), And/Or the left operand's (rendered as &&/||), both sides' hoisted scope bodies in either case (they execute regardless, gh-ocannl-637), the Arg1/Arg2 projections only the selected operand (the discarded one is never rendered, hoisted definitions included); opaque code counts zero (an under-count is sound in this direction); Tile_mma keeps the lane-cooperative attribution, exact when the lane binding is in scope. Statements producing an open_placement node — the Set family and Tile_mma with an open accumulator — count zero: an inline completion instantiates the producer only at surviving consumer sites, possibly fewer cells than the setter loop covers, so "recomputation only adds ops" does not hold and the producer's whole effect attributes to the open placement. Call this on the all-materialized specialization of the decision surface, where every open node's work sits in its own producer statement.
  • fr_bytes: per node and direction, the sum of the exact images when they are pairwise provably disjoint (a disjoint union attains its sum — both extractions then agree, gh-ocannl-578), otherwise the largest exact image (a union is at least its largest member — dual to the upper extraction's capped sum; a second nonzero contribution then marks the floor loose); a certain access whose image is not exact — an overlapping window's s*o + d*k, a dynamic gather's or a vector run's known coordinates — counts Affine.image_cardinality_lb of its coordinate view (gh-ocannl-1601), at most its true image; guarded, dead-loop-enclosed, conditionally-evaluated (a Where arm's or an And/Or right operand's inline read — not a hoisted scope body's) and open-producer-operand accesses contribute zero — their execution is not certain in every completion. So does an accumulation's read of its own cell (the read at the position its read-modify-write statement writes): a privatizing completion accumulates in a register and stores the target once (gh-ocannl-1601). Nodes with open_placement contribute zero.

Committing a placement decision is re-evaluation with the narrowed open_placement: the suppression sets only shrink, so the floor is monotone in refinement — the property that lets a bound prune as commitments accumulate. (An incremental per-node delta cannot be sound in isolation: a Materialize commitment also makes its producer's operations and operand reads certain, not just the node's own traffic.) Committing to Inline tightens nothing for now: a nonzero recompute floor needs lower-bound multiplicity metrics, deferred until the driver proves the need.

A max (fr_flops/peak_flops) (fr_bytes/peak_bandwidth) roofline over these floors (roofline_seconds) lower-bounds every completion — the two legs' minima need not be simultaneously achievable for the max of the two to be sound.

val approximate : summary -> bool

flops_approx || footprint_approximate: some count is an upper bound rather than exact. Such counts are still upper bounds (unlike under opaque), but a candidate whose guards mostly fail can carry counts far above the work it performs — quantities derived from an approximate count (achieved throughput, the roofline bound vs. a measurement) are not evidence about the hardware. Exactness is per leg: op counts (flops_approx) and byte counts (footprint_approximate) go approximate independently.

val roofline_seconds : ?peak_flops:float -> ?peak_memory_bandwidth:float -> flops:int -> bytes:int -> unit -> float option

The roofline lower-bound time: max (flops/peak_flops) (bytes/peak_memory_bandwidth) over the envelope constants present (peak_flops in FLOP/s, peak_memory_bandwidth in bytes/s — the advisory Backend_intf.hardware_limits fields); None when neither is given. Monotone: raising either constant never increases the bound. A lower bound only up to the model's upper-bound byte/op counts — rank with it, do not predict.

The ranking score (gh-ocannl-1253)

analyze charges distinct cells under a perfect cache: that is what makes it a lower bound, and what scores an untiled contraction exactly at its roofline floor however often its operands are re-read from DRAM — the branch-and-bound over the tiling families then fathoms every sketch. The ranking score is the second, separate quantity the untimed choosers rank by (Autotune.model_default, the auto seeding gate of Autotune.seeded_default). The bound is unchanged and keeps serving pruning, pre-filtering, the agreement check and calibration rows; putting a cache model into it would raise BOUND VIOLATION whenever a kernel hits in cache.

Contract:

  • Global reads are REQUESTED per block: the cells one block touches — its Grid loops standing still, Affine.fiber_cardinality over the remaining loop box, capped by the node — times the number of blocks (the product of the enclosing Grid extents). An untiled weight gradient under a Grid row and a wg-thread Workgroup requests M·N·K·elt·(1 + 1/wg); a bm × bn blocktile M·N·K·elt·(1/bm + 1/bn). Reuse within a block is free (it is what the block's shared tiles and L1 are for); reuse across blocks is what is priced. Global means neither Local nor workgroup-shared (global_in): staged tiles and thread-private scratch keep their distinct-cell charge. Per node, the requested bytes are never below analyze's distinct read bytes.
  • Two tiers (the wave decision of 2026-10-18 on the measured HIP boxes, where cache-served re-reads ran at 1.5–2.8 TB/s against 235–261 GB/s from DRAM). Past capacity — the working set, per-block bytes times the blocks resident at once (max_resident_threads over the kernel's launch block, Low_level.launch_dims, at most the blocks; all blocks when no residency is given), the largest over the kernel's launch nests, exceeding cache_capacity_bytes — the requested bytes are charged at the DRAM rate (below). Within it (or with no capacity), they are charged at cache_bandwidth beside the distinct bytes at the DRAM rate, whichever leg is longer; with no cache bandwidth either, the memory leg is the distinct bytes at the DRAM rate — with no reuse extraction and no DRAM rate, exactly the roofline. A cache bandwidth below the DRAM rate is read as the DRAM rate.
  • Its own rates (gh-ocannl-1442). The bound divides by ceilings (peak_flops, peak_memory_bandwidth: class ceilings, so that no kernel beats its bound); the score divides by what kernels achieve. dram_bandwidth (the STREAM-achieved DRAM rate) prices the DRAM tier and the distinct bytes; issue_rate (the effective scalar operation rate of a register-blocktiled kernel, its staging included) prices the scalar operations, while the Tile_mma work the backend accepts (the caller's mma_flops, accepted_tile_mma_flops) is priced at mma_rate (below): a scalar rate never prices work on the matrix units. Tile-MMA work not counted there — declined by a layout or by the backend's hook, so its scalar fallback runs, or not classified at all — is priced as scalar work. Each rate reads as at most its ceiling, and as the ceiling when not given, so a device without them scores exactly as before.
  • Memory space (gh-ocannl-1442). Under the per-block model (a reuse extraction given), the bytes of the nodes the kernel touches outside global memory (reuse.ru_scratch: staged workgroup tiles and thread-private scratch) are off the DRAM leg. Their cost is carried by the fitted issue rate — an empirical approximation that holds for the staging geometry the rate was fitted on, not a model of copies, barriers or shared-memory gathers. Without a reuse extraction they keep the roofline's charge.
  • Tile-MMA rate and device gathers (gh-ocannl-1495). Accepted tile-MMA work is priced at mma_rate, the effective rate the staged tensorized kernels of a site achieve, read as at most peak_flops and as it when not given. The per-lane operand gathers those statements issue straight from device memory (the caller's device_gathers, device_operand_gathers) add their count over device_gather_rate to the compute leg, at the Tile_mma contexts' fill under a launch model; no rate, no term. That is what operand staging buys: at the gh-ocannl-1190 fp8 site on rog the staged leaves ran 2.3x faster than the unstaged ones, which every score before tied. Shared-memory gathers, ldmatrix and whole-fragment loads are not priced (their cost is in the fitted mma_rate), nor bank conflicts, swizzle arithmetic or barriers, and the two plain/swizzled twins of a staged geometry still tie exactly. Several Tile_mma contexts in one kernel share their class's harmonic fill, as the accepted work does.
  • Launch fill (gh-ocannl-1479). Given a fill_model and the kernel's launch_contexts, the scalar work is priced at the issue rate times its contexts' fill (context_fill): per parallel context, its operations over its fill, summed. Serial loops (a plain leaf's batch loops) multiply work but add no parallelism; Grid and Workgroup loops add parallelism, not work. Tile-MMA work takes the fill of the Tile_mma statements' contexts: accepted work at mma_rate, declined work (its scalar fallback) at the issue rate. The saturating thread count is fitted on scalar kernels; for the matrix units it is uncalibrated, and the blocks-over-multiprocessors factor is what orders a plain tensorized leaf against its bgrid twin. Without a fill model the compute leg is exactly as before. A launch-shape proxy, not an occupancy model: no registers, shared memory, wave quantization, or the block a wider sibling nest allocates.
  • Memory transactions (gh-ocannl-1600). Given the kernel's memory_transactions and a transaction_rate (sectors/s), the excess sector transactions of its global accesses -- per lane group, the sectors touched beyond the compact count for the same distinct bytes, each context's over its fill under a launch model -- add their count over the rate to the compute leg: a strided access's replays occupy the issuing multiprocessor. That is what orders a layout whose lanes read contiguous cells against a twin whose lanes stride, which every term above ties (same work, launch and footprints). A fitted relative term: alignment is assumed, L1/L2 reuse of an over-fetched sector is in the fitted rate, bank conflicts are not modeled. No rate, or no excess: the leg is exactly as before. And the kernel's occupancy, given a workgroup capacity per multiprocessor: the compute leg over the fraction of a multiprocessor's thread slots its resident blocks fill -- what orders a deep-K staged tile (16-64 KiB of workgroup memory per block) against its shallow twin on HIP's RDNA parts, measured. Registers are not modeled, nor the launch size (the fill's).
  • Never below the bound: the memory leg is at least the distinct bytes at the peak_memory_bandwidth ceiling, and the compute leg at least the operations at the peak_flops ceiling (a fill is at most 1), so ranking_seconds is at least roofline_seconds over analyze's counts — and therefore at least any roofline over completion_floor. Monotone: raising the capacity, the cache bandwidth, the issue rate, the DRAM rate, the tile-MMA rate, the device-gather rate or the transaction rate never raises the score; raising the fill model's multiprocessors or saturating threads never lowers it.

Writes, op counts and the opacity flag are analyze's.

val memory_transactions : ?sector:int -> lane_width:int -> is_global:(Tnode.t -> bool) -> Low_level.t -> transaction_context list

The excess memory transactions of one kernel, per parallel context in first-access order (contexts with no global access are absent). Lane groups are lane_width consecutive threads of the kernel's launch block, slot .x fastest; sector (default transaction_sector_bytes) is the counting unit. Activity follows each access's own workgroup loops (a lane outside one is idle), a slot the access has no loop of is a broadcast, a lane's innermost run (the serial loops inside every hardware loop, while the lane group's footprint over them is at most 8 KiB) is one footprint with its lane group's (L1 serves the next iteration), the other symbols stand at their base with the base averaged over its sector residues, guards are taken, buffers start sector-aligned, Tile_mma statements and non-global nodes are left out (is_global, as reuse_traffic).

The excess transactions as the compute leg divides them by the transaction rate: each context's over its context_fill under a fill model, the plain sum without one.

The ranking score of one kernel from its extractions: the larger of the compute leg and the two-tier memory leg (section contract; None for the reuse means no per-block charge, the roofline). Tile-MMA operand loads (gh-ocannl-1254)

Not a priced term and not part of any score (only its device-gather part is, device_operand_gathers): a count the untimed choosers break exact ranking ties with (Autotune.model_default's family search, through Schedule_space.search's tie_break). Twins that differ only in a staged tile's physical layout — the plain and Swizzle_b128 staged fp8 twins of gh-ocannl-1190 — touch the same cells with the same operations, so analyze and the ranking score tie them; what differs is how a lane brings each operand tile into registers, which the backend's load rule decides (Backend_intf.codegen_capabilities.mma_operand_loads, the rule its emission applies).

Each Tile_mma operand is classified, in the statement's emission scope, from its place — workgroup-shared, per-thread (Local) or device, and its optimized.swizzled layout — by that rule. The count, per execution of the statement (the enclosing loop extents over its lane extent), is per lane: an ldmatrix operand costs one instruction per lane_bytes it delivers to each lane — 16 for a, CUDA's emitted .x4 form, and 8 for b, its .x2 form — a fragment the arm loads whole (wmma's and rocWMMA's load_matrix_sync, Metal's simdgroup_load) one load, a gathered one one load per element (fp8 gathers bytes, the 16-bit arms 16-bit halves, f32 32-bit words) — counted per intrinsic fragment of the arm's own tile, with the reloads its loop nest repeats (Backend_intf.mma_fragments), since ties fall between geometries too. Only a backend that describes its arms counts at all (CUDA, Metal and HIP; gh-ocannl-1456). A statement whose accumulator the schedule marked in optimized.simdgroup_fragments is counted in the fragment scope where the backend's hook accepts it there as an update-only call, and every other statement per statement where the hook accepts it with its destination's own place (mma_accepts, the hook itself); a statement the hook declines both ways has no count.

The cost of one inlined computation (gh-ocannl-637 Part 2, gh-ocannl-1011)

The cost model's account of what a node costs to recompute at ONE read site — the flops and bytes of one instantiation of its computation, with the exactness the extraction tracks. The reader's multiplicity stays outside, as in the virtualizer's traced proxy (inline_reduction_extent × read multiplicity × inline_fanin); these queries replace the extent × fan-in factor with the modeled arithmetic, and Low_level.recompute_pricer feeds them to the flip-candidate ordering (gh-ocannl-555), the memory-budget planner and, through fa_recompute_cost, footprint-scoped materialization (gh-ocannl-616).

What is priced is code, not a rewrite of it: the inliner's own instantiation of the node's computations at a synthetic read site, after the pipeline the emitted code receives (Low_level.instantiate_at_synthetic_read). The guards the inliner emits (a multi-setter node's per-component range guards and selects, a diagonal producer's consistency guards, a unit-solved affine position's range guard and the loop it keeps), the lane-extract form of a packed-uniform producer, a scope retracted to a read, the simplifier's collapses and the CSE are all in that code, so their cost — and whether each leg is exact — is analyze's verdict on it: a guarded arm with inline work makes the op count a guards-taken bound there as everywhere, a read under a guard's arm makes the byte count one, and a component whose work hoists or whose arm only reads keeps the op count exact.

The exactness contract: a count is exact for the most general in-bounds reader — per axis a fresh index spanning the axis. What a particular reader does on top of that — folding arithmetic once a constant stands for an index, binding an affine position structurally where the generic reader's unit solving keeps a loop, collapsing a loop over a sub-image, or sharing one instantiation between sibling statements through hoist_cross_statement_cse — only LOWERS what executes, so a modeled count times a read multiplicity is an upper bound in the same sense the traced proxy's is; the reader's side of the account stays outside these queries.

type recompute = {
  1. rc_flops : int;
    (*

    Operations of one instantiation.

    *)
  2. rc_bytes : int;
    (*

    Bytes one instantiation reads from nodes other than the computed one — its own cells are a scope local once inlined. Distinct cells within the instantiation's code.

    *)
  3. rc_flops_approx : bool;
    (*

    The op count is an upper bound rather than exact (analyze's flops_approx): a guarded arm with inline work, charged guards-taken. Low_level.recompute_pricer prices only operations, so this flag alone decides whether it returns a count.

    *)
  4. rc_bytes_approx : bool;
    (*

    The byte count is an upper bound (analyze's per-node footprint flags): notably a read under a guard's arm, of which one executes per read. Exactness is per leg, as in summary.

    *)
  5. rc_opaque : bool;
    (*

    Opaque code: the counts may under-estimate.

    *)
}
val sexp_of_recompute : recompute -> Sexplib0.Sexp.t
val instantiation_cost : ?static_indices:Indexing.static_symbol list -> ?placements:Tnode.Placements.t -> self:Tnode.t -> (Indexing.axis_index array option * Low_level.t) list -> recompute option

One read of a node whose computations are given (an optimize_ctx.computations entry, newest first): analyze over Low_level.instantiate_at_synthetic_read's code, the node's own traffic excluded. placements (default: empty) is the lineage the read is instantiated against — it decides which nested scopes the pipeline retracts to reads and whether a packed-uniform producer's counter can serve the lane-extract form; static_indices are the routine's. None when the inliner refuses the read.

val recompute_cost : ?static_indices:Indexing.static_symbol list -> Low_level.optimize_ctx -> Tnode.t -> recompute option

One read of a node the lineage stored computations for, through instantiation_cost under the lineage's placements; None for a node with none. Nested virtual producers need no expansion: a stored computation carries every producer inlined when it was stored as a nested scope, exactly what a read replays, and a producer read that stayed a read is a read in the emitted code too. The flip-candidate pricer (Low_level.recompute_pricer) reaches the same instantiation through the world specialize_proc hands it per node — including, for a node a heuristic cap materialized, the computations the virtualizer's own walk stores once the node is not materialized. Memoized per lineage: partially apply to the context once per compile.

val tile_mma_macs_per_update : int

How many multiply-accumulates of a Tile_mma fork_join_updates charges as one scalar update (16: on cc a Tile_mma renders as a register-tiled vector micro-kernel; gh-ocannl-1564).

val fork_join_updates : cap:int -> Low_level.t -> int

Scalar updates one run of the statement performs, saturating at cap: one per executed store or register update, loop extents multiplying, Local_scope bodies counted (an apparently single store may carry a whole reduction), a whole-node Zero_out its cells, an If guards-taken, a Tile_mma its MACs over tile_mma_macs_per_update; Staged_compilation, barriers and Scan_loop read as cap. The one count both CPU fork/join judgments use (gh-ocannl-1458): the renderer's launch floor (C_syntax, config cc_grid_min_updates) and the default CPU annotator's per-dispatch gate (Schedule.default_cpu, config cpu_schedule_min_work) -- so at equal thresholds the annotator never retypes a loop the renderer would decline. A decline heuristic in machine-independent units, not a runtime prediction: arithmetic inside a store's expression is not charged.
