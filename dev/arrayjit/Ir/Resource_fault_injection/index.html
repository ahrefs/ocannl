Module Ir.Resource_fault_injection

Test-only fault-injection points for resource-owning seams.

Production code calls hit at boundaries where an exception must leave resource ownership honest, passing the concrete artifact identity alongside the point (whose ownership_phase is derived exhaustively by phase_of_point). The default callback is a no-op and no configuration selects it. Tests install a callback with with_event_callback, with_callback, or with_sticky_async_fault.

The callback is per DOMAIN, like the Autotune.Seam hooks: hit calls the value installed in the calling domain, a scenario running in another domain neither reaches nor disturbs it, and a newly spawned domain starts with the no-op. That is sound because every injection point fires on the domain that called the operation (a Context transfer, compile or release, a schedule cache open, store or lookup) and none inside a task a scheduler enqueues, so the multidev_cc worker domains never reach one. A new point keeps that property: one placed in an enqueued task (a kernel or transfer task, as opposed to the routine-level schedule that only enqueues it) would fire on a worker domain and never reach the test's callback. resource_fault_injection_domains pins both halves.

val is_async_sync_point : point -> bool

true for asynchronous synchronization/await boundaries where persistent worker or stream errors are sticky by default (From_host_before_await, Init_from_device_before_await, Transfer_cleanup_before_await, Finalize_before_await).

exception Simulated_capture_error of string

Test-only exception injected at CUDA/HIP graph-capture points to exercise the same fallback path as a non-OOM driver capture error without linking vendor driver bindings into tests.

exception Simulated_graph_replay_oom of string

Test-only exception injected at Graph_capture_replay to exercise the same exec-drop and plain fallback path as an out-of-memory driver launch refusal.

val with_event_callback : (event -> unit) -> f:(unit -> 'a) -> 'a

Installs a domain-local callback receiving both the ownership phase and the artifact identity for f, and restores the prior callback even when f raises.

val with_callback : (point -> unit) -> f:(unit -> 'a) -> 'a

Convenience wrapper over with_event_callback that passes event.point to the callback.

type sticky_fault

Domain-local sticky asynchronous fault handle. Once latched by its trigger point, every subsequent is_async_sync_point hit raises the same persistent exception until clear_sticky_fault is called.

val with_sticky_async_fault : trigger:point -> ?exn:exn -> (sticky_fault -> 'a) -> 'a

Installs a domain-local sticky asynchronous fault callback for f. When trigger fires, the fault latches and raises exn on trigger and on every subsequent is_async_sync_point hit until clear_sticky_fault is called. Restores the prior callback even when f raises.

val sticky_fault_hits : sticky_fault -> event list

Every event observed while sticky_fault was installed, in occurrence order.

val sticky_fault_triggered : sticky_fault -> bool

Whether sticky_fault is currently latched.

val clear_sticky_fault : sticky_fault -> unit

Clears a latched sticky fault so a subsequent retry can complete cleanly.

val pool_cap : default:int -> int

The working cap in the calling domain.

val with_pool_cap : int -> f:(unit -> 'a) -> 'a

Lowers the pool cap to at most the given byte count in the calling domain during f. The cap must be a positive power of two to preserve the link floor for page-rounded allocations. Otherwise raises Invalid_argument before entering f. An outer cap still applies to an inner scope. The prior cap is restored even when f raises.
