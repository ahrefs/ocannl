val vendor_header_idents : Base.String.t Base.List.t

gh-ocannl-707: the file-scope names the CUDA and HIP preludes' headers put in the global namespace beyond the C floor, which an extern "C" __global__ void <name>( definition collides with. One table for both dialects: each vendor's names are implausible as the other's routine names, and reserving a name a toolchain does not declare only renames that routine.

Harvested from the headers rather than by probing (the probe needs the toolchain: nvrtc on an NVIDIA box, hiprtc on an AMD one), and restricted to the classes that collide BY LANGUAGE RULE -- a typedef or macro of the same name, or a C-linkage function -- since C++ overloading lets a kernel coexist with an ordinary C++ function (Metal's harvest, where every vendor function compiled as a kernel name, is the measured instance of that). Everything in the implementation's reserved namespace (__half, __nv_bfloat16, __hadd, __expf, __syncthreads, ...) is covered by C_syntax.implementation_reserved instead, and whatever an SDK adds later fails as the routine name's, through C_syntax.attribute_routine_name_failure. Sources as of CUDA 13.4 and ROCm 7.1, per group below.
